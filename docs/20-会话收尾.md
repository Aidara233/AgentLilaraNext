# 20 · 会话收尾（`wait` 之后会发生什么）

> 这是一篇**设计**文档：说该是什么样，代码尚未实现。
> 它回答一个问题：**一轮结束之后，会话什么时候被叫醒、什么时候彻底结束。**
> 连接与说话方向见 [`19`](19-会话连接.md)。

---

## 0. 一句话

`wait` 不是一个"停"按钮，它是一份**声明**：我要停多久、到点之后拿自己怎么办。声明写进状态，由一个扫描器执行。

---

## 1. 三种形态

```
wait()                      // 停，直到有人来找我。没有期限，永不被自己唤醒
wait(timeout, release=false)  // 小睡：到点自己醒来跑一轮
wait(timeout, release=true)   // 到期释放：到点没人来，就把我收了
```

| 形态 | 到点之后 | 中途有人来 |
|---|---|---|
| `wait()` | 什么都不会发生——它只是在等外部事件 | 正常跑一轮 |
| `wait(T, false)` | 跑一轮，输入为空 | 正常跑一轮，小睡取消 |
| `wait(T, true)` | **释放**：归档会话、关闭连接 | 取消释放，正常跑一轮 |

第三种是"任务完成就该释放"的落地形状：**模型自己说"我干完了，给我一小时，没人来就收了我"。** 宽限期是缓冲，不是延迟。

### 参数怎么读

`timeout` 是**秒**（1 到 604800），`release` 是布尔。下面三种都会被**拒绝**，而不是被当成"没有期限"：名字不认识的参数、超出范围的值、以及 `release` 不带 `timeout`。

理由很直接：参数名打错一个字母，行为就会从"一小时后收了我"悄悄变成"永远睡着"，而且没有任何人看得见。

### 被拒绝的调用不算 `wait`

回合不因为一次被拒的 `wait` 而结束——错误作为工具结果回到模型手里，它可以当场改。若照旧结束回合，那个错误就永远不会被读到，"打错字"会被记成"成功停下"。

为此回合循环多了一条：**连续几轮没有任何调用成功，就刹车结束**。它和"对着空气说话"用同一个上限，因为同一个毛病——没有进展还在花钱。任何一次成功都把它归零：被刹的是"没进展"，不是"调用多"。

---

## 2. 声明写在哪

写进会话自己的 state（`state.json`），两个字段：

```jsonc
{ "wait_until": "2026-11-01T20:15:00+08:00",   // 没有就是 null：不在等
  "wait_release": true }
```

三条理由：

1. **真相只有一份。** 内存里再存一遍就是第二份真相，进程一重启就漂。
2. **重启天然恢复。** 杀进程之后下次启动，扫描器还在，声明还在，什么都不会丢。
3. **可观察。** WebUI 上"这个会话在等，等到几点、等完自毁"是能直接读出来的，不需要推断。

---

## 3. 被打断 = 取消

**任何入站激活都清掉 `wait_until`。** 一条频道消息、一次工具委托、一次显式 `activate`——都算。

清掉同时意味着两件事：小睡取消、释放取消。这是对的：`release=true` 的语义是"**没人**再来找我才收我"，有人来了就说明判据不成立。

顺着这条，`wait` 可以**续命**：再调一次 `wait(T2, true)` 就是覆盖成新的期限。允许，而且应该允许——它表达的是"我还想留着"，硬要禁止只会逼模型编别的办法。

---

## 4. 谁执行

**宿主的一个周期扫描**：启动时一次，之后每 30 秒一次，看所有 `wait_until <= now` 的会话。

不用"每个会话挂一个一次性定时器"，因为它会引入第二份真相：定时器对象和 state 可能对不上（会话被归档了定时器还在、进程重启了定时器没了）。扫描器只是"去看一眼" state，看完什么都不改，所以**不需要和谁保持同步**。

这里要把话说明白，免得和"不要后台定时任务"自相矛盾：

> 反对的是**定时器去启动需要模型参与的工作**——ALP 那个 30 秒循环就是去孵化 review 会话，没人收尾就永久堵住，实测有一条从 8 月卡到今天。
>
> 这里做的是**一次本地状态扫描**：不出模型调用、幂等、失败重试无害。两者不是一类东西。

代价也要诚实：精度就是 30 秒，不可能是秒级。对"一小时后收了我"这件事，30 秒误差无所谓。

---

## 5. 小睡醒来那一轮

按 `wait_release = false` 到点的会话，要跑一轮。这一轮：

- **输入为空**：没有人说过话，这是关键事实。
- 必须往时间线注入一个**唤醒块**，写明"没有任何人说话；这是你自己在 {时刻} 声明的等待到期了"。
- 使用会话自己存着的 spec 跑，和普通一轮走同一个 `RunTurnAsync`。
- 会话正忙（上一轮还没结束、锁没放）就跳过这一次，下一轮扫描再试。**不要排队**：一个攒了七八次唤醒的会话，醒来看到的是七八条"你醒了"。

### 为什么唤醒块是必须的

模型看到自己突然在跑，而上下文里没有新消息，它**会自己编一个理由**——"用户刚才问了…"。这不是模型不听话，是它只能这么解释。唤醒块就是不给它编的机会。

这是这一整套机制里最容易出的一类幻觉，也是最容易被忽略的：它不会报错，只会让模型开始对着不存在的话回答。

### 没有连接的会话醒了怎么办

`speak` 会失败（见 `19` §6：目的地只能来自连接）。这是**正确**的：它不该对空气说话。所以唤醒的那一轮里，模型能做的是做事、写记忆、再 `wait`——提示词要说清这一点，否则它会把"说不出去"当成故障。

---

## 6. 释放：归档，不是删除

`wait_release = true` 到期且确实没人来过：

1. **归档**会话（`ArchiveManager`，`kind = session`，已有实现），不是删除。
2. **关闭连接**：`connection.closed_at` 写上。否则频道还指着一个已经不存在的会话，下一条消息会 `resolve` 到那个 id，然后对着一段归档文件跑一轮。
3. 两步都要**幂等**：扫描器可能在中途崩，重启后再来一遍不能变成两条归档记录。

**为什么归档而不是删除**：`release` 是模型的自我销毁声明，而模型会误判"我干完了"。误判的代价不该是上下文永久消失。宽限期 + 归档可捞回，这两个加起来才让"模型有权结束自己"这件事可以接受。

---

## 7. 它为什么比"模型说完了"更可靠

之前想过的判据是"模型说完最后一句话就释放"。它不可靠，因为模型每一轮都在说"说完了"——`wait` 本来就是每轮的收尾动作，分不出"这一轮说完了"和"这件事做完了"。

现在的判据是**两个条件的合取**：

- 模型主动声明了一个期限（它的判断），并且
- 期限到了**且真的没人再来**（现实的反驳机会）。

第一个条件单独不成立（模型会误判），第二个条件单独也不成立（人不在的时候会话永远留着）。合起来才勉强够用。

---

## 8. 明确不做

| 不做 | 为什么 |
|---|---|
| 每会话一个定时器对象 | 第二份真相，会和 state 漂 |
| `release` 时删除 | 模型的误判不该不可逆 |
| 秒级精度 | 需要更细的调度器，而这件事没有那个需求 |
| 唤醒时排队 | 攒起来的唤醒等于让模型一次读七条"你醒了" |
| 跨进程/持久化调度器 | 单进程宿主 + 30 秒扫描已经够；真需要时再谈 |
| 用 `wait` 之外的动作表达"结束" | 新工具会让模型有两个停法，其中一个必然没人用 |

---

## 9. 这套东西自己的失效点

**扫描器是唯一的执行者。** 它不跑，就永远没有任何会话被释放，也不会有任何小睡醒来——而且**不会有任何报错**，因为"什么都没发生"和"没人在等"长得一模一样。

所以要有可见性，最小的一条：启动收据里报一句"当前 N 个会话带等待声明，最早的一个在 {时刻}"。这句话能回答"这套机制还活着吗"，比任何日志都直接。
