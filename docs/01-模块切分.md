## 1. 边界原则（一句话）

> **图是唯一的跨模块通道；模块内部的调用是硬代码。**
> 判据不是"种类"，是**所有权**：**自己拥有的东西可以硬调，不拥有的一律走图。**

⚠️ 代码里**没有**「功能模块 / 设施模块」这种分类。那只是文档与评审判据（判据 = 有没有自己的外部输入源），用于决定一个模块放哪、由谁驱动。**不落类型、不落分支**——`X-` 台账里 ALP 的 `ISubEngine.IsInfrastructure` 就是反例：一个布尔分类，两条路各长出特例。

---

## 2. 模块清单（定）

| 模块 | 母实例 | 子实例 = 一条什么 |
|---|---|---|
| `session` | SessionManager | 一个会话 |
| `channel` | ChannelManager | 一条频道（一个来源/目的地的消息集） |
| `adapter` | AdapterManager | 一个平台连接（账号 / 端点 / 目录） |
| `store` | StoreManager | 一个库（见 §6） |
| `graph` | GraphManager | 一张图 |

顺带一条纪律：**能不能算模块，看它有没有自己的输入源**。只被调用、没有输入的（日志/时钟/配置）不是功能模块——但它们**仍然是模块**（同一个形状），只是没有一个"事件"喂它们。

## 3. 三层暴露（定）

每个模块的每一层都暴露四类成员。合起来叫**这个模块的对外面**，也是图能寻址的地址空间。

| 层 | 地址 | 生命周期 | 调用接口 | 属性 | 事件（触发源） |
|---|---|---|---|---|---|
| 管理器 | `adapter` | 起/停/重载全体 | 建/删/列举/按 id 取 | 连接数、健康汇总 | 实例增删 |
| 抽象 | `adapter.qq` | 定义契约（连接/断开/重连） | `send`、`probe` | 平台能力、限流 | —— |
| 实例 | `adapter.qq#1` | 实例自己的连接生命周期 | 实例级调用 | 运行态、最后心跳 | 收到消息、连接断开 |

三条硬约束：

1. **只有"实例"层能承载状态。** 管理器与抽象必须无状态（只做索引与契约）。`X-10`（`ModuleHost` 用单实例字典把状态塞在母层）就是这么来的。
2. **只有"端口"上的成员进描述符。** `public` ≠ 可被图寻址：每个模块显式声明自己的端口（生命周期/调用/属性/事件四组），**描述符只投影端口**，实现细节不进。否则图能调内部实现，契约面立刻失控。
3. **三层同构**：`graph` 自己也有 `graph` / `graph.class` / `graph.instance` 三层，用的是同一套形状。这是同构最划算的一次兑现——否则图会变成"特殊的那个"，然后所有特例都会向它致敬。

---

## 3.1 模块契约的必需成员（少一个都不许加载）

模块除了"三层暴露"，还必须提供五样东西。**没提供 = 加载期失败**（"忘了"不能变成静默事故）：

| 必需成员 | 作用 | 缺了会怎样 |
|---|---|---|
| **描述符** | 三层暴露面的机读投影（端口/属性/事件） | 装配无法校验，"接不上"变成静默 |
| **能力声明** | `requires: [file, net, store]` | 装配无法判"该不该批"，默认授予会漏 |
| **急停响应** `OnEmergencyStop(deadline)` | **立刻停到最安全**，不要求收拾干净（[`08` §6.3](08-会话与循环.md)） | 急停时这个模块停不下来 |
| **恢复响应** `OnResume(deadline)` | **把急停期间欠的账还上**（[`08` §6.4](08-会话与循环.md)） | 急停的尾巴永久留在系统里 |
| **生命周期** | 起 / 停 / 重载 | 无法热替换，也无法释放资源 |

⚠️ **急停与恢复是一对**，两个都是必需成员而不是钩子：钩子可以"没实现"，必需成员不行。它们与描述符同级——**少了任何一个，这个模块不被接受**。

⚠️ 四个共同约束（缺一条就不合格）：都有 `deadline`、都**幂等**、都**不抛异常**（异常吞掉并记录）、都会留一条审计。默认实现允许存在（"只拒绝新调用"），但**必须显式声明用了默认**，审计会把"用了默认实现"标出来——能偷懒，但偷懒要留痕。

## 4. 所有权边界（定）

### 4.1 谁能硬调谁

| 调用 | 走哪 | 为什么 |
|---|---|---|
| 同一个实例内部 | **硬代码** | 自己的内部 |
| 管理器 → 它管的实例 | **硬代码** | 管理器**拥有**这些实例 |
| 实例 → 自己的兄弟实例（同模块跨实例） | **图** | 实例不拥有兄弟，也不该持有它的引用 |
| 任意跨模块调用 | **图** | 不拥有。**没有例外**：哪怕只是跨模块把一个计数器 +1 |
| 内核 → 各模块端口 | **图** | ⚠️ 见 §4.3：内核也不例外，一步之内的跨模块调用同样入图 |

### 4.2 由此推出的五条

1. **管理器是唯一持有子实例集合的地方。** 实例里不得出现兄弟实例的字段/构造参数——这条可审也可测（反射扫实现程序集）。
2. **描述符只含端口**（§3 约束 2）：图连的是端口，不是"任意 public 方法"。
3. **高频跨实例通信 = 设计异味**：两个实例需要频繁同步，说明它们本该是一个实例，或者该**上提到管理器**（管理器拥有双方，硬代码合法）。**图不是消息总线**——把热路径塞进图求解器，性能和可调试性双输。
4. **图的边界与"一步"不冲突**（见 §4.3）。
5. **图不得表达"要不要执行"**：权限、能力、模式判定住在模块或内核，图只负责"把事件接到动作上"。

### 4.3 一步之内也走图（已定，推翻上一版）

上一版这里提过一个"端口注入给内核推进器、一步之内不走图"的方案——**作废**。规则没有例外：

> **只要跨模块，再简单也得走图。**（用户裁定）

所以"推进一个会话"里对频道 / 存储 / 模型的每次跨模块调用，都过一次图。这不破坏原子性的原因、以及"一步的序列也是出厂图"这条推论，见 [`02-图模块.md`](02-图模块.md) §6。

由此会话实例**不持有**任何其它模块的端口引用——它自己就是"跨模块只走图"的最大受益者，也是最强的证明：会话不需要认识频道。

## 5. 事件泵：模块怎么发事件而不依赖图

模块不能直接调 `graph`（那本身就是一次跨模块调用，会成环）。所以：

```
契约层：IEmit（最小接口：emit(事件名, 载荷, 来源地址)）
             ↑ 注入                        ↑ 订阅
        adapter/channel/session          graph（订阅全部，求解后调各模块端口）
```

- 模块只认识 `IEmit`（契约层类型），**永远不知道图存在**；
- 图是 `IEmit` 的消费者，也是"跨模块调用"的唯一发起者；
- 事件携带 `$source`（`adapter.qq#1`），节点据此解引用——所以"按 id 取存储"里的 id 来自**来源实例的配置属性**，不写死在图里，同一张图可跨部署复用。

## 6. 存储：正交形状（定，待补第四节）

```
StoreBase            打开 / 事务 / 版本 / 迁移 / 关闭 + 基础读写
  ├─ AdapterStore    原始报文、附件字节引用、平台 id ↔ 内部 id 映射
  ├─ ChannelStore    去重清洗后的消息、参与者、频道元信息
  └─ SessionStore    spec / state / history
  └─ GraphStore      ★待定：挂了哪些图 + 执行态（图也是模块，也有存储需求）
```

硬约束：

1. **数据模型住在契约层**——否则存储模块要引用功能模块才能知道"消息长什么样"，第一根反向依赖就出来了。存储只认数据，不认 `SessionManager`。
2. **物理隔离**：各自目录/库，不是一张大表加前缀。三种数据寿命不同（原始报文可整批丢，会话记录一个字节都不能丢），混在一起没法单独清理和单独升级。
3. **主抽象只承载"怎么存"，不承载"存什么"**；主抽象塞不下的能力，说明那个 store 不该继承它。判据见后续 `H2`。
