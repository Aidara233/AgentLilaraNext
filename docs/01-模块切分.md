# 模块

> 状态：**定稿**（本文件之后改动即为设计变更）。它回答一个问题：**什么算一个模块，模块之间怎么说话。**
> 别的文档引用本文件，不重复它。会话内部见 [`08`](08-会话与循环.md)，频道见 [`09`](09-频道与连接.md)，接口形状见 [`10`](10-接口契约.md)。
>
> **实现进度**：`ModuleId`、`ICatalog` 与六个唯一模块（`AdapterManager` / `ChannelManager` / `SessionManager` / `ModelManager` / `GraphManager` / `Clock`）已上线，启动收据会报出注册表；`IModule` 目前只有 `Id`，`Mounts` 随派发表一起落地（§6）；实例与脚本尚未登记——它们要等 `Address` 换成 `ModuleId`（§12 第一条）。

## 1. 一句话

系统里只有一种东西：`IModule`。**管理器、实例、脚本实例都是它。** 区别只有两点——谁持有谁（管理关系），以及谁在解释它（CLR 还是脚本引擎）。

```csharp
public interface IModule
{
    ModuleId Id { get; }
    IReadOnlyList<ModuleId> Mounts { get; }   // 转述目录，不是自有状态
}

public interface IAdapter  : IModule { }      // 适配器行为
public interface IChannel  : IModule { }      // 频道行为
public interface ISession  : IModule { }      // 会话行为
public interface IModel    : IModule { }      // 模型行为
public interface IScript   : IModule { }      // 脚本行为
```

**抽象层是接口，不是对象。** 所以"三层同构"实际只有两层有活物：**管理器 + 实例**。不存在"一个叫 `Adapter.QQ` 的实例"——`Adapter.QQ` 是类型，不是东西。

## 2. 身份：三种 id，三条规矩

| | 是什么 | 谁依赖它 |
|---|---|---|
| **模块类型** | 类声明的语义类型，用来筛选 | 逻辑**只**靠它找人 |
| **唯一模块的 id** | 它自己的名字，写进契约常量 | **契约**——可以按 id 直接查 |
| **其余模块的 id** | 装饰；长得像 `类型#后缀` 只为好看 | 没人依赖格式 |

三条规矩：

1. **逻辑只用类型筛选找人，不从 id 读任何东西。**
2. **唯一模块的 id 是契约**：改它等于改 API。多实例模块的 id **不是契约**：改成任意合法值，功能都不变。
3. **id 不是描述**，是名字。`Adapter.QQ#ABCDEF12` 里没有一个字符是给代码读的。

### 格式依赖 vs 引用依赖

这两件事长得很像，性质完全不同，必须分开看：

- **格式依赖 —— 永远禁止。** `StartsWith` / `Split('#')` / 读段落，都是错的。
- **引用依赖 —— 必然存在。** 挂载边、配置里的目标、`mounts()` 返回的列表，都指向具体 id。**改名会让这些引用失效，但那是改名的后果，不是设计缺陷。**

## 3. id 的规则：校验 ≠ 解析

**校验**问的是"这个名字能不能用"；**解析**问的是"这个名字是什么意思"。前者必须有，后者绝对不许有。

```
允许字符：[A-Za-z0-9._#-]，长度 1..96
禁止：路径分隔符、控制字符、整体等于 . 或 ..
禁止：Windows 保留名（CON / PRN / AUX / NUL / COM1-9 / LPT1-9）
不合法 → 拒绝创建并报错，绝不改写
```

**拒绝而不是改写**：`sanitize("a/b" → "a_b")` 就是格式化解读，还会让两个不同 id 悄悄撞成一个。

**唯一性按大小写不敏感判定**：文件系统不敏感，`#ABC` 与 `#abc` 是两个 id、同一个目录——不按不敏感判，就会在磁盘上静默合并。

### 怎么用 id 才不算"依赖格式"

| 允许 | 禁止 |
|---|---|
| 当字典键查表 | 从里面读出类型 / 类别 / 归属 / 父级 |
| 当文件名拼路径（`sessions/<id>`） | 当零件拼出**另一个 id**（`"s-" + hash`） |
| 打日志、显示给人看 | 按前缀 / 后缀 / 分隔符分支 |

## 4. 模块的三种形态

| | 例子 | 说明 |
|---|---|---|
| **管理器** | `AdapterManager`、`ChannelManager`、`SessionManager`、`ModelManager`、`GraphManager` | 全局唯一，持有自己命名空间下的实例。**它就是它自己那个类，不是 `IAdapter` 的实现** |
| **实例** | `Adapter.QQ#…`、`Channel.Conversation#…`、`Session.Chat#…` | 由所属管理器创建，地址带后缀 |
| **脚本实例** | `Channel.Chat#…` | 由脚本引擎按挂载规则创建，与其它实例同权 |

**管理器只持有自己命名空间下的实例**——这就是"管理与被管理"的全部内容。**跨命名空间一个引用都不许有。**

### 类型存在哪里

存在 spec 里，作为 `type` 字段（`"type": "adapter.file"`）。**不是从 id 里切出来的**，而且**是必填的**：文件里没有 `type`（或是空串）就是一条加载错误，不猜、不补、不"先当 A 类型试试"。早期写过那种文件的那一次迁移已经做完，现在只剩"读字段"这一条路。

这也是为什么 `AdapterInfo` / `ChannelInfo` 上都有一列 `TypeId`（模型的在 `Descriptor` 里）：想按类型筛实例的人读那一列，而不是去解析地址。凡是还在用 `Address.TypeId` 判断"这是什么"的地方，都是一处没改完的债。

这条不是洁癖：地址变不透明之后，`id` 里已经没有类型可读，任何"取到类型"的代码都必须从这里拿。

> 管理器不是特例。它只是一个"约定为单例"的模块，没有被实例化多次而已。任何类都可以声明自己是单例。

## 5. 目录与发现

```csharp
public interface ICatalog
{
    IModule? Find(ModuleId id);                                  // 唯一模块的正确用法
    Result<IModule> Require(ModuleId id);                        // 找不到 = 报错，不是 null
    IReadOnlyList<CatalogEntry> List(string? category = null, string? typeId = null);
    IReadOnlyList<ModuleId> MountsOf(ModuleId id);
}

public sealed record CatalogEntry(ModuleId Id, string TypeId, string Category, Role Role);
```

- **目录不是模块**，是基础设施（和事件泵、存储同级）。否则"找模块要先有模块"就是自举循环。
- **由宿主任装配根第一件创建**，加载任何包之前就有；通过 `HostServices` 发布（现成机制）。**不用静态单例**——静态对象在热重载后是陈旧指针，且并行测试会互相覆盖。
- 静态的东西只放**名字**，不放对象——而且名字就声明在模块类自己身上（`[Module("AdapterManager", Category = "adapter", Singleton = true)]`），宿主不在登记时替它填类型、类别或角色。登记调用只有一个参数，真相只有一处。

### 为什么"列举"是必需品

id 不可猜。所以如果只能 `Find(id)`，那"拿到 id 就能调"就退化成"**拿不到 id 就永远调不了**"。

- 找唯一模块：`catalog.Require(ModuleNames.AdapterManager)`。
- 找实例：`catalog.List(typeId: "Adapter.QQ")`，再从结果里挑——**永远不能靠猜 id**。

### 授权

调用是全局可达的（地址即引用），所以**列举结果必须按授权过滤**，否则目录就是一张可扫描的地图。

## 6. 挂载

挂载是一条边：**脚本实例 → 目标模块实例**。

**它只授予一件事：接收目标的生命周期事件。** 不授予调用权——调用权来自地址 + 授权，跟你挂没挂在这里无关。

| 规则 | 说明 |
|---|---|
| 挂到**类型** | **不是一种边，是规则的展开**：新实例出现时按规则创建脚本实例并挂上。派发表里永远只有实例 |
| 一个实例一个目标 | 同时挂两处，"这个事件派给谁"就没有答案 |
| 换挂载 | 先卸后挂；卸时发 `module.unmounted` 让它收尾。`unmounted` 抛错**不阻止**换挂（事件无返回，只进日志） |
| 挂载表的真相 | 在图的派发表；契约暴露在目标模块上（`Mounts`，返回 `ModuleId` 列表，不返回带类型的字符串） |

**脚本可以挂到脚本上**，与普通挂载无异——因为脚本本身也是模块，有地址、有自己的生命周期事件。

---

## 7. 两种交互

| | **生命周期事件** | **函数调用** |
|---|---|---|
| 发起 | 模块（挂载点） | 任何模块或脚本 |
| 接收 | 挂在它上面的**所有**脚本，同名函数 | **一个指名道姓的实例** |
| 返回值 | 无 | 有 |
| 一个失败 | 不影响其它挂载者，进信号日志 | 调用者拿到错误 |
| 定位 | 不需要（广播） | 必须给 `ModuleId` |

两条不能混，因为失败语义不同：**事件失败了没人等它，调用失败了调用者必须知道。**

- 事件**串行**、按挂载序号派发。**靠现有单线程事件泵，不靠锁**——给派发加锁是把顺序问题变成死锁问题。
- 函数名拼错**必须报错**，不许返回空。
- 授权粒度 =**（目标 `ModuleId` + 函数名）**。

## 8. 生命周期事件

所有模块都有的通用事件：

| 事件 | 时机 | 谁收得到 |
|---|---|---|
| `module.initialized` | 刚被 spawn，或刚从磁盘读回内存。只保证自己能跑 | **只有宿主与基础设施** |
| `module.ready` | 全体 `initialized` 完成后统一发（屏障） | 挂载的脚本 |
| `module.faulted` | 内部故障，已降级或停止工作 | 挂载的脚本 |
| `module.stopping` | 开始离开内存，不再接新活 | 挂载的脚本 |
| `module.stopped` | 主要步骤做完，只差释放内存 | 宿主 |
| `module.emergency-stopped` | 急停：在 deadline 内停到最安全，不保证收尾 | 宿主 |
| `module.resumed` | 急停后恢复，把停摆期间欠的账还上 | 挂载的脚本 |
| `module.mounted` / `module.unmounted` | 挂载边建立 / 拆除 | 脚本自己 |
| `module.mounts-changed` | 某个模块的挂载集合变了 | 宿主与观察者 |

### 两处必须区分的语义

**① 卸载前"能不能走"是函数调用，不是事件。**
排空在途工作、拒绝新请求的结果可能是 `NotReady`，**事件无返回就拦不住卸载**。顺序是：先 `PrepareUnload()` 拿 `Ready/NotReady`，再广播 `module.stopping`。

**② `initialized` 阶段没有脚本能收到。**
脚本要挂在模块上才收得到事件，而此刻它刚存在。所以 `initialized` 的观察者只能是宿主与基础设施；**从 `ready` 开始才有脚本能看见**。挂载规则里声明接收 `initialized` 的，**挂载时直接拒绝**——否则就是一个永远不触发的静默失效。

## 9. 图

```
目录：ModuleId → IModule          ← 谁能被找到
派发表：实例 → [脚本实例]          ← 事件沿它往下流
职责：寻址 / 沿边派发事件 / 派发函数调用
```

**不认识业务、不持有任何模块。** 它不替任何人判断"你俩该不该说话"——那是授权表的事。

---

## 10. 脚本

- 一个脚本文件里**至少一个类实现 `IScript`**，可以有多个（一个文件多个模块）。
- **无状态功能脚本**落成"固定名字的单例实例"：不挂任何目标、不接生命周期事件、可以被任何有授权的调用方按名字调用。**没有实例就没有调用入口**，所以"没有实例"必须落成"一个固定实例"。
- 脚本 id 由运行时生成，**不采用 `script.<名字>#<id>` 这种结构化格式**（那就是被禁止的拼接）。
- 导出函数与接收事件在**挂载时核对**：缺函数、或接了目标没声明的事件 → 拒绝挂载并报错。

---

## 11. 不变量

1. 地址唯一，由目录保证（大小写不敏感）。
2. **模块之间零引用**——这是根，别的都是推论。
3. 事件只沿挂载边向下流，不横向、不向上。
4. 派生关系（类型 → 实例、规则 → 挂载）都是**规则的展开**，不是存储的边。
5. 目录不是模块；静态只放名字，不放对象。
6. 逻辑不读 id 的形状；允许把 id 当键、当文件名、当显示值。

## 13. 反向判据（会红的测试）

1. **把所有 id 换成随机合法乱码**（含 `#`、`.`、大写、中文以外的怪字符），主流程照常跑通。
2. 两个类声明同一个唯一模块 id → 后加载者**失败**，不覆盖。
3. 挂载规则声明接收 `module.initialized` → **挂载被拒**。
4. 函数调用写错函数名 → 报错，不是空返回。
5. 一个脚本的事件处理抛错 → 后续挂载者**仍然收到**事件。
6. 换挂载后，脚本的 `state` **不丢**（作用域按实例，不按目标）。
