# 工程最小闭环

> 状态：早期工程路线草案。新的脚本编排方向、项目树和逐阶段验收以 [`13-脚本编排与工程实施蓝图.md`](13-脚本编排与工程实施蓝图.md) 为准。
> 范围优先级按用户裁定：**先解决工程问题；模块完整性与安全细节后续推进。**安全边界仍受 `06` / `07` 已定的绝对要求约束。
> 最小闭环从 **Adapter + Graph** 开始：适配器收到消息，Jint 脚本按事件和消息内容决定是否使用已授予的 Adapter 能力回复。图不再是纯静态接线表。

## 0. 目标与边界

### 目标

```text
平台/测试 Adapter 收到消息
  → emit adapter.envelope
  → Graph 按事件找到已挂载的 Jint 脚本
  → 脚本检查消息并通过受限 API 调用来源 Adapter 的 send
  → 外部可观察到回复
```

验收语义：FileAdapter 收到 `ping` 时，挂载脚本向同一实例发送 `pong`；收到其他消息时不回复。条件判断属于脚本，不是 Graph 静态接线语法。这个闭环不依赖聊天平台账号，用来验证 Adapter、Manager 生命周期、Graph 挂载、Jint 宿主和派发器。完整项目树、manifest/API 草案及验收分阶段见文档 `13`。

### 当前不纳入闭环

- Model、Session、Tool、Memory、持久化历史、账号主备切换；
- 全量权限体系与外部内容信任设计；
- WebUI / CLI 的产品形态；
- 通用规则编辑器与自举。

这些不进入首个可运行垂直切片，不代表永久取消。

## 1. 部署与执行模型：单线程异步（v0 建议）

（用户此前已定：**单线程异步**。本节把它解释成工程约束，避免误读成“整台进程永远只占一个 OS 线程”。）

### 1.1 定义

- **一个逻辑派发器**拥有事件队列与图状态；所有图求值、模块状态转移按队列串行推进。
- 适配器的 socket / HTTP 等外部 IO 使用**异步 API**；等待 IO 时不占着 CPU 忙等。
- 平台回调可能来自运行时线程池；回调只做最小封装并**投递到派发队列**，不直接跑图、不直接改模块状态。
- 异步操作完成后，把完成结果作为新工作投回同一派发队列；状态只在那里提交。

所以：**逻辑上串行，IO 上异步；不是每个 Adapter / Graph 都开一条业务线程。** .NET async continuation 可由运行时线程池恢复，线程身份不作为正确性依据；正确性来自单一队列与串行状态提交。

### 1.2 为什么适合首个闭环

1. **首个脚本工作负载很小**：ping/pong 只做字段读取、条件判断和一次异步 send；Jint 语句数与时限仍须显式设预算，不把所有脚本都假设成轻活。
2. **可复现**：同一输入与同一脚本版本按同一队列顺序执行，日志更容易还原因果；先不引入共享 JS realm 和状态竞争。
3. **异步 IO 不需要多线程业务逻辑**：等待 Adapter.send 的网络响应时，派发器可以处理别的已入队事件。
4. **保持已有模块约束一致**：同一模块实例内状态转移串行；脚本的跨模块调用经过 Graph Runtime（`01 §4`、文档 `13`）。
5. **足以验证架构中心**：先证明 Adapter → Graph/Jint → Adapter 的统一授权调用路径成立，再用测得的队列延迟决定是否需要并行化。

### 1.3 必须守住的实现边界

```text
外部回调 ──快速投递──▶ 单一事件队列 ──串行──▶ 图 / 模块状态
网络 IO   ──async await──────────────────────────┘
IO 完成   ──完成事件投回队列──────────────────────▶ 状态提交
```

- **不得在事件队列上同步阻塞**（`.Result` / `.Wait()` / 阻塞式 socket / 同步文件 IO）。
- Adapter 回调不得等待 Graph 完整处理后才返回平台线程；若协议要求 ACK，ACK 与 ALN 的持久化可靠性边界另行定义。
- 慢 `send` 必须 `await`，不能阻塞 OS 线程；若要等回执，等待期间派发器仍可处理其他输入。
- `await` 期间可以有多个 IO 在飞，但**共享业务状态不能在各自 continuation 中直接变更**：完成结果回到队列后串行应用。
- 队列必须有容量 / 背压策略；不允许无限积压。首版可以拒绝并记数，不允许静默丢弃。
- 单线程逻辑执行不等于“一步内所有副作用都并行”：相同模块实例的状态变更按事件顺序提交；发送请求是否允许多个在飞由 Adapter 的实例级串行策略决定，首版默认串行发送。

### 1.4 什么情况下再考虑多线程

先有运行数据再决定。满足以下任一项时，另起设计评估：

- 单队列的 P95 排队延迟超出产品目标，且 CPU 而不是外部 IO 是瓶颈；
- 大量独立 Adapter 的协议转换 / 媒体处理吃满单个 CPU 核；
- 必须保证一个 Adapter 的慢处理不拖住其他 Adapter，且有清晰的隔离边界。

届时优先**按 Adapter 实例或独立 IO/解析池分区**，图与共享 Channel 状态仍保持单一串行所有权；不要直接把所有模块方法改成可并行调用。

## 2. 首个垂直切片的工程步骤

| 步骤 | 产物 | 最小验收 |
|---|---|---|
| 1. 建解决方案骨架 | Contracts、Runtime、Graph、Scripting.Jint、Adapter.File、Host、Tests | 项目依赖单向；所有项目目标 `net10.0` |
| 2. 契约与 Manager | Address、Envelope、Result、Adapter 生命周期/发送、Manager 注册与查询 | 抽象不可实例化；Manager 是实例集合唯一所有者；Contracts 不引用实现或 OS IO 库 |
| 3. 单一异步派发队列 | 有界队列、取消、关闭、背压计数 | 并发入站时共享状态只串行提交；慢 IO 不堵塞入队 |
| 4. Graph manifest 与 Jint 宿主 | 脚本发现、manifest 校验、继承匹配、能力 facade、执行记录 | 未知事件/目标类型/能力或预算超限时拒绝启动；Jint 不获得任意 CLR 能力 |
| 5. FileAdapter | 测试入口注入 Envelope，send 输出可观察并可注入延迟/失败 | 测试走生产 Adapter 契约；不依赖外部平台 |
| 6. 默认挂载与端到端闭环 | Host 先装载/挂载脚本，再开放 Adapter 入站 | `ping` 发一次 `pong`；非命中零回复；回到来源实例 |
| 7. 生命周期与可诊断性 | 实例新增/销毁、脚本重载、执行记录 | 新实例先挂脚本再启动；销毁无残留；可追踪输入、脚本和能力调用 |

⚠️ 表内是工程顺序草案，不是最终模块接口；正式接口仍以 `10` 的迭代设计为准。任何工程实现若迫使修改 `01`/`02` 的核心边界，应先修设计文档，不在实现里偷偷留例外。

## 3. 最小验收案例

```text
输入：adapter.file#1 收到 { platformConversationId: "room-1", text: "ping" }
脚本：onEvent(event, ctx) 判断 text；命中时 await ctx.self.adapter.send(..."pong"...)
输出：adapter.file#1 观察到恰好一条发往 room-1 的 pong
```

反例：

- 输入 `hello` ⇒ 输出 0 条；
- default 脚本声明目标为不存在的抽象类型或声明未授予能力 ⇒ Host 启动失败；
- 脚本执行失败 ⇒ 输入有失败记录，不能伪装成“未命中”；
- 脚本尝试访问未注入的 CLR/系统能力 ⇒ 拒绝并记录；
- Adapter.send 延迟期间再注入 `ping` ⇒ 第二条输入仍能入队；共享状态仍只在派发队列串行提交。

### 3.1 会红的工程判据

1. 外部回调直接调用 Graph / Channel 实例 ⇒ 红；
2. 事件循环调用 `.Result` / `.Wait()` 或同步阻塞 IO ⇒ 红；
3. 脚本能力调用绕过统一 Runtime 的授权、取消和记录入口 ⇒ 红；
4. 条件命中一次产生两条发送 ⇒ 红；
5. 不命中仍发送，或命中后没有可查的因果记录 ⇒ 红；
6. 测试 Adapter 可用而生产 Adapter 契约无法同形实现 ⇒ 红。

## 4. 启动、失败与停机的暂定规则

首切片必须能做到以下最小工程语义，但暂不在此扩展为完整模块生命周期设计：

- **启动原子性**：Adapter 或 Graph 任一加载 / 校验失败，Host 不进入“运行中”；不能半装配后悄悄接消息。
- **先加载并校验脚本、完成 default 挂载，再开放 Adapter 入站**：避免收到消息时处理器尚未就绪。
- **停止时先拒绝新输入，再排空有界队列，最后关闭 Adapter**；超过关闭期限则记录未完成工作并退出。
- **运行期端口失败不杀整个进程**：输入事件关联的派发记为失败并可查；是否重试由该操作语义明确规定，首切片不自动重试非幂等 send。

这些规则覆盖 Adapter + Graph 的最小 Host；全模块依赖图、部分可用启动、升级迁移仍留待装配与启动设计。
