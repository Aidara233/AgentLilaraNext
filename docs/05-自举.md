## 0. 决定（一句话）

> **自举 = agent 能改两样东西：订阅表（连什么）和模块（做什么）。**
> **两样都是"能力容器里的代码"**——代码形态可以是 C#（内建/插件），但**"任意逻辑"必须跑在受限容器里**（WASM / Lua sandbox / 内置表达式），因为**语言里没有的原语，才是真正拿不到的能力**（详见 [`06-能力与审计.md`](06-能力与审计.md)）。

配套的一句话：**权限由"能引用/能 import 什么"在加载前决定，且一切能力调用过审计。**

⚠️ **本文件 §1 的原始理由（"agent 更喜欢正常代码"）已被修正为安全性理由**：脚本语言存在的根因不是好用，而是**正常 C# 太全，BCL 就是全部能力**。保留 §1 原文作推导记录。

## 1. 为什么砍掉"脚本语言"这一层

我上一版给过 L1 纯表达式 / L2 沙箱脚本 / L3 界碑。按你的两个理由，这个阶梯该收敛：

| 反对"自研 DSL"的理由 | 结论 |
|---|---|
| agent 擅长 C#，不擅长只有我们自己认识的语法 | 让它写 C#，省掉一整套语法、文档、工具与模型训练成本 |
| 配置表达力低 ⇒ 复杂需求被塞进配置 ⇒ 配置长成代码 | 更糟：那是**没有类型检查、没有编译器、没有测试**的代码 |
| "能碰 / 不能碰"跟正常代码很像 | 用**引用面**表达权限，比任何运行时闸门都更结构化（见 §3） |

于是 [`03`](03-自由逻辑.md) 的四级阶梯收敛成一句话：**规模不同，机制相同。全是 C#，全部编译。**

| 规模 | 形态 | 住哪 |
|---|---|---|
| 一条判定 | C# 表达式（编译成 `IEvaluator`） | 数据（源码字符串，随规则表） |
| 一小段逻辑 | 单函数模块（实现求值端口，返回意图） | 模块（源码） |
| 一个能力 | 完整模块（实现端口，真正的副作用） | 模块（源码） |

⚠️ **不变的那条界碑**：**"编排"仍然不许数据化**——订阅表仍然是有限的边集合，单条订阅仍然只有最后一个节点能是 `call`。复杂度可以去代码里（有编译器、有测试），**不能去数据里（没有工具链）**。

> 预算只管数据：订阅表 ≤12 条、单条 ≤8 节点。代码没有节点预算，但有编译、有校验、有测试、有回滚。

## 2. 自举的闭环

```
agent 写两样东西（都无需本地编译、无需 shell）：
  a) 订阅表（JSON，≤12 条）        → 结构校验 → 生效（不重启）
  b) JS 脚本（Jint 硬化工档）       → 反查用到的能力 → 按需注入 → 装载
                                    → 订阅指向它

失败 / 不满意 → 回滚到上一版「装配版本」（订阅表 + 脚本集合的快照）
```

⚠️ **自举产物不可能是"C# 源码编译成模块"**：没有本地 shell 就没有 `dotnet build`（[`06` §8.1](06-能力与审计.md)）。真需要新的 C# 模块＝**开发者行为**（改版本、进发布），不是自举行为。

⇒ 因此有一条干净的界线：**自举能加"行为"（订阅 + 脚本），不能加"能力"（碰 OS 的实现）。**

每次自举改动产生一个**装配版本**（数据）：可审计、可对比、可回滚、可重放。这是"演进自举"的全部机制——**不是热补丁，是版本**。

## 3. 权限：三层，全部在加载前

### 3.1 程序集引用面（第一层，最主要）

编译 agent 写的模块时，只给它引用 **Contracts**（数据模型 + 端口接口 + **能力接口的子集**）。

- 拿不到任何模块实现 ⇒ **结构上调不动世界**（这是 `I-18` 结构上排除的直接应用）；
- 要做事，只能返回意图（[`03` §2.1](03-自由逻辑.md)）或实现一个端口（由订阅接线）。

### 3.2 能力接口（第二层）

要读时钟、要网络、要写盘，必须拿到对应的**能力接口**（`IClock` / `IHttp` / `IStorage`…），而能力接口按模块声明的 `RequiredCapabilities` 由宿主注入。

> **"能不能碰" = "引用得到吗"。** 这句就是你说的"跟正常代码很像"——而且它不靠纪律，靠编译器。

## 3.3 ~~IL 白名单扫描~~ → 降级为事后防线（本文原判断已被 [`06`](06-能力与审计.md) 推翻）

我原写"三层权限，第三层是 IL 扫描"，并把它当主闸门。**错**：反射、动态加载、P/Invoke 的缝追不完，而且"事后检查能力存在" ≠ "构造上不存在该能力"。

修正后的三层（详见 [`06`](06-能力与审计.md)）：

1. **host 层是唯一碰 OS 的地方**（其余一切只拿 scoped 句柄）；
2. **能力 = 范围句柄**，不是权限位；
3. **任意逻辑跑在能力容器里**（WASM / Lua sandbox / 内置表达式）——**没有 import 就没有能力**，这才是结构性闸门。

IL 扫描保留，但只作为"最后一道事后发现"，不作为安全边界。⚠️ **它不足以保证安全，因此不能替代 §3.1/§3.2 与容器化。**

## 4. 威胁模型：安全是前置，不是后续（原判断作废）

原文写"防意外、不防恶意"，理由是"agent 本身有 shell 权限"。**这条作废**：接入群聊之后，威胁来自**外部输入**（群友消息不可信）与**第三方代码**（插件/脚本），而这两者都不该被信任；用户明确裁定 **安全性是绝对要求，不允许放宽**。

因此：

| 目标 | 地位 |
|---|---|
| **不可逃逸** | **前置要求**（靠能力容器 + 构造上不存在） |
| 可回退 / 可终止 / 可追溯 | 仍然必要，但都是**补充**，不是替代 |

⚠️ 由此引出一个必须先答的问题：**`shell` 这类万能出口是否存在于 ALN**。若有，上面全部作装饰。见 [`06` §8](06-能力与审计.md)。

## 5. 铁律：自举能改行为，不能改"什么算允许"

三样东西**不可自举**，写死在版本里：

1. **能力准入策略**（谁能拿哪些能力接口）
2. **出厂订阅**（一步的过程、入站/出站主链）
3. **权限 / 安全 / 验证强度的判定**

理由只有一个：否则自举会变成一个**权限提升环**——agent 给自己加能力，再给自己授权，再改判定说这是允许的。

⚠️ 但它可以**提议**：把改动写成一个待批的装配版本，由用户（或权限轴）批准后生效。这样"能改行为、不能改规则"就落成了一条具体的流程，而不是一句禁令。

## 6. 与已有规则的关系（一次对账）

| 已有条目 | 自举如何落上去 |
|---|---|
| `I-18` 结构上排除 | 引用面即权限；拿不到模块实现就调不动世界 |
| `I-06` 能力声明 | 从"声明一个枚举"变成"实现一个能力接口"，准入仍在**绑定前**；且能力 = scoped 句柄（[`06` §3](06-能力与审计.md)） |
| **`I-18` 结构上排除（强化）** | 自举的能力边界靠**容器**（语言里没有的原语 = 拿不到），不靠扫描；IL 扫描只作事后发现 |
| `J3` 加载期校验 | 订阅表校验 + IL 扫描 + 端口签名匹配，全在加载前 |
| `X-08` 开关矩阵 | 自举**取代**它：要改行为就改装配版本，不是加环境变量 |
| `J8` 出厂 vs 用户 | 自举只能动"用户"那半边 |
| `X-03` 按类型分支 | 仍然禁止：功能差异由订阅 + 模块表达，不由会话类型分支 |
