# 30 · 搜索与抓取：三层，各干一件事

> 状态：第一期已实现（`ALN.Web` + 两个工具 + 一个动作 + 25 条测试）。
>
> 本文回答一个问题：**模型怎么能"搜一下"和"读这页"，而这件事不会变成"这个进程能访问任意地址"。**

---

## 0. 三层，不是一个口

网站上的需求其实有三种，混在一个口里就会做出 `net_fetch` 那种半吊子（曾经做过，撤了）：

| 层 | 工具 | 地址从哪来 | 谁执行 | 私网 | 凭据 | 返回 |
|---|---|---|---|---|---|---|
| **受控** | `web_search` / `web_fetch` | 任意 URL | 供应商（或 local 自己） | local 可，其他不可 | 无 | 搜索条目 / Markdown 正文 |
| **硬核** | `http_request` | 任意 URL | 我们自己 | 可以 | 调用方自己带 | 状态 + 头 + 原始正文 |
| **具名** | `net.fetch`（动作，不是工具） | 配置里的 target | 我们自己 | 看 target | target 的 secret | 正文文本 |

三层的分工不是"自由度不同"，是**问题不同**：

- `web_fetch` 问的是"这页讲了什么"，所以它做 HTML→Markdown，返回能读的东西；
- `http_request` 问的是"这个接口回什么"，所以它返回状态码、响应头、最终地址，原样；
- `net_fetch` 问的是"调那个我登记过的服务"，所以它有路径白名单和凭据，模型看不到钥匙。

模型拿到前两个。第三个只有脚本（`ctx.actions.call`）和 WebUI 用 —— 因为它是"部署时的决定"，不是"这一轮的想法"。

---

## 1. 为什么 `web_fetch` 收完整 URL

**因为用户会直接把一个网址贴进来。** "看看这个" 后面跟着一条链接，是最常见的请求，比"搜一下某某"还常见。要求调用方先把地址登记成 target 再取，等于把这个功能关掉。

代价必须说清（`docs/29 §4` 的那道闸在这条路上**不生效**）：

| | `web_fetch` | `http_request` |
|---|---|---|
| 谁解析这个域名 | 供应商（deepseek/tavily）或我们的 local provider | 我们自己 |
| 私网/元数据检查 | **只有 local 有**（它是我们连的） | 有 |
| 审计里记什么 | URL 的路径部分（query 值去掉） | 同 |

所以 `web_fetch` 的**能力**由供应商决定，我们的**形状校验**只挡四件事：scheme 必须 http(s)、不能带 `user:pass`、长度上限、local 走的那条仍然过六道闸。一个公网域名解析到 `10.0.0.1` 我们看不见 —— 那一步在别人机器上。

`http_request` 反过来：地址是我们连的，所以私网规则生效，但它没有 allowlist，能挡的只有"不能设 Host 头"这一条。**每一行都留在审计里**，这是它唯一但真实的控制。

## 2. 两家供应商，事实对照

| | DeepSeek Search & Fetch | Tavily |
|---|---|---|
| 端点 | `POST /v1/tools/search`、`POST /v1/tools/fetch` | `POST /search`、`POST /extract` |
| 搜索参数 | `query`（支持 `site:` `-site:` `lang:` `after:` `before:` `"短语"` 操作符）、`count` 1–50、`ori_question`、`localization`（**一个 IP**）、`need_content` | `query` + `search_depth` / `max_results` 0–20 / `topic` / 时间窗 5 种 / `include_domains` ≤300 / `exclude_domains` ≤150 / `country` / `language` / `include_answer` / `include_raw_content` / `safe_search` / `exact_match` |
| 每条返回 | `rerank_score` 0–3、`authority` 0–4、`snippet` 100–200 字、`summary` 600–800 字、`content`、`date`、`site_name` | `title` `url` `content`（每块 ~500 字，最多 3 块拼接）`score` 0–1 `raw_content` `published_date` |
| 顶层多给 | 无 | `answer`（自带一次 LLM 生成）、`usage.credits` |
| 取正文 | `/v1/tools/fetch` 收任意 URL，回 Markdown | `/extract` 收 URL 列表，回正文 |
| 计费 | $0.75/1000 成功请求（search、fetch 各自），`count` 不影响价 | credit：basic/fast/ultra-fast 1、advanced 2 |
| 限流 | search 100 QPS、fetch 25 QPS（账户级 + fetch 每域） | 429 / 432(套餐) / 433(按量) / 434(实时抓取容量) |
| 错误格式 | OpenAI 兼容 | `detail.error`，或 `detail` 是校验数组 |

**两家都提供了"取出整页正文"的原语**，所以"两家都接、按配置切"是可行的，也是已经做到的。

### 2.1 两个接口，不是两个布尔位

```csharp
interface IWebProvider { string Name { get; } }
interface ISearchProvider : IWebProvider { … SearchAsync … }
interface IFetchProvider : IWebProvider { … FetchAsync … }
```

`CanSearch` / `CanFetch` 那样的字段迟早和实现对不上；实现了就一定行，没实现就**根本拿不到那个方法**。于是：

- `local` 只实现 `IFetchProvider`，"它不能搜"不是一条校验，是一个不存在的方法；
- 以后加只做搜索的（Brave / Exa）只实现一个接口，`fetch` 那条路一行不用改。

注册表是**两张表**，因为 `search` 和 `fetch` 是两条独立的部署决定。"Tavily 搜、DeepSeek 取正文"是最常见的组合，不是配错。

## 3. 两段式，而且 `answer` 永远关掉

三个字段在代码里写死为 `false`，**不给配置**：

| 字段 | 谁 | 为什么固定 |
|---|---|---|
| `need_content` | DeepSeek | 十条结果各带整页 = 一轮上下文报废 |
| `include_raw_content` | Tavily | 同上 |
| `include_answer` | Tavily | 它会让 Tavily 先用自己的 LLM 写一段答案，再交给我们的模型读 —— 两层翻译、两份幻觉来源。**我们自己的模型就在那里。** |

这不是部署偏好，是设计：**我们只买料，不买结论**。

所以工具是两步：`web_search` 拿指针（title + URL + 短摘要），`web_fetch` 把要读的那一个变成正文。默认一轮最多 3 次搜索、8 次取页，超了直接告诉模型"这一轮够了"。

---

## 4. `local`：唯一的"我们自己取"

它给的是另外两家结构上给不了的东西：

| | 为什么别人给不了 |
|---|---|
| 内网 / `127.0.0.1` / `.local` | 供应商的机器到不了你的局域网 |
| 页面不经过第三方 | 敏感内网页面不该交给外部索引服务 |
| 不花钱 | 每次 $0.00075 看起来小，循环起来不小 |
| 自己的 UA / 超时 / 重定向策略 | 供应商只有它给的选项 |

代价只有一件事，但它是真的：**HTML→正文我们自己写**。这里用 `ReverseMarkdown`（MIT、纯托管、依赖 AngleSharp），包在 `IHtmlToText` 的位置上，换实现是一个类的替换。质量不如 Tavily 多年的提取器 —— 这一点写在 §10。

**私网默认开放**（`localAllowPrivate: true`）。理由是这里的目标本来就是"贴一个地址就能读"。代价：`web_fetch` 于是能打到本机任何端口，包括 `127.0.0.1:5199` 的 API（它有令牌，所以只会 401，但这仍是一次内网探测能力）。缓解不是关掉它，而是让它**不隐形**：审计里写 `local:<authority>`，`net.request` 那行还记下真正连上的 IP。

## 5. 配置：`<DataRoot>/web/search.json`

文件不存在 = **两个工具都不出现**。这是全新数据根的默认，与 `api/server.json`、`net/targets.json` 同一条规矩：一个默认值就是一次没人做过的决定。

```json
{
  "search": "tavily",
  "fetch": "local",

  "maxResults": 8,
  "maxChars": 32000,
  "searchesPerTurn": 3,
  "fetchesPerTurn": 8,
  "cacheMinutes": 10,

  "deepseekTarget": "deepseek",
  "deepseekCount": 8,
  "deepseekLocalization": null,

  "tavilyTarget": "tavily",
  "tavilyDepth": "basic",
  "tavilyTopic": "general",
  "tavilyCountry": null,
  "tavilyLanguage": null,

  "localAllowPrivate": true,
  "localMaxBytes": 2097152,
  "localTimeoutSeconds": 20
}
```

| 字段 | 缺省 | 说明 |
|---|---|---|
| `search` / `fetch` | 无 = 该能力不提供 | provider 名：`deepseek` / `tavily` / `local` |
| `maxResults` | 8 | 调用方可以要更少，不能要更多 |
| `maxChars` | 32000 | 一页正文的上限；超了标 `Truncated` |
| `searchesPerTurn` / `fetchesPerTurn` | 3 / 8 | 一轮的上限，`0` = 不许 |
| `cacheMinutes` | 10 | 同一 URL 在这段时间内直接回缓存；`0` = 不缓存 |
| `deepseekTarget` / `tavilyTarget` | 同名 | 指向 `net/targets.json` 里的哪一条；**凭据在那边**（`secret` → `FileSecretStore`） |
| `deepseekLocalization` | null | **是 IP 地址**，填了等于告诉供应商你在哪 |
| `tavilyDepth` | basic | `advanced` 双倍 credit |
| `localAllowPrivate` | **true** | 见 §4 |

数值越界不会静默替换：响应里的 `Issues` 逐条进 `web: …` 的启动输出，用默认值继续跑。

**启动收据**一行，说清谁在干什么、哪些名字可用：

```
restored web: search=tavily fetch=local; can search: deepseek, tavily; can fetch: deepseek, local, tavily
```

配成 `"search": "local"` 时这一行会显示 `search=local` 而 `can search` 里没有它 —— 调用会得到 `NotConfigured`，`Detail` 里列出可用的名字。

## 6. 配额、缓存、审计

- **配额**按轮：`WebTools.ToolsAsync` 每轮造一个预算，search 与 fetch 各自计数。超额是 `Conflict`、**不可重试**（这一轮没救了，下一轮才有）。
- **缓存**在网关：键是规范化 URL，`cacheMinutes` 过期，上限 200 条。**命中缓存不消耗配额**，审计记 `cache`。同一 URL 不同 `maxChars` 复用同一条，返回前重新截断。
- **审计**两条：`web.search`（provider、query **原文**、结果数、耗时）、`web.fetch`（provider、URL 的路径部分、字符数、耗时、是否缓存）。actor 是 `model` / `test` 这类调用者。
  - query 记原文是按明确的选择做的，含义是**搜索词与会话内容同等对待**：它们都会进 `aln.db` 的审计表。
  - URL 的 query **值**不记（`docs/29 §6` 的既有规则），路径记。
- **信号**：`Group=web`、`Name=<provider>`、`Mechanism=search|fetch`。

## 7. 错误映射

供应商的状态码在 provider 里就译成 `WebErrorKind`，网关之上不再出现 HTTP 词汇。

| 状态 | DeepSeek | Tavily | 可重试 |
|---|---|---|---|
| 400 / 413 / 422 | `InvalidUrl` | `InvalidUrl` | 否 |
| 401 | `NotConfigured` | `NotConfigured` | 否 |
| 402 | `Quota` | — | 否 |
| 403 | `Blocked`（安全策略拒绝） | — | 否 |
| 404 | `NoContent`（取不到可用正文） | — | 否 |
| 429 | `RateLimited` | `RateLimited` | 是 |
| 432 / 433 | — | `Quota`（套餐 / 按量上限） | 否 |
| 434 | — | `RateLimited`（实时抓取容量不足） | 是 |
| 5xx / 504 | `Upstream` / `Timeout` | 同 | 是 |

**空结果不是错误**：`hits: []` 是成功，工具回答"没找到，换个说法"。把它当失败，模型会去跟用户说"搜索坏了"。

## 8. 明确不做

| 不做 | 为什么 |
|---|---|
| `crawl` / `map` / 多页深入研究 | 那是另一个产品，不是一个工具调用 |
| 让模型自动"搜了再搜" | `searchesPerTurn` 就是为这件事设的上限；自激在结构上不可能（`I-22`） |
| 供应商自己的 `answer` | 见 §3 |
| 会话罐（Cookie / 登录态） | `http_request` 能带一次性的头，跨调用的状态是另一个东西 |
| 把 provider 做成可热插拔的包 | 它们没有生命周期：被调用时存在，不调用时不存在。做成模块要牵进 kernel 的相位与依赖排序，换不到任何东西 |
| `web_fetch` 返回 HTML | 返回 HTML 等于把"提取"这件事推给模型，模型会把它烧掉的上下文换成一次正则 |

## 10. 现状、验证与没做的事

**已实现**：`ALN.Contracts/Web`（两个 provider 接口 + 注册表 + 7 个 DTO + 错误分类）、`ALN.Web`（`DeepSeekProvider`、`TavilyProvider`、`LocalProvider`、`WebProviderRegistry`、`WebGateway`、`WebOptionsFile`、`WebTools`）、`ALN.Net/HttpActions`（`http.request` 动作）与 `HttpTools`（`http_request` 工具）、`IAdHocNetAccess`（`HttpNetAccess` 实现，与具名路径共用同一段核心）、宿主装配与收据行。

**离线可验证的部分都有测试**（25 条）：

- DeepSeek 的 search 响应解析（`rerank_score` → 分数与上限、`authority`、`date`），且请求体里 `need_content` 是 `false`；
- Tavily 的同样是 `false` 的 `include_answer` 与 `include_raw_content`；
- 空 `results` 是成功；
- 五种状态码各自译对、可重试标记对；Tavily 的 432 是 `Quota` 且**不可重试**，错误消息里保留供应商原话；
- `local` 把 HTML 变成 Markdown：标题进 `#`、`<script>` 与 `<style>` 的内容不出现；
- `local` 的 404 是 `NoContent`；
- 网关缓存：同一 URL 两次、服务器计数仍是 1；
- 混搭部署（Tavily 搜 + local 取）跑通；
- 没配 provider 时两个能力都是 null，而 provider 仍在可用列表里；
- `http.request` 返回状态/头/正文/最终地址；`Host` 头被拒；`file:` 与带 `user:pass` 的地址被拒；
- `http_request` 的 schema 里有 `url`，描述里指路 `web_fetch`。

**没有验证的（明确的空白）**：

1. **一次真实的 DeepSeek 或 Tavily 调用都没跑过。** 没有 key，所有测试都对着本机 socket。响应形状是按官方文档写的，字段名、错误体形状、`/extract` 的 `raw_content` 是否真叫这个名字，都还没有被现实核对。
2. **`ori_question` 没启用。** 这个字段要的是"触发搜索的用户原话"，而工具层现在只拿到模型写的 query。传 query 自己等于传了个空 —— 所以现在传 `null`。接上 `RoundContextRequest` 里的用户输入是一行改动，前提是那个字段先确认拿得到。
3. **`local` 的提取质量没有与 Tavily 对比过。** 一个真实文档站、一篇博客、一个 JS 渲染的页面，三种情况都该各跑一次。
4. **JS 渲染的页面 `local` 取不到东西**（它只做静态 HTML）。这类页面只能靠供应商，或者以后的浏览器 provider。
5. **缓存没有失效策略**：10 分钟内读同一页会拿到旧内容，没有 "bypass cache" 参数。
6. **WebUI 没有入口**：`http.request` 是动作，界面里的"动作"页可以直接调；`web_search` / `web_fetch` 是工具，界面上没有"试一下"的框。
7. **`web_search` 的 `domains` 传给 DeepSeek 时是拼进 query 的 `site:` 操作符**，两家对它的解释不完全一样；跨家对比行为没有测过。
