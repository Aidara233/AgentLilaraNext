# 32 · 指令：人在对话里下的一句话

> 状态：第一期已实现（`ALN.Commands` + 契约 + 派发前钩子 + 12 条测试）。真机未验，见 §8。
>
> 本文回答一个问题：**一个人在群里打一句 `//reload`，为什么不该经过模型，又凭什么轮到他来下这条命令。**

---

## 0. 它是什么，不是什么

| | |
|---|---|
| 是 | **人在频道里发出、宿主直接执行、不进入频道也不进入模型**的一条命令。执行体是已有 action 的一层薄壳。 |
| 不是 | 模型可用的工具（那是 `actions_call`）；不是脚本语法；不是 shell（没有管道、重定向、子命令求值，`X-13` 已作废）。 |

它解决的是一个具体的缺口：**等级体系里没有"人在场"的入口**。Agent 级会话不能改系统，向上请求只能靠模型自觉（`I-28`），而人常常不在终端前。指令让"人在群里说一句话"成为一种**确定性的、可审计的、能按等级放行**的动作。

---

## 1. 拦截点：适配器之后、频道之前

```
Adapter ──publish──▶ EventQueue ──▶ EventPump ──▶ graph.DispatchAsync ──▶ 脚本 ──▶ channel.accept ──▶ Channel ──▶ Session
                                        │
                                        └─ 指令：在这里被取走
```

`EventPump` 在派发之前给拦截器一次机会（`IEnvelopeInterceptor`）。命中的消息：

- **不写频道历史**（`AcceptAsync` 根本没被调用），
- **不产生** `channel.message.accepted`，不进 delta，
- **不被脚本看见**（脚本在 `dispatch` 里），
- **不被 Session 感知**。

这是整条链上唯一能做到"取走"的位置。再往后的任何一个点都至少会留下一样东西：频道历史、pending 标记、或者一条被脚本读到的 envelope。

### 1.1 代价：去重必须自理

频道层的重复投递检查按 `platformMessageId` 做，而它在下游、永远看不到这条消息。所以注册表自己记一份 `(adapter, platformMessageId)` 的 LRU（512 条）。**没有这一步，适配器重连重投递就会让 `//reload` 执行两次。**

### 1.2 代价：回复不进频道历史

回复直接走 `IAdapterManager` → `IOutboundAdapter.SendAsync`，而 `speak` 走的是 `RecordReplyAsync`（会留一行）。所以暂停之后模型**看不到**"我回答过 `//help`"。一期接受这个断裂：指令本来就不是模型的对话内容；二期若要接上，是在会话被唤醒时补一行系统记录，不是改这里的路径。

---

## 2. 前缀

默认 `//`，环境变量 `ALN_COMMANDS_PREFIX` 覆盖。

选双斜杠的理由是**误报的代价不对称**：一条以 `//` 开头的消息会被**回答**（而不是当作普通文本），所以前缀撞车的代价是吞掉一句人真正想说的话；单斜杠在路径、URL、以及半个群的 bot 里都太常见。

`https://…` 不是指令（它不以 `//` 开头）。前面的空格会被容忍（手机键盘会加）。

---

## 3. 指令树：`//order a` 里的 `order` 是一个模块

```csharp
new CommandNode("order", "下单", MinLevel: AccessLevel.Agent)                       // 命名空间
new CommandNode("order.add", "下一单", MinLevel: AccessLevel.Agent, Body: …)        // 叶子
```

**一个路径要么是叶子、要么是命名空间，不能两者都是。** 这一条换来的是解析没有歧义：

| 输入 | 结果 |
|---|---|
| `//order add x` | 走到叶子 `order.add`，`x` 是参数 |
| `//order` | 命名空间无参 = 列出子指令（也就是这一支的 help） |
| `//order zzz` | 报错，并列出 `order` 下有的名字 |
| `//say hi` | `say` 是叶子，`hi` 是参数 |

代价是不能像 `git` 那样"既是命令又是命名空间"——但 `git` 无参也是 help，所以这个代价是零。

其它规则：最多 3 段；名字 `a-z0-9_-`，≤32；大小写不敏感；双引号可包空白（`//say "hello world"`）；注册冲突（重复、叶子下挂子节点、命名空间变叶子）**注册时即拒**，不覆盖。

**命名空间的 `MinLevel` 决定整棵子树的可见性**：一个 operator 级的命名空间，agent 连它下面有什么都看不到。

---

## 4. 谁能发：身份表就是权限表

一条指令的调用者身份只有一处来源：**消息信封的 `(adapter, sender)` 经 `IPersonDirectory.Find` 得到的那个人的 `level`**。没有第二处：参数不能自报（`//help --as=xiaolin` 无效），模型不能代替（它没有频道入口），脚本不能冒充（脚本注册的指令以脚本身份执行，见 §6）。

| 谁 | 深度 | 能发 |
|---|---|---|
| 没登记的人（`null`） | `L0 agent` | 显式标 `agent` 的指令（`//help`、`//whoami`、`//status`） |
| `level: agent` 的卡 | `L0` | 同上 |
| `level: operator` 的卡 | `L1` | 全部内置指令 |
| `level: full` 的卡 | `L2` | 全部；但这只能人手写 `info.json`（`identity.people.level` 只能授出 ≤ 自己） |

放行判据与 action 完全同构：`人的 level ≥ 指令的 MinLevel`。内置指令的缺省是 `operator`——**没声明的指令都是要人来做的事**。

执行时构造的 actor 是 `command:<人的 id>`，深度是他的 `level`。于是 `sessions.setLevel` 的 `AssignsLevel` 照常生效：一个人不可能在群里把自己升成 `full`，也不可能把会话升到比自己深。

## 5. 一条指令的一生（含错误语义）

```
//order add "两个 苹果"
  ├─ 前缀匹配？否 → Pass，交给脚本（模型照旧看得见）
  ├─ 去重：这条 platformMessageId 见过？是 → 静默丢弃，outcome=duplicate
  ├─ 限流：这个人这一分钟超过 10 条？是 → **静默**丢弃 + 一条 throttled（不回复，否则限流成了放大器）
  ├─ 解析：逐词下降。找不到 → 回错误（含"它有什么"），记 invalid
  ├─ 判级：人的 level < 节点 MinLevel？→ 回一条"需要 L1 operator，你是 L0 agent"，记 denied
  ├─ 执行：Body(context)
  ├─ 回复：走 adapter，replyTo = 原消息 id
  └─ 审计：signal（group=command）+ audit（action=command.<名字>）
```

错误一律**回答**（人打了前缀就是有话要说），但一律**不落库**、不进模型。同一个节点失败不会 fall through 成普通消息。

## 6. 脚本自制指令（第二期，本期未实现）

允许模型通过脚本注册自己的指令——`//order` 这类东西本来就该由脚本提供。但形状必须是这六条，缺一条都会变成提权：

| 闸 | 规则 | 防的是什么 |
|---|---|---|
| 开关 | `ALN_COMMANDS_SCRIPTED=true`，**默认关** | 模型的影响面自动伸进人的输入通道 |
| 下限 | 脚本指令 `MinLevel ≥ operator`，不接受脚本声明更低 | 陌生人替模型触发代码 |
| 路径 | 只能注册未被内置占用的路径，冲突即拒 | 冒充 `//reload`，让人以为在跑内置 |
| 身份 | handler 以**脚本自己的** actor 执行（深度/能力来自脚本） | 借发送者的等级提权——最关键的一条 |
| 生命周期 | `owner = script:<实例>`，卸载/重载即收回 | 幽灵指令 |
| 可见性 | `//help` 标来源，审计记 owner | 人以为在用人写的东西 |

---

## 7. 明确不做

| 不做 | 为什么 |
|---|---|
| `//level` | 指令在频道之前，手上只有 `(adapter, conversation)`，要先把 conversation → binding → channel → session 的映射做对。它是第一个改系统的写动作，值得单独一期 |
| `//stop` / `//resume` | **死锁**：指令在 adapter 之后，停掉 adapter 就再也收不到指令，只能回终端恢复 |
| 指令进频道历史 / 进模型上下文 | 那正是这套系统要避免的（§1.2 说了代价） |
| 管道、重定向、子命令求值 | 那是 shell，不是这个 |
| 用频道等级代替人的等级 | 群是公共的，等级必须落在人身上 |

---

## 8. 现状、验证与没做的事

**已实现**：`ALN.Contracts/Commands`（`CommandNode`、`CommandContext`、`CommandInvocation`、`CommandOutcome`、`EnvelopeDisposition`、`IEnvelopeInterceptor`、`ICommandRegistry`）、`ALN.Commands`（`CommandRegistry`、`CommandInterceptor`、`BuiltinCommands`、`CommandOptions`）、`EventPump` 的派发前钩子（`null` 时行为不变）、宿主装配与启动收据行。

**有测试的**（`CommandTests`，12 条）：树与命名空间、叶/命名空间互斥、未知路径与未知子指令的错误文案、`owner` 收回、陌生人的 `L0` 与 operator 指令被拒（含审计落 `denied`）、同一个人 operator 级可用、help 按等级过滤、`//whoami` 的两种回答、重复 `platformMessageId` 只执行一次、限流静默、前缀可配、非指令返回 `Pass`、payload 与事件不自洽被拒。

**没有验证的**：

1. **真机零次**：QQ 群里的 `//help`、`//reload` 没有跑过；`@机器人 //help` 里 @ 是否已被适配器剥掉没有确认。
2. **发送路径没测**：测试里的 `IAdapterManager` 永远返回失败，所以"回复真的发出去了"只有代码路径，没有断言。
3. **`//status` / `//reload` 的输出形状是猜的**：`Flatten` 只取顶层标量前 6 个字段，`system.info` 与 `scripts.reload` 的真实 JSON 字段名没有对齐过。
4. **`commands.scripted` 只有开关，没有实现**：§6 的六道闸是设计，代码里还没有脚本注册入口。
5. **限流窗口是固定 60 秒**，不是滑动窗口：一分钟的边界上可以过 2N 条。
6. **指令层的审计没有和 `signals.recent` 之外的工具对齐**：`audit` 里的 action 叫 `command.<名字>`，还没有任何查询入口按这个前缀过滤。
