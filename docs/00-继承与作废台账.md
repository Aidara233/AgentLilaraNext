## 一、从 ALP 继承（`I-01` – `I-09`）

| 编号 | 条目 | 为什么它是对的 | 怎么证明没走回头路 |
|---|---|---|---|
| `I-01` | **统一会话、不子类化**：一种会话，行为由 `SessionSpec` 组装（模型/提示词/工具/预算/初始状态） | 会话形态应由内容决定，不是由「它挂在哪个频道」决定；子类化会逼出同一段逻辑在每个子类各写一遍 | 类型层断言：会话类型只有一个具体实现；出现第 2 个 `class *Session` 即红 |
| `I-02` | **三件套持久化**：`spec.json` / `state.json` / `history.jsonl`，`formatVersion` 显式 | 追加型 history 与全量 state 分开写，崩溃恢复语义简单；`formatVersion` 让升级路径可枚举 | ① 无 `formatVersion` 的落盘写入即红；② 断点重启后从 state+history 复原的往返测试 |
| `I-03` | **工具契约窄 + 元数据外置**：接口只留 `Name/Description/Parameters/Execute`，`Group/ContinueLoop/OutputOnly` 这类行为元数据走特性 | 插件只需实现一个方法；schema 有默认推导，不强制手写 | 契约接口的方法数上限（>4 即红） |
| `I-04` | **插件路径只能由宿主注入**：`Global/Instance/Workspace/Data` 四类目录由宿主按「插件名 + 作用域」绑好 | 插件永远拿不到绝对路径，「越权写盘」在类型层就表达不出来 | 契约程序集里出现 `Path` / `Directory` / `File` 类型即红 |
| `I-05` | **模块 = 接口 + 描述符投影**：`[Module]` 标在 **interface** 上，公开方法/属性投影成可枚举的节点类型；**未绑定实现 → 加载期失败**；公开方法未标注 → 描述符生成失败 | 「清单与实现永远同步」被类型系统 + 加载期校验强制，不靠人记；「图上凭空少一个节点」变成显式错误 | ① 未绑定实现时的加载必须抛错（正向测试）；② 无描述符的公开成员必须让生成器失败 |
| `I-06` | **能力声明，而不是假沙箱**：模块声明 `RequiredCapabilities`（net/disk/db/exec/secret），宿主在**绑定前**准入，拒绝是硬失败 | 老实承认进程内没有代码沙箱；比假装有隔离诚实 | 声明超集的模块必须绑不上（正向测试）；代码里出现「沙箱」语义的 API 即红 |
| `I-07` | **反向测试防过期**：把架构意图变成会红的测试（读编译后 DLL 元数据断言边界；对每张出厂图做「装载→挂载→求解→断言产出」；用 `Assert.Single` 卡住静默失败） | 散文会漂，测试不会；且测试自己声明局限，不冒充证明 | 见 `X-04` / `X-05`：边界测试必须覆盖**程序集名与目录两种入口** |
| `I-08` | **决策台账含推翻项**：只写结论不够，必须写「为什么否掉」；推翻项也要收进台账，不能只留在被推翻的文档里 | 重写项目最大的浪费是重新讨论已经吵过的事 | 本文件 + 后续用于替换的决策日志；`X-` 条目一律带理由（无理由的 `X-` 即红，人工审） |
| `I-09` | **淘汰清单带前置条件**：每条写规模、为什么删、**删除的前置条件**，从而可排序 | 避免「删了一半发现没有替代」 | 每个 `X-` 条目必须能被回答「不满足它会不会出事」 |

## 二、从 ALC 继承（`I-10` – `I-18`）

| 编号 | 条目 | 为什么它是对的 | 怎么证明没走回头路 |
|---|---|---|---|
| `I-10` | **母原则：前缀稳定性**——上下文逐字节喂给上游，缓存只认前缀；所有失效触发源（过期/换模型/断链/闲置）坍缩成同一个事件；「平时克制以保前缀，失效时放肆以还债」 | 它把整个系统的经济学压缩成一条判据，且**运行时每一步都在付账** | 逐字节稳定性测试：同输入两次渲染必须逐字节相同；历史只追加 |
| `I-11` | **会话 = 配置 ⊗ 结构化记录；会话是数据，推进是过程** | 行为不挂在会话上，于是「重启恢复」「父死子活」「空闲不占资源」全部变成同一件事的推论，不需要各自的状态机 | 会话类型不得持有长生命周期后台循环/定时器/订阅（结构性：构造参数里出现 `Task`/`Timer` 即红） |
| `I-12` | **头核分离**：头 = 观察者 + 命令源，不是执行路径；命令投递即返回，结果以事件流出；「卡住」是一等状态且持久化 | 核心离线期间照常干活；头重连按游标补齐 | 控制面契约里不得出现阻塞式 RPC 语义（返回体类型只能是回执或订阅句柄） |
| `I-13` | **记录 = 系统块 + 时间线（第 0 条是开场 user 消息）+ 本轮注入块（末尾，其中浮动不落盘）；块数恒定** | 块边界 = 缓存断点 = 失效爆炸半径；块数随插件数漂移的话，缓存断点与位置语义全部跟着动 | 渲染结果块数断言（与插件数量无关的固定值） |
| `I-14` | **工具是渲染器**：执行/渲染/优化/取消四钩子；结果 = 引用 + 快照 + 指纹；**渲染必须是纯函数**；不可重演类永久保留并冻结形态 | 否则重建历史会重发邮件；快照是「不想破缓存时还有旧内容可喂」的唯一手段 | ① 同输入两次渲染逐字节相同；② 不可重演类结果落盘后不再被重新渲染 |
| `I-15` | **核心是空壳：内容全由模块提供，含系统提示词**；「没有任何模块」是合法形态（纯 chat）；内核只留**机制入口** | 这是「能力自举」的第一层（见 `C`），也是把「能跑」与「能干活」分开的唯一办法 | 「零模块可启动」测试：空模块目录下核心必须起得来、能跑完一步 |
| `I-16` | **机制与策略分离；知识住在知识所在的地方**（脏不脏问工具、协议怪癖问适配器、提示词问模块、装配问内核），没有全局裁判 | 让边界收敛成「谁的知识谁负责」，而不是不断加中央协调层 | 契约程序集不得引用具体实现程序集（编译期即红） |
| `I-17` | **能派生的不要持久化**；顺序、指纹、索引这类「算得出来」的东西不落盘 | 持久化状态会因与真相无关的原因变化（重装/迁移/漂移/损坏），每一次都是一次缓存失效 | 落盘 schema 里出现「可算字段」即红（人工审 + 该字段必须有唯一派生源） |
| `I-18` | **结构上排除，而非规则禁止** | 好设计让错误不可能发生（如工具调用/结果是一块的两面 → 悬空不可能发生） | 每条禁令优先改写为「类型层不可能」；只留无法结构化排除的才写纪律 |

## 三、安全与机制的反向要求（`I-19` – `I-24`）

| 编号 | 条目 | 为什么它是对的 | 怎么证明没走回头路 |
|---|---|---|---|
| `I-19` | **ALN 自己不具备能力**：内核与模块都不直接碰 OS，唯一碰 OS 的是一层极小的 host；上层只拿 scoped 句柄 | 这是"所有接口都受限"能成立的前提；否则每个模块都是逃逸口 | `Contracts` 与各模块程序集引用 `System.IO`/`System.Net` 即红（并入 `E2`） |
| `I-20` | **任意逻辑跑在能力容器里**：语言里没有的原语 = 拿不到的能力（Jint 硬化工档 / WASM 无 import），**不是"有但被扫描拒绝"** | 事后检查 ≠ 构造上不存在；IL 扫描追不完反射与动态代码 | 一条反向测试：容器里写 `System.IO.File` 必须失败；且全库 `AllowClr` 只允许出现在 host 白名单文件 |
| `I-21` | **单向刹车**：`lock()` 任何内部权限都能触发，`unlock()` 只有用户能；锁状态**落盘**，在飞的步允许收尾 | 内核不给硬上限，就必须有一个"一定能停下来"的机制；而**非对称**（能锁的主体 ⊃ 能解的主体）才是它有效的原因——否则等于没锁 | ① `unlock` 不出现在任何工具表/能力清单里（`grep` 即知）；② 锁定后重启仍锁定（可测）；③ 解锁路径只有控制面一条 |
| `I-22` | **模型看不见自己发的消息**：bot 的输出不回流进上下文，模型只靠自己的 `tool_use` 记录知道自己说了什么（同 ALP） | 自激在结构上不可能，不必靠"打标记再过滤"这类易漏补丁；回声只用于回执与对账 | 反向测试：让会话发一条消息后，下一步的请求里不得出现该消息（除它自己的 tool_use 参数） |
| `I-23` | **工具双超时**：`syncWait`（模型愿意卡多久）+ `asyncDeadline`（转异步后的硬上限）；同步超时后**承认超时并转异步**，模型继续循环 | 一次慢调用不该让整个会话停住；而"干等"与"永远挂着"都要有明确边界 | ① 同步超时必须回一条"已转异步"结果块（保证配对）；② 异步到点必须真取消而非仅标记；③ 每个工具都声明这两个时间 |
| `I-24` | **信号日志是派发的副产品**：每次 emit / call 在**唯一派发点**记一条结构化记录（`stepId` / `edgeId` / `from` / `to` / `mechanism` / 结局 / 耗时），分组 + 命名 + 结构化 detail（沿用 ALP `ISignalLogger` 的形状），级别由单一配置源的 `MinLevel` 控制；**信号日志与审计是两条通道，不可合并** | 因果在产生时就已知（边是装配期数据），所以 ALP 事后才补出来的"拍 + `causes[]`"在 ALN 是派发的副产品，不是另一个要维护的子系统；反过来，若记录散在各模块里，"漏记"就只能靠纪律 | ① 模块内不得直接写链路日志（只有驱动派发点可写，依赖注入即可判）；② 把级别调到最高不得让任何审计条目消失（测试）；③ 日志写入失败不得改变任何派发结果 |
| `I-25` | **长会话靠"折叠 → 检查点 → 回收"三段，顺序不可颠倒**：折叠只改这一次请求带多少（记录不动、可逆），检查点把旧的那段换成一条 `role: system` 的摘要记录（记录仍不删，装配从它开始，块数不变），回收才真的按边界扔；三者都只在**装配期**发生，时间线永远只追加 | 请求的代价是每轮都付的，所以"少带"必须分层：能免费拿回的（工具结果、写文件的正文）先缩成提纲，再不行才花一次模型调用换一段摘要，最后才由人/模型声明"这件事办完了"。跳过前两层直接摘要是把免费的信息卖了一个价钱；而把压缩做成滑动窗口则是每轮改前缀——缓存全灭，省下的 token 数被单价吃掉 | ① 折叠后同一份时间线两次装配逐字节相同；② 检查点之后单次请求不再包含被它覆盖的记录，但 `history.jsonl` 里一条不少；③ 摘要超过上限时从中间砍（保留"还悬着"那节）；④ 连续两轮不得重复压缩同一段（`coversUpTo` 必须前进） |
| `I-26` | **权限本身也是接口**：接口有等级（写死在代码表里，改它 = 改代码/重挂载），调用者有等级（有动作、热生效）；任何"定级/授权"动作只能授出 **≤ 自己** 的等级，且**不存在**能改等级表的动作 | 一个能改写"谁能碰什么"的接口就是唯一真正重要的接口；而"能委派"若不封顶，就等于"能给自己升"。两面必须不对称：一个能拧，一个不能拧 | ① `AccessLevels` 无任何公有可变成员（反射测试）；② 交出去的等级高于自己的调用一律 Denied（测试两个方向）；③ 模型 actor 的 `*` 被等级取代——模型是 Agent，不是第二个操作员 |

## 四、明确作废（`X-01` – `X-16`）

> 作废 = **不要在新项目里重新长出来**，不是「ALP 没做完」。

| 编号 | 作废的东西 | 错在哪 | 判据 |
|---|---|---|---|
| `X-01` | **引擎生态**：`MasterEngine` + `ISubEngine` + `SpawnCheck` 注册表（把「要不要起一个引擎」做成可插拔判定） | 它把「生命周期」变成扩展点，于是任何新架构都只能寄生在旧扩展点里（ALP 的图运行时就是接在 `ExpressEngineSpawnCheck` 内部）。替换成本随每次新功能单调上升 | 代码里出现 `SpawnCheck` / `ISubEngine` 概念即红 |
| `X-02` | **资源池 + 频道 claim + 端口权重激活**（mention=100 / normal=5 攒满） | QQ 频道中断模型被雕刻进内核；ALC 已判定「用事件驱动的显式唤醒替代」 | 会话状态里出现权重/占用/池的概念即红 |
| `X-03` | **按类型分支的会话预设**（`SessionTypeProfiles` 内置种子 + `type` 决定分支） | 与 `I-01` 冲突：类型一旦分支，统一会话就退化成伪装过的子类 | 内核里出现 `switch (session.Type)` 即红（人工审） |
| `X-04` | **搬文件不搬命名空间**（`src/Lilara.Session` 声明 `namespace AgentCoreProcessor.Engine.Session`）+ **`InternalsVisibleTo` 全开**（16 个库把 internal 开给宿主） | 它让程序集边界与源码可读性脱钩：封装为零，且「同一职责两处实现」在编译期不可检测（两侧无同名类型 → 不会红）。**这是 ALP 全部混乱的乘数项** | ① 任何实现程序集不得 `InternalsVisibleTo` 给宿主；② 命名空间根必须等于程序集名 |
| `X-05` | **空占位项目 / 命名空间幽灵**（`src/AgentLilara.GraphRuntime`、`GraphModules`、`GraphSandbox` 零文件，而对应命名空间真实存在于别的程序集，测试也真实存在） | 制造三个互相矛盾的真相（目录空 / 命名空间真 / 测试真），并**欺骗一切自动检查**——ALP 的边界测试用 `Directory.GetDirectories("src","Lilara.*")` 扫，永远扫不到这三个 | ① sln 里每个项目目录必须含至少一个源文件；② 扫描入口必须**同时**覆盖 sln 与目录树 |
| `X-06` | **两套生命周期词表并存**（`[Lifecycle(mount\|kill)]` vs SDK 的 9 钩子） | 先定了新词表又保留旧词表，导致任何一侧都无法被真正废弃 | 生命周期钩子只允许一套枚举，出现第二套即红 |
| `X-07` | **多套决策编号并存**（`contracts` D1–D66 与 `modularity` D1–D8 重叠） | 「D3 是什么」永远需要追问「哪个文件的 D3」 | 见本文件编号规则；仓库内只允许一个 `I-/X-` 序列 |
| `X-08` | **用环境变量逐个切片开关**（`LILARA_GRAPH_MODE` / `LILARA_MEDIA_SHADOW` / `LILARA_HISTORY_TEXT_SHADOW` / `LILARA_SESSION_BRAIN` …，各自一套 `ParseMode` 与 off 分支） | 没有单一真相回答「现在是开还是关」；开关变成第二套配置系统，且没人会删一个 off 的开关 | 允许开关，但**必须收进一个配置源**并有一个拒绝的理由字段；散落的 `Environment.GetEnvironmentVariable` 即红 |
| `X-09` | **新架构寄生在旧架构的扩展点内**（图入站接在 `ExpressEngineSpawnCheck` 里） | 两个生命周期开始互相寄生；这是「永远迁不完」的机制成因 | 一个调用点只允许属于一条执行路径（人工审 + 架构图唯一路径） |
| `X-10` | **模块宿主用 `Dictionary<string, object>` 单实例绑定** | 「模块 = 类型 + 实例 + 行为 + 数据 + 生命周期」里实例是最核心一维，做成「一模块一对象」后所有需求都要绕过它打补丁 | 见 `C`（自举）与 `E1`：模块寻址必须带实例维度 |
| `X-11` | **图纸先于消费者**（16 张出厂图只挂 1 张、5 个生产模块、30 余个只在测试里出现的 `[Module]`） | 没人消费的东西不会被验证，于是「设计有、实现没有」长期共存且看起来一样健康 | 每个声明的模块/节点必须有**生产**消费点，否则不许进主干（测试专用件放测试工程） |
| `X-12` | **设计文档与实现状态混写**（ALC 也有此病：一份文档里大量「设计有、实现没有」的旁注） | 读者无法区分「意图」与「今天」；漂移无处对账 | 文档二分：设计文档不写「已实现/未实现」，状态文档必须写 `最后更新：<commit>` |
| `X-13` | **本地命令执行**（`shell` / `Process.Start` / `dotnet build` 之类"在本机跑命令"的能力） | 它绕过整个能力层：有它，路径前缀绑定、域名白名单、审计里的"对象"全部失去意义（一条 `cat` 就抹平）。ALP 与 ALC 都有它，因为它们的威胁模型里没有"接入群聊" | 代码里出现 `Process.Start` / `ProcessStartInfo` 即红；能力清单里不得有 `exec.local`；需要远端执行时走 `ISsh`（主机白名单 + 全量审计） |
| `X-14` | **会话的 goal / iterate 模式轴** | 会话本来就基本自带目标（除聊天），把"目标"做成模式轴是给同一件事开第二条表达途径；ALC 用它是因为它有"自主循环"这个独立需求，而 ALN 的自主性是 `continuation` 属性 + `objective` 数据（[`08` §6](08-会话与循环.md)） | 会话剖面上不得出现 `goal`/`iterate` 这类枚举；目标只能是 `objective` 字段，完成即释放 |
| `X-15` | **"等待用户输入"作为会话状态** | 它把"用户消息"提升成一种状态，于是每种激活源都要一个新状态（等外部、等定时、等子会话…）。ALP 的关键性质恰恰是**要么在跑、要么等被激活**（[`08` §1](08-会话与循环.md)） | 状态枚举只允许 `Running` / `Dormant`；等待原因必须是 `Dormant` 上的字段 |
| `X-16` | **用"暴露标记"把端口投影成工具**（`exposesToModel` 一类） | 端口是机制契约（类型化、随重构变），工具是对外产品契约（schema、稳定、面向模型）。耦合起来，任何端口重构都会改到**最贵的工具表**；且"默认暴露再挑着关"方向反了 | 每个工具必须有独立声明 + 显式绑定；描述符里不出现"是否暴露"这种布尔 |
| `X-17` | **模型 actor 拿 `*`（全部能力）** | 能力名回答"这是哪类活"，回答不了"你被信到多深"。一个什么都被授予的调用者让授权表永远回答"是"，而它本来要回答的问题是"谁来做这件事"；于是"改端点、换密钥、卸模块"与"读一眼频道列表"在权限上无法区分 | 授权 = 能力名 ∧ 等级比较；模型是 `Agent`；内部动作只能由 Operator 及以上执行（`I-26`） |

## 六、本文的效力范围

- 本文记录的是**判断**，不是现状。它不描述 ALN 代码今天做到哪一步。
- 本文的每条 `I-` 都应当在 `E` 分支变成一条会红的测试；凡不能变成测试的，会退化为纪律——**纪律的数量必须被显式计数并保持极小**，否则等于没有。
- ALP 的教训按此自检一次：**ALP 那 12 条 `X-` 里，有 4 条（`X-04`/`X-05`/`X-07`/`X-12`）在当年都是「已经写进文档的规矩」**，照样发生了。文档不是防线，**派生源与测试才是**。
- **（2026-10）** `I-26` / `X-17` 落地时推翻了一条既有判断：模型 actor 不再持有 `*`。授权现在是"能力名 ∧ 等级比较"两件事，见 [`07-域与权限分级.md` §9](07-域与权限分级.md)。
