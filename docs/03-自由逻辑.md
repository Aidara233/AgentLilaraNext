# 自由逻辑

> 状态：早期设计草案。本文把 Jint 限为纯逻辑求值的边界已被用户最近方向重新打开；脚本主导编排见 [`13-脚本编排与工程实施蓝图.md`](13-脚本编排与工程实施蓝图.md)。本文中纯计算、能力隔离等仍适用部分需与新契约逐项对齐。
> 前置：[`01-模块切分.md`](01-模块切分.md)、[`02-图模块.md`](02-图模块.md)。
>
> 本文回答：**用户要"自由逻辑"（想写多复杂就多复杂）时，它住在哪、走哪条路、天花板在哪。**

---

## 0. 一句话

> **自由度只允许长在"纯判定"上；副作用永远是有限枚举 + 显式接线。**

不是"逻辑能多复杂"，而是**逻辑有没有副作用**——这条线比"表达力"那条线重要得多：

| | 纯（判定 / 取值 / 计算） | 有副作用（发、存、删、调外部） |
|---|---|---|
| 跑错了能重算 | ✅ | ❌（邮件发出去收不回） |
| 可静态校验 | ✅ | ⚠️ 只能查签名 |
| 可缓存 | ✅ | ❌ |
| 该住哪 | **数据表 + 求值模块** | **图 + 有限动作枚举** |

## 1. 关键：判定点与执行点分离

一次"条件触发"其实是两件事，分开之后两边都不需要泛化：

```
判定（可以是任意复杂逻辑）        分流 + 执行（必须是有限枚举）
  rule.when: 表达式/脚本      →     rule.do: post | inject | ignore | stop …
        ↑                                ↑
   logic 模块求值（纯）              图按 do 接线到端口
```

- **判定点**（policy decision point）：吃消息与状态，吐一个**decision**。它可以是表达式的、脚本的，甚至将来是模型判断的——因为它**不碰世界**。
- **执行点**（policy enforcement point）：拿 decision 去调端口。它只能是**有限枚举**，因为副作用必须可枚举、可审计。

> ⚠️ 这条分离是本文唯一的核心。**只要守住它，判定逻辑要多自由都可以**——自由的是"它怎么算出来的"，不是"它能做什么"。

**图不需要任何新节点**：判定的求值就是一次 `call`（`{"call": "logic.any.eval", ...}`），分流靠 `$event.do` 的值传给不同的执行端口。图仍然是 `call` / `resolve` / `map` 三种，语法一个字不加。

### 1.1 职能三分（三句话，别让它滑）

> **`logic` = 算（纯）· 图 = 连（静态、可枚举、笨）· 各模块 = 做（有副作用）**

| | 谁 | 判据 |
|---|---|---|
| 复杂条件、分类、变换、打分、模板渲染 | `logic` | 拿不到世界，只拿得到数据 |
| 谁在什么时候被调、数据从哪来到哪去 | **图** | 加载期已定，运行期不做决定 |
| 发、存、删、调外部 | 各业务模块的端口 | 副作用只发生在端口上 |

⚠️ **图作为基础设施，意味着它必须保持愚笨。** 越聪明的基础设施越难被替换——ALP 的图最后同时是语言、编译器、注册表、开关面板和台账，于是没人能替换它，也没人能看懂它。

由此两条硬约束：

1. **`logic` 拿不到端口引用。** 它的参数表里只有数据（事件、表、快照），没有任何模块句柄。**这是结构性排除，不是纪律**：即使有人往逻辑里写了 `send(...)`，也无从表达。
2. **数据不能决定"打到哪个端口"。** 数据只能决定"动作的哪一款"（有限枚举内，由执行模块分派）。若目标端口来自数据，图的静态可求解性立刻失效——加载期无法校验一个运行期才知道的目标。这也是"不加分支"的另一面。

## 2. 四级自由度（阶梯，可按需上台阶）

**四级阶梯已收敛**（详见 [`05-自举.md`](05-自举.md) §1）：不再有"自研表达式语言 / 沙箱脚本引擎"，**全部是 C#，区别只是规模**——

| 规模 | 形态 | 住处 | 谁产出 |
|---|---|---|---|
| 一条判定 | **JS 表达式**（无能力注入，纯） | 数据（源码字符串，随规则表） | agent（自举） |
| 一小段逻辑 | **JS 脚本**（注入白名单能力，返回意图） | 数据（脚本，随装配版本） | agent（自举） |
| 一个能力 | **C# 模块**（实现端口，真正的副作用） | 模块（程序集，进版本） | **开发者（不是 agent）** |

⚠️ 第三行是安全边界：**agent 不能自己造"碰 OS 的东西"**，只能组合"已被授予的能力"。这就是"自举能加行为、不能加能力"（[`05`](05-自举.md) §2）。

⚠️ 下面这张历史阶梯保留作推导记录，**"L3 是界碑"这一句已被修订**：编排数据化仍然禁止，但"要更自由的编排"正确去处是**写模块（C#）**，而不是把编排塞进数据。

| 级 | 形态 | 住处 | 表达力 | 代价 |
|---|---|---|---|---|
| **L0** | 封闭匹配器（contains / regex / 名单 / 时间窗）+ 有限动作枚举 | 数据表 | 够用大多数规则场景 | 零代码 |
| **L1** | **纯表达式**（无副作用、输入是事件与状态快照、输出 bool 或标签） | 数据表，`logic` 求值 | `msg.len > 50 && now.hour in 0..6` | 一个求值器 + 静态校验 + 字段白名单 |
| **L2** | **脚本**（沙箱内，仍只能读、只能返回 decision） | `logic` 模块 | 接近任意逻辑 | 超时 / 内存 / 可用字段 / 确定性 四道闸 |
| **L3** | **任意编排**（多步、循环、跳转、自己决定调谁） | ❌ 不是配置——**写模块（代码）** | 真正的任意 | 版本、评审、重启；**这是有意的天花板** |

⚠️ **L3 不是"以后再补的一级"，是"到此为止"的界碑。** 一旦编排能数据化（循环、跳转、动态选目标），你就重新发明了一门语言、一个解释器、一套语义分析——而且它跑在求解器里、没有隔离、没有超时。那就是 ALP 的第 2 条症状。

### 2.1 脚本要"做事"怎么办：产出意图（intent），不直接调用

你说"全都想要"，这一条是让它成立的接缝。脚本**不能**拿端口做事，但可以**说出来**：

```jsonc
// 脚本的返回值（data，不是动作）
{ "decisions": [
    { "kind": "post",   "target": "self",         "text": "收到" },
    { "kind": "inject", "target": "session",      "text": "有人提到你了" },
    { "kind": "ignore" }
] }
```

- **意图 = 数据**：`kind` 是**封闭枚举**，`target` 只能是**相对角色**（`self` / `session` / `source`），不是任意地址；
- **执行点**（接收方模块）按枚举分派，把意图变成真正的副作用；
- 于是脚本能表达"复杂序列的意图"，却**仍然碰不到世界**——它说的每一句话都要经过一个已被校验过的执行者。

⚠️ ALP 有 `intent` 这个概念，**这个想法是对的**；它死在两件事上：意图目录大于可执行的意图（`sink.*` 无执行方也在目录里）、以及算出来的意图没人消费却没人报错。所以我们把这两条写进校验：**每个 `kind` 必须有且只有一个执行方（编译期枚举 → 执行方穷举匹配）；`kind` 集合是代码，不是数据。**

判据：**脚本能说"我想做什么"，不能做；执行点能做的，必须已经登记在枚举里。**

## 3. 数据形状

```jsonc
// channel.group-1234.rules
[
  // L0：封闭匹配器
  { "id": "r1", "when": { "kind": "contains", "text": "报时" },
    "do": { "kind": "post", "text": "现在几点？" } },

  // L1：纯表达式
  { "id": "r2", "when": { "kind": "expr", "src": "msg.text.len > 50 && now.hour >= 23" },
    "do": { "kind": "inject", "text": "深夜长消息，提醒会话注意语气" } },

  // L2：脚本（仍只返回 decision）
  { "id": "r3", "when": { "kind": "script", "src": "return msg.tags.includes('urgent') && state.unread > 3;" },
    "do": { "kind": "post", "template": "urgent-nag" } },
]
```

两条硬约束：

1. **`do.kind` 是封闭枚举**（`post` / `inject` / `ignore` / `stop` …）。加一种动作 = 改代码（一个模块的端口），不是加数据。
2. **`when` 里能引用的字段是白名单**，来自端口描述符（`msg.text`、`now.hour`、`state.unread`…）。引用未声明字段 ⇒ 加载期失败。

> 判据沿用 [`02` §7.6](02-图模块.md)：**"能表达什么"由代码决定，"这一条规则是什么"由数据决定，图只负责"命中之后接到哪"。**

## 4. `logic` 模块：最窄的模块，最重的一道闸

形态极小：

```
logic            （母，无状态）
 └ logic.expr    （抽象：一种求值器）
    └ #1         （实例：一个求值器实现 + 闸门配置）
端口：eval(rules, input) → decision     ← 表随输入进来，自身无状态
属性：超时、体积上限、可用字段、是否纯
```

⚠️ **`logic` 不持表，表随输入进来**（修订上一版：原写 `eval(source, input)` 且暗示它自己存规则）。这一条把它压成**纯函数**：

- 表归**提供方**（频道的配置，或独立 `rule` 模块的属性）——所以 `logic` 不需要任何存储，也不需要认识谁；
- 于是任何人（任何模块、任何图）都能拿任何一张表来求值，它只是一次函数调用；
- 于是它可以被缓存、被重算、被替换实现，而不涉及任何状态迁移。

**它就是"唯一允许执行用户提供的逻辑的地方"。** 这句话就是它存在的全部理由——不是因为逻辑多，而是因为**闸门必须有落点**。

闸门清单（缺一条就会出事）：

| 闸 | 值 | 不做会怎样 |
|---|---|---|
| 超时 | 有上限，超时即决策失败 | 一条正则灾难性回溯就能卡住整条消息链 |
| 体积 | 表达式/脚本长度上限 | 数据表变成代码仓库 |
| 字段白名单 | 只能读声明过的字段 | 逻辑能摸到内部状态，等效于偷看一切 |
| **纯函数判定** | 禁止 IO、禁止写、禁止读时钟（时间作为输入传入） | 判定不可重算、不可缓存，且"同一输入两次不同结果"会毁掉可验证性 |
| 确定性 | 同输入同输出 | 否则重放与对拍都失效 |

⚠️ **"时间作为输入传入"这条特别重要**：`now` 是**参数**，不是环境。判定的纯性一旦破了，整个"可重算/可对拍/可缓存"的红利全部作废（这也是 ALC 那条"渲染必须是纯函数"的同一条思路）。

## 5. 为什么它不"繁重"：繁重感的错位

把逻辑放进图里，看起来省掉一个模块，实际上：

| | 加一个 `logic` 模块 | 把逻辑放进图 |
|---|---|---|
| 增量 | 一个项目（一个端口 + 一套闸门） | 图语言加表达式 → 再加作用域 → 再加错误处理 → **再加类型检查** → 再做语义分析 |
| 复杂度归谁 | 收在一处，**只有它需要懂逻辑** | **摊到每一个用图的人**：任何写图的人都要理解这套语义 |
| 闸门 | 天然有落点（模块边界） | 没有落点（逻辑跑在求解器里） |
| 换实现 | 换模块实现，内核不动 | 换语言版本 = 升级整个内核 |
| 出错后果 | 一条规则失败 | 一张图加载失败，或更糟：静默算错 |

> **把复杂度收进一个窄模块，比摊到所有图里便宜得多。** 后者才是真的繁重，而且繁重是永久的。

顺带：`logic` 正是"能力自举"最干净的样例——把求值器从"内建 C# 表达式"换成"另一个实现"甚至"一个模型"，都是**换它一个实例**，订阅、模块、内核一个字不改。
