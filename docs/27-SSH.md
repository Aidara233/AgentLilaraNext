# 27 · SSH：模型能碰到的那几台机器

> 状态：第一期实现中（端口与假实现已落地，真实传输在 Q3）。
>
> 本文回答一个问题：**一个会话怎么连上「用户现场的某台机器」，而这件事不会变成「模型能访问任意系统」。**

---

## 0. 威胁模型（先写这一节，后面所有争论都由它判）

**信任边界 = 宿主磁盘与进程。** 磁盘是最后一道防线：到这一步守不住，上面叠多少层都没有意义，所以不为此设计。
SSH 模块守的只有三件事：

1. **凭据不从上下文进来**（用户贴在对话里的私钥不是凭据，见 §4）；
2. **凭据不被外传**（不进工具结果、不进信号、不进审计、不进异常 detail、不进 `aln.db`）；
3. **凭据不被别的会话用掉**（现场通道按会话隔离，存量通道要 operator）。

不守的：宿主被攻破、内存被 dump、磁盘被读。这不是"不重要"，是"到那一步已经没有可谈的边界"。

`06` 说"ALN 本身不该具备随意访问系统的能力"，SSH 正面撞上这句话。这里的回答是：
**能连的机器是一个个具名的、由人给出的目标，不是一个网络。** 所以端口（`ISshAccess`）里不接受任意地址也不是
服务的形状——它接受一个 `SshTarget`（谁给的、给哪个会话、什么策略，都在调用点回答），并且只做 SSH 一件事：
不做端口扫描、不做任意 TCP、隧道只绑回环（§7）。

---

## 1. 两条通道，门在「凭据从哪来」

| | 现场（live） | 已保存（saved） |
|---|---|---|
| 谁给的 | 用户在这一轮对话里给的设备信息，或模型按它 `ssh_init` 时生成的 | 磁盘上一直存在、任何会话都可能碰到的那一份 |
| 存在哪 | 进程内存（配置 + 密钥）；空闲 2 小时随会话丢弃 | `module.json` 基线 + `ssh/keys/`（0600） |
| agent 级会话 | ✅ 全部功能 | ❌ 看不到、用不了、连名字都查不到 |
| operator 级会话 | ✅ | ✅ 直接用，不再加一道 |
| 成为另一条通道 | 只有 `ssh_save`（**operator**） | 只有 `ssh_load`（operator）把它载入当前会话 |

**每会话只有一个 live 配置。** 再 `ssh_init` 就是换一台：旧密钥清零、旧连接关闭、旧 job 全部 kill，
返回里写明被替换的是谁。多个目标靠 saved + `ssh_load` 切换，而不是靠一个会话里叠好几个。

这样划线的理由：`07` 的等级是"人在什么深度上授权"。用户当场把机器交给你，那是人在当场授权；
磁盘上存着一把谁都能拿的钥匙，那才是"未经授权的访问"。

## 2. 第一次连接：人必须做两件事，其余不用

```
① 模型 → ssh_init {"device":"prod-web","host":"1.2.3.4","user":"deploy"}
   ← publicKey / keyFingerprint / hostFingerprint / pinned
② 模型把 publicKey 交给用户（手动：回复、channels.send、静默时写进 workspace 等人来看）
③ 用户把公钥加进目标机 ~/.ssh/authorized_keys
④ 模型 → ssh_run {"command":"…"}   ← 成不成，答案直接在这一步
```

没有独立的"确认"步骤，也没有状态机：配置存在即可用。**唯一的体检就是真跑一条命令**，所以
`ssh_run` 的失败必须能分开五类（§5）。简化换来的代价写在 §3。

## 3. 信任：首次即钉（TOFU），这是有意的取舍

- `ssh_init` 给了 `fingerprint` 就用它钉住；没给就用**第一次真正连上时看到的那一个**，并在结果里回显；
- 之后指纹一变 → **硬失败**，两个指纹都报出来，只能重新 `ssh_init` 才能接受新指纹；
- 因此：**第一次连接如果撞上中间人，我们分辨不出来。** 这不是疏忽，是"不要确认步骤"的直接后果。
  缓解有三条，都不增加步骤：init 结果回显实际指纹、`ssh_init` 接受用户手里的指纹（`ssh-keyscan` 那一行）、
  变化时硬失败。

## 4.1 命令策略与远端路径（`policy`）

```json
{"mode":"allowlist",
 "commands":["systemctl status","journalctl -u * -n 200"],
 "paths":["/srv/app","/var/log/app"]}
```

- `mode: any` —— live 的默认。用户当场把机器交出来，命令与文件路径都不限制。
- `mode: allowlist` —— 命令按前缀或 glob 匹配；**文件读写还要单独声明 `paths`**，没声明 = 全部拒绝。
  这一条是被逼出来的：命令策略只管 `ssh_run`，一次 `ssh_put` 写到 `~/.ssh/authorized_keys` 就等于
  给自己加了一把永久钥匙——那是比任何单条命令都大的授权。所以路径和命令一样，**不点名就到不了**。
- 路径必须是绝对路径、不含 `..`；前缀按**整段**匹配（`/srv/app` 不允许 `/srv/application`），
  目录本身与它下面的一切都算在内。
- 存量设备（`ssh_save`）必须显式声明策略，见 §7。

## 4. 私钥：六格生命周期

| 环节 | 规则 |
|---|---|
| 进 | 只接受 `ssh_init` 生成的（或 operator 用 `ssh_load` 载入的 saved 配置）。**`keyText` 字段不存在** |
| 存 | 默认只在内存（`memory-only`）；`ssh_save` 才落盘，创建即 `0600`。永不进 `aln.db` |
| 读 | 以 `Stream` 交给 SSH 客户端（`PrivateKeyFile(Stream)`），读完即弃；接口里没有"把私钥读成 string"的方法 |
| 用 | 只在认证那一瞬 |
| 出 | 只有**公钥**与**指纹**可以出（它们本来就是公开的） |
| 清 | 换配置 / 空闲 2 小时 / 会话回收 / `ssh_remove` → 内存清零 + 文件删除（先覆写再删） |

用户把私钥贴进对话时：模块**拒绝**，并说明"这段已经在对话历史里，请换一把"。
不是因为拦得住——那一刻它已经写进 `history.jsonl` 与模型调用原文了——而是因为**系统绝不再复制它一份**。

## 5. 失败要分得开

| kind | 含义 | 谁的问题 |
|---|---|---|
| `Refused` | 端口上没有 sshd | 用户（服务没开） |
| `Timeout` / `Unreachable` | 地址、端口、防火墙、路由 | 用户（网络） |
| `Auth` | 公钥没装、或 `authorized_keys` 权限不对 | 用户（部署） |
| `HostKey` | 这台机器不是上次那台 | **停下来问人** |
| `Command` | 连上了，命令自己失败 | 命令 |

把五类压成一个"失败"，模型只能对用户说"连不上"，而用户没法据此修任何东西。

## 6. 工具

| 工具 | 作用 | 等级 | 对外办事 |
|---|---|---|---|
| `ssh_init` | 建/换当前 live 配置，自动生成密钥 | agent | 否 |
| `ssh_hosts` | 看当前配置 + 上次错误 | agent | 否 |
| `ssh_remove` | 丢掉当前配置（密钥清零、连接关闭、job kill） | agent | 否 |
| `ssh_run` | 执行命令（策略、超时、截断、可取消、可后台化） | agent | 是 |
| `ssh_job` | 后台命令 list / output / kill | agent | 是 |

**后台命令同时写进后台任务账本**（`IJobRegistry`，`docs/28 §9`）：行名沿用 `ssh_job` 用的那个 id（两个 id 会让
"job 3f2a" 对不上），kind 是 `ssh.run`。**结束是推的**：`ssh_run {wait:false}` 起一个没人等的观察者
（`ISshJob.WaitForExitAsync`），命令一结束就写行，写它的那一层顺手把会话叫醒（`docs/28 §9.4`）。`ssh_job list` /
`output` 仍然会把行补上——写失败时靠它收敛。在那之间重启，账本读到的是 `Interrupted`（"可能做完了，
也可能没有，进程没了"，这比猜一个准确）。`kill` 记成 `Killed`，不通知——叫人停的，叫的人知道；**而且先写行、
再杀进程**，否则观察者会把一次故意的停止记成"它做完了"。
没有账本时一切照旧，只是重启后连痕迹都没有（这正是加它之前的状况）。
| `ssh_put` / `ssh_get` | 文件进出，**字节原样**（文本、tarball、证书、二进制都行） | agent | 是 |

### 6.1 任意类型文件：字节走另一条通道

`fs` 的文本面是给"模型能读回来整理"的东西用的，所以它只吃 UTF-8。但**"模型只能写文本"和"模型只能在机器之间搬文本"
不是同一条规则**——搬一个 tarball、证书、编译产物是正常需求，而且**字节根本不需要经过模型的上下文**。于是：

| | 契约 | 作用 |
|---|---|---|
| 文本面 | `IFileSystemAccess`（不变） | 模型读写它能读回来的东西（7 个 `fs_*` 工具） |
| 字节面 | `IBinaryFileAccess`（`LocalFileSystemAccess` 一并实现） | `ssh_put` / `ssh_get`：流式、上限来自模块配置（`maxTransferBytes`，默认 `0` = 无上限）、临时文件 + rename 保证原子 |

三条规则：**只有显式登记为字节区的 scope 才收字节**（宿主默认只给 `workspace`——"删光也不心疼"的房间，
记忆库与脚本草稿仍然是文本区）；路径规则与文本面完全相同；超过（若配置了）上限时**拒绝而不是截断**。
模型看到的仍然只是"scope + 相对路径"，所以 40 GiB 的文件对上下文是零成本。

下载是**流**而不是先攒成一个 `MemoryStream`：早先那版把整份文件读进内存，"一次能搬多大"因此成了内存问题，
64 MiB 这个数就是这么来的。现在 `SftpDownloadStream` 把 SFTP 会话的所有权交给调用方拿到的那个流，字节边读边写，
上限只剩"谁来给"这一件事。
| `ssh_tunnel` | 本地回环转发 | **operator** | 是 |
| `ssh_save` / `ssh_load` / `ssh_forget` | live ↔ 存量 | **operator** | 否 |

`ssh_tunnel` 与三个 `ssh_save` 系列**不出现在 agent 级会话的工具表里**（不是"出现了但拒绝"）：
一个只会被拒的工具会买走一轮，并教会模型怀疑整张工具表。

## 7. 存量通道的细节

- 保存的是一条**记录** + 一个**密钥文件**：记录写进 `aln.db` 的 `ssh.saved`（设备的地址、用户、钉住的指纹、
  命令策略、**密钥的名字**），私钥写进 `<dataRoot>/ssh/keys/saved-<device>`（创建即 0600）。**记录里没有私钥**。
- **存量设备必须显式声明命令策略**：live 的默认 `any` 不能被子类化——一台长期存在的机器没有一句对话给它兜底。
  明确写 `{"mode":"any"}` 仍然允许，那是人的决定。
- `ssh_load` 会把密钥从文件库**复制**到内存库再绑定到会话：live 通道始终只在内存里持密钥，这条不变量不为存量让路。
- 枚举的缺口：`IStateStore` 没有"列出某个 scope 下所有 key"的接口，所以**没有 `ssh_saved.list`**。
  运营者知道名字，模型不知道——先错在安全的一侧。要补，需要先给状态存储加枚举，那是个单独的契约变更。

## 8. 明确不做

| 不做 | 为什么 |
|---|---|
| 任意 TCP / 动态转发（SOCKS） | 那是"把宿主变成出口"，与 `06` 直接冲突。`ssh_tunnel` 只做回环本地转发 |
| 绑定非回环地址 | 同上：一个监听 `0.0.0.0` 的转发就是开放代理 |
| 密码认证 | 第一期只认密钥；密码要另一套"不进历史"的设计 |
| 模型自己加 saved 主机 | 那是提权：`ssh_save` 是 operator 的 |
| 多目标并存于一个会话 | 一个 live 配置，切换用 `ssh_load`（operator） |

## 10. 现状、验证与没做的事

**已实现**：端口（`ISshAccess` / `ISecretStore`）、假实现与真实现（SSH.NET 2025.1.0）、
ed25519 生成（BouncyCastle 2.6.2，OpenSSH 格式）、模块（`ssh.local`，`module.json` 只管时长与上限）、
九个工具、审计与信号、每会话单配置与 2 小时空闲回收、失败五分类、存量通道。

**离线可验证的部分都有测试**：密钥能被 SSH.NET 解析、文件密钥 0600、名字不可穿越、
`keyText`/`password` 一律拒绝且不回显、重 init 顶掉旧配置并清密钥、策略拒绝并回报允许项、
后台命令的 list/output/kill、job 上限、put/get 只走 scope、审计带命令不带输出、
`ssh_tunnel` 与存量三件只对 operator 出现、存量记录里没有私钥。

**没有验证的（明确的空白）**：

1. **真机握手**：本仓库的测试环境没有可连的 sshd，所以 probe / connect / 执行 / job / sftp / 转发
   只有编译与映射测试覆盖，**没有一次真实 SSH 会话**。这是下一件该做的事，做法是起一个容器
   （`docker run -d -p 2222:22 …`）或指向一台测试机，把 `ssh_init → 部署公钥 → ssh_run` 跑通一次。
2. **SFTP 走第二条连接**：SSH.NET 不允许复用 `SshClient` 的会话，所以 put/get 各自建一条连接再断开。
   功能正确，代价是多一次握手；要省掉它得自己复用 `Session`。
3. **后台 job 的输出泵**没有在真实长命令上跑过。
4. **没有控制面动作**：`ssh_save` 等是"工具"，不是 `IControlPlane` 里的 action，所以 WebUI 现在还看不到、
   也管不了存量设备。要接，就是按 `15` 的表加 `ssh.saved.list` / `ssh.saved.forget` 两个动作。
