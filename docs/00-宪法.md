# 宪法

> 只规定做什么，不解释为什么。理由在 [`00-继承与作废台账.md`](00-继承与作废台账.md)，结构细节在 [`22-模块图与生命周期.md`](22-模块图与生命周期.md)。
> 冲突以本文为准。条文编号不复用；废止一条就留编号、另起新条。

## 名词

只列这些词。表外的词要么是普通中文，要么是代码里的名字，都不另立概念。

| 名词 | 定义 |
|---|---|
| **模块** | 程序内一个**可实例化**的、实现某一特定功能的**功能整体**。 |
| **类型** | 模块的实现类型，写在 `module.json` 的 `type` 里，实例由它造。类型不是模块。 |
| **包** | 装进进程的分发单元，一个包可以携带多个类型。包不是模块。 |
| **实例** | 模块的一次具体存在，由 `id` 指认。实例是模块。 |
| **图** | 进程内全部模块及其关系的集合。 |
| **边** | 一条主从关系：从响应主的生命周期事件，主向从发控制命令。只在主的 `module.json` 里声明。一个实例可以有多条入边；每条边各自成立、各自可坏。 |
| **主 / 从** | 发生命周期事件、发控制命令的一方 / 响应的一方。接口由主定义，从实现。一个从可以有多个主。 |
| **触发** | 一次"叫醒某个模块"的推送。不是边，不影响启动顺序。发出者是触发源，接收者是触发接收方。 |

## 一、身份与形状

- **C-01** `id` 只用于指一个模块：不解析、不改写、不给别名；改名即换身份。
- **C-02** `id` 与它所在的目录名逐字一致。
- **C-03** 一个模块一个目录：`modules/<id>/`，里面有一份 `module.json`。文件记录的是"它被造成什么样"（身份、类型、初始配置），**会变的东西不在这里**——一处状态，一次写完；文件只当初始值读一次（`22 §2.1.1`）。
- **C-04** 类型、类别、角色只写在文件里，不编进目录名、文件名或 `id`。
- **C-05** 边只写在主的 `module.json`；从不写"我的主是谁"。
- **C-06** 能力只从模块本身取，不按名字、目录或前缀判断。
- **C-07** 边不带计数器；需要计数的模块自己记。

## 二、生命周期

- **C-08** 启动顺序固定：加载 → 初始化 → 接线 → 就绪；初始化结束才开始接线，就绪按环内并发的拓扑序。停止逆序，逐模块限时。
- **C-09** 环必须写进启动记录。
- **C-10** 接线失败只报告，不阻断启动。
- **C-11** 不重试。失败交给该模块自己的错误处理；它再失败就记录并吞掉。
- **C-12** 同一份磁盘内容，两次启动给出同一份启动记录。
- **C-13** 启动记录分项：模块、边、坏边、环、节奏。坏边保留；`system.info` 与它同口径。
- **C-14** 一个 `id` 只登记一次；重复是冲突，不是覆盖。
- **C-15** 启动**前**宣告的实例按声明处理、走全套；启动**中**宣告的实例当场走完。

## 三、实例与关系

- **C-16** 实例是模块：它出现在图上，由类型造出；持有它的每个模块都是它的主，可以不止一个。加载、初始化、就绪、停止由核心发出，不由主发起。
- **C-17** 触发不是边：接收方声明节奏，触发源挂接；只有声明会排班的源参与。
- **C-18** 挂接必须可见：成功在 `system.info` 有一行（启动时挂上的同时进启动记录），失败记 warn。
- **C-19** 调用走接口（返回结果、可失败）；广播走队列（只承诺入队）。

## 四、数据

- **C-20** 数据只写两处：模块自己的目录；或由一个模块统一负责多模块共享的数据（现在是 `aln.db`）。
- **C-21** 可派生的不落盘。
- **C-22** `config` 对内核不透明：不解析、不校验、不改写。
- **C-23** 会话目录里：`module.json`（spec 带 `formatVersion`）、`state.json` 全量、`history.jsonl` 追加；崩溃的中间态先写 breadcrumb。
- **C-24** 形状变化一次性手工迁移并留备份；仓库里不放迁移器。
- **C-25** 销毁先归档；卸载默认归档，保留目录必须显式。

## 五、失败与观测

- **C-26** 信号是派发的副产品，审计是独立通道：两者不合并；审计不可关，拒绝也记。
- **C-27** 一个模块失败不得否决别人的一整轮；降级并记录。
- **C-28** 任何"没接上、没挂上、没加载"都必须有一条可查记录。

## 六、能力与动作

- **C-29** 动作是唯一执行入口：先校验能力，拒绝也审计，返回 DTO。
- **C-30** 动作名按域：`modules` 指图、`packages` 指包；改名时旧名转发到同一实现，能力单向兼容。
- **C-31** 没有本地 shell；任意逻辑跑在拿不到系统原语的环境里；扫描只是事后防线。
- **C-32** 工具显式声明，加载期校验绑定目标存在。

## 七、会话与上下文

- **C-33** 一种会话：行为由 `SessionSpec` 组装，不按类型分支。
- **C-34** 上下文块数恒定；历史只追加；系统块走全局快照 + 全局重载，没有单会话重建。
- **C-35** 模型看不见自己发出的消息。
- **C-36** 会话状态只有 `Running` / `Dormant`；等待原因是字段，目标写在 `objective`。

## 八、改动纪律

- **C-37** 本文只写规定。理由写进台账或 `22`，不写进本文。
- **C-38** 推翻一条结论：改本文条文，并在台账或 `README §4` 记一条。编号不复用。
- **C-39** 只用名词表里的词，不新造名词；代码与动作里的用词跟随名词表。
- **C-40** 不为零声明接线；每个声明的类型必须有生产使用点。
- **C-41** 先定三件事：谁构造、谁是主、谁销毁。三者不同时必须能从代码里直接看出来。
- **C-42** 设计文档不写实现状态。
