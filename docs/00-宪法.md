# 宪法

> 只规定做什么，不解释为什么。理由在 [`00-继承与作废台账.md`](00-继承与作废台账.md)，结构细节在 [`22-模块图与生命周期.md`](22-模块图与生命周期.md)。
> 冲突以本文为准。条文编号不复用；废止一条就留编号、另起新条。

## 名词

| 名词 | 定义 |
|---|---|
| **模块** | 程序内一个**可实例化**的、实现某一特定功能的**功能整体**。 |
| **模块类型** | 模块的实现类型，写在 `module.json` 的 `type` 里，实例由它造。类型不是模块。 |
| **模块包** | 装进进程的代码分发单元，一个包可以提供多个模块类型。包不是模块。 |
| **模块实例**（实例） | 某个所有者持有的一份模块。实例是模块。 |
| **管理器** | 构造并持有实例的模块，依赖由宿主注入。 |
| **图** | 进程内全部模块及其关系的集合。 |
| **边** | 一条"主持有从"的关系，只在主的 `module.json` 里声明。 |
| **主 / 从** | 持有方 / 被持有方。接口由主定义，从实现。 |
| **触发** | 一次"叫醒某个模块"的推送。不是边，不影响相位顺序。发出者是触发源，接收者是触发接收方。 |
| **相位** | 模块在一次启动中的位置。只有内核能推进它。 |
| **收据** | 一次启动的结果记录，分段记账。 |
| **模块目录** | `<DataRoot>/modules/<id>/`。模块的家，目录名就是它的 `id`。 |
| **存储模块** | 跨模块、跨重启的数据，落在 `aln.db`。 |
| **（不用）节点** | 图上的东西就是模块；需要区分时加限定语：实例、管理器。 |

## 一、身份与形状

- **C-01** `id` 只用于指一个模块：不解析、不改写、不给别名；改名即换身份。
- **C-02** `id` 与模块目录名逐字一致。
- **C-03** 一个模块一个目录，目录里有一份 `module.json`。
- **C-04** 类型、类别、角色只写在文件里，不编进目录名、文件名或 `id`。
- **C-05** 边只写在主的 `module.json`；从不写"我的主是谁"。
- **C-06** 能力只从模块本身取，不按名字、目录或前缀判断。
- **C-07** 边不带计数器；需要计数的模块自己记。

## 二、生命周期

- **C-08** 相位固定为：加载 → 初始化 → 接线 → 就绪 → 停止。初始化是屏障，接线在屏障之后，就绪按强连通分量的拓扑序、环内并发。
- **C-09** 环必须出现在收据里。
- **C-10** 接线失败只报告，不阻断启动。
- **C-11** 不重试。失败交给该模块自己的错误钩子；钩子再失败就记录并吞掉。
- **C-12** 同一份磁盘内容，两次启动得到同一张收据。
- **C-13** 收据分段：模块、边、坏边、环、节奏。坏边保留，`system.info` 与收据同口径。
- **C-14** 一个 `id` 只登记一次；重复是冲突，不是覆盖。
- **C-15** 启动**前**宣告的实例按声明处理、走相位；启动**中**宣告的实例当场走相位。

## 三、实例与关系

- **C-16** 实例是模块：它出现在图上，生命周期归持有它的管理器。
- **C-17** 触发不是边：接收方声明节奏，触发源挂接；只有声明会排班的源参与。
- **C-18** 每次成功挂接在收据与 `system.info` 里留一行；拒绝挂接记 warn。
- **C-19** 调用走接口（返回结果、可失败）；广播走队列（只承诺入队）。

## 四、数据

- **C-20** 跨模块、跨重启的数据进存储模块；只属于自己的留在模块目录。
- **C-21** 可派生的不落盘。
- **C-22** `config` 对内核不透明：不解析、不校验、不改写。
- **C-23** 会话目录里：`module.json`（spec 带 `formatVersion`）、`state.json` 全量、`history.jsonl` 追加，崩溃中间态写 breadcrumb。
- **C-24** 形状变化一次性手工迁移并留备份；仓库里不放迁移器。
- **C-25** 销毁先归档；卸载默认归档，保留目录必须显式。

## 五、失败与观测

- **C-26** 信号是派发的副产品，审计是独立通道：两者不合并；审计不可关，拒绝也记。
- **C-27** 一个模块失败不得否决别人的一整轮；降级并记录。
- **C-28** 任何"没接上、没挂上、没加载"都必须有一条可查记录。

## 六、能力与动作

- **C-29** 动作是唯一执行入口：先校验能力，拒绝也审计，返回 DTO。
- **C-30** 动作名按域：`modules` 指图、`packages` 指包；改名时旧名转发到同一实现，能力单向兼容。
- **C-31** 没有本地 shell；任意逻辑跑在拿不到系统原语的环境里；扫描只是事后防线。
- **C-32** 工具显式声明，加载期校验绑定目标存在。

## 七、会话与上下文

- **C-33** 一种会话：行为由 `SessionSpec` 组装，不按类型分支。
- **C-34** 上下文块数恒定；历史只追加；系统块走全局快照 + 全局重载，没有单会话重建。
- **C-35** 模型看不见自己发出的消息。
- **C-36** 会话状态只有 `Running` / `Dormant`；等待原因是字段，目标写在 `objective`。

## 八、改动纪律

- **C-37** 本文只写规定。理由写进台账或 `22`，不写进本文。
- **C-38** 推翻一条结论：改本文条文，并在台账或 `README §4` 记一条。编号不复用。
- **C-39** 只用名词表里的词，不新造名词；代码与动作里的用词跟随名词表。
- **C-40** 不为零声明接线；每个声明的类型必须有生产使用点。
- **C-41** 先定拥有权：谁构造、谁持有、谁销毁。三者不同时必须能从代码里直接看出来。
- **C-42** 设计文档不写实现状态。
