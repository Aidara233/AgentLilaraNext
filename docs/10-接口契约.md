> 状态：草稿，逐模块推进。**本目录只写接口形状与不变量，不写实现，也不写"已实现"。**

## 0. 通用约定（所有接口共用）

### 0.1 结果形状：`Result<T>`，跨模块调用**不抛异常**

```csharp
public readonly record struct Result(bool Ok, Error? Error);
public readonly record struct Result<T>(T? Value, Error? Error);

public sealed record Error(
    ErrorCode Code,          // denied | unavailable | timeout | conflict | invalid | internal
    string    Message,       // 一句人话，可直接给模型或人看
    string?   Detail = null, // 底层/平台原话，不解析
    bool      Retryable = false);
```

三条规则：

1. **跨模块调用一律返回 `Result`**，失败写成 `Error`，**不抛异常**。
2. **异常只表示程序错误（bug）**，走崩溃 / 急停路径，不属于业务语义。
3. 于是 [`08` §5](08-会话与循环.md) 的"工具绝不抛异常"、[`01` §3.1](01-模块切分.md) 的"钩子不抛异常"不再是特例——**它们是通则的一个实例**。

`ErrorCode` 的六个值是封闭集合；新增值要改台账（`X-07`：只允许一个序列）。

另有一个配套类型，用于"读到 / 没读到"——它与失败**不是一回事**：

```csharp
public readonly record struct Option<T>(bool Has, T? Value);
```

`GetAsync` 返回 `Result<Option<T>>`：`Result` 表示"这次操作成不成功"，`Option` 表示"这个 key 有没有值"。把两者混在一起会让"没有"和"出错"分不清。

### 0.2 取消与超时

```csharp
ValueTask<Result<T>> M(..., CancellationToken ct);
```

- 每个异步端口都带 `CancellationToken`；内核在**派发点**按订阅边的 deadline 建 `CancellationTokenSource`。
- 超时统一映射成 `Error(Timeout, Retryable: true)`，**不是异常**。
- 取消（用户中断 / 急停）原样冒泡为 `OperationCanceledException`，**不算失败**（`08 §9`）。

### 0.3 地址与句柄

```csharp
public readonly record struct ModuleId(string Value);   // 不透明，只支持相等
```

- **id 是名字，不是描述**（[`01`](01-模块切分.md) §2）。**没有三段、没有 `TypeId` 推导、没有 `TryParse`**——类型、类别、归属、挂载关系全部由目录回答，不从 id 读。
- **地址是字符串可寻址的**（图 / 装配 / 日志都用它），不是对象引用。
- **能力是 scoped 句柄**（[`06`](06-能力与审计.md)），句柄里只放 id 与生命周期，不放可序列化的业务数据。
- 模块之间**不传对象引用**，只传 id 与不可变数据。
- **唯一模块**可以直接按 id 找；**其余模块只能按类型筛选**（`01 §5`）——实例 id 是装饰，没人依赖它的格式。
- 字符集、长度、大小写不敏感的唯一性、以及"允许怎么用 id / 禁止怎么用 id"，见 `01 §3`。

### 0.4 时间、随机与幂等

```csharp
public interface IClock
{
    DateTimeOffset UtcNow { get; }
    ValueTask Delay(TimeSpan d, CancellationToken ct);
}
```

- **时钟必须注入**（`IClock`），禁止 `DateTime.Now`；测试用假钟推进 `wait` 与心跳。
- 随机数同理（`IRandom`），种子可复现。
- **必需成员幂等**（`01 §7`）；写操作要么天然幂等（按 key `Put`），要么带幂等键（`Append` 的记录 id）。

### 0.5 模块清单与推进顺序

**模块的定义、身份、目录、挂载、两种交互全部在 [`01`](01-模块切分.md)，本节不重复。** 这里只回答一件事：每个模块的接口形状落在本文哪一节。

下面列的是**模块**（都实现 `IModule`，都可被挂载、可被指名调用），不是类型。管理器是模块，但它**不是**它所管理类型的实现——`AdapterManager` 和 `IAdapter` 只有名字沾边（`01 §4`）。

| 模块 | 有自己的输入源？ | 为什么是模块 | 接口状态 |
|---|---|---|---|
| `store` | 无（只被调用） | 有状态、有生命周期、有迁移 | **本文 §1** |
| `model` | 无 | provider 池、流式、计量、限流 | §2 |
| `tool` | 无 | 注册表、五阶段执行、双超时 | §3 |
| `logic` | 无 | 纯函数宿主（Jint） | §4 |
| `session` | 有（被激活） | 会话是数据、推进是过程 | §5 |
| `channel` | 有（收到 envelope） | 归一、绑定、游标 | §6 |
| `adapter` | 有（平台推） | 平台协议边界 | §7 |
| `graph` | 有（订阅的事件） | 订阅表 + 过程 + 派发 | §8 |
| `audit` | 有（被写） | 不可关 | §9 |
| `journal` | 有（被写） | 可过滤的链路记录 | §9 |
| `log` / `clock` / `config` / `secret` | 无 | 后勤 | §9 |

`driver`（队列 + 步调度）**不是模块**，是内核（`02 §2.1`）。执行模型已定：**单线程 async，无真并行**。

**推进顺序**（按依赖从下往上）：`store` → `model` → `tool` → `logic` → `session` → `channel` → `adapter` → `graph` → 后勤。

### 0.6 共用数据模型：住在契约层

这些类型**不在任何模块程序集里**（`17 §2`：数据模型住契约层，存储与模块不得定义自己的版本）。全部**不可变、无行为、可序列化**。

| 类型 | 形状出处 | 用途 |
|---|---|---|
| `ModuleId` / `Result` / `Error` / `Option<T>` | §0.1、§0.3 | 寻址与结果 |
| `AdapterEnvelope` | `09 §2.1` | 平台清洗后的入站 |
| `ChannelMessage` | `09 §2.2` | 逻辑消息（canonical） |
| `OutboundMessage` | `09 §2.4` | 平台无关的出站 |
| `SendResult` | `09 §6.2.1` | 统一回执（sent / accepted / failed） |
| `PromptBlock` | `08 §10` | 渲染产物的一块 |
| `TimelineItem` | ★待定 | 时间线的一条；`Opening`（第一条 user 消息）也是它 |
| `ContentPart` | ★待定 | 结构化内容片段（文本 / 媒体引用 / …） |
| `BuiltPrompt` | §5.2 | `{ System, Opening, Timeline, Tail, Tools, Fingerprint }` |
| `ActivationReason` | ★待定 | 激活源（入站 / 定时 / 子会话 / wait 到期） |
| `*Info`（Store / Session / Channel / Adapter / Graph / Provider / Tool / Logic） | ★待定 | 列表项摘要 |

⚠️ **`*Info` 是一族，不是一个一个自由设计**：统一形状为 `{ ModuleId, string? Name, HealthState, JsonNode? Metrics }`，否则八个管理器会长出八种列表类型，前端与 `adapter` 工具都要各写一套。

## 1. `store`：一个库

### 1.1 唯一模块 `store*`（`IStoreManager`）

```csharp
public interface IStoreManager
{
    // 生命周期：管理器由内核创建；库由它打开
    ValueTask<Result<IStore>> OpenAsync(StoreKind kind, StoreOptions options, CancellationToken ct);
    ValueTask<Result>        CloseAsync(IStore store, CancellationToken ct);

    // 索引
    IReadOnlyList<StoreInfo> List();
    bool TryGet(StoreKind kind, [NotNullWhen(true)] out IStore? store);

    // 维护
    ValueTask<Result<SchemaVersion>> MigrateAsync(StoreKind kind, CancellationToken ct);
    ValueTask<Result<long>>          PurgeAsync(StoreKind kind, PurgeQuery query, CancellationToken ct);
}

public enum StoreKind { Session, Channel, Adapter, Graph }   // Graph 是否成为第四库：★待定
```

- 管理器**持有全部库实例**（`01 §11` 规则 1），自己不存业务状态。
- 同一 `StoreKind` 只允许一个实例；重复 `OpenAsync` 返回 `Error(Conflict)`。

### 1.2 模块类 `store.<kind>`（`IStore`）

```csharp
public interface IStore
{
    StoreKind Kind { get; }
    bool      IsOpen { get; }
    StoreStats Stats { get; }          // 条数 / 字节 / 最后写入时间 / 是否只读

    // 生命周期
    ValueTask<Result> OpenAsync(StoreOptions options, CancellationToken ct);
    ValueTask<Result> CloseAsync(CancellationToken ct);

    // 事务
    ValueTask<Result<IStoreTransaction>> BeginAsync(CancellationToken ct);

    // 版本与迁移
    ValueTask<Result<SchemaVersion>> VersionAsync(CancellationToken ct);
    ValueTask<Result<SchemaVersion>> MigrateAsync(CancellationToken ct);

    // 读写（数据模型住契约层；存储只认 T）
    ValueTask<Result<Option<T>>> GetAsync<T>(string table, string key, CancellationToken ct);
    ValueTask<Result>            PutAsync<T>(string table, string key, T value, CancellationToken ct);
    ValueTask<Result>            DeleteAsync(string table, string key, CancellationToken ct);
    ValueTask<Result>            AppendAsync<T>(string stream, T record, CancellationToken ct);
    IAsyncEnumerable<T>          ScanAsync<T>(string table, ScanQuery query, CancellationToken ct);
}

public interface IStoreTransaction : IAsyncDisposable
{
    ValueTask<Result> CommitAsync(CancellationToken ct);
    ValueTask RollbackAsync();
}
```

### 1.3 实例 `store.<kind>#…`

一个库一条物理存储（目录或文件），**它自己就是实例**——类型不是对象，存储不必为"类型"再造一层空壳（`17`：主抽象只承载"怎么存"）。

### 1.4 事件（由 `IEmit` 发，`01 §7`）

| 事件 | 何时 | 载荷 |
|---|---|---|
| `store.opened` / `store.closed` | 生命周期 | `kind`、路径摘要 |
| `store.migrated` | 版本前进 | `kind`、`from`、`to`、耗时 |
| `store.purged` | 显式清理完成 | `kind`、删了多少、保留水位 |
| `store.degraded` | 磁盘满 / 只读挂载 | `kind`、`Error` |

### 1.5 不变量（写代码前必须成立）

1. **物理隔离**：四个库各自目录/文件，不共用一张大表（`17`）。
2. **迁移只前进**：版本号单调上升；没有"降级迁移"这条路，回退靠恢复备份。
3. **`Purge` 必须显式**：**没有自动过期**（对齐 `09 §4.2` 的"留存默认永久 + 清理接口"）。
4. **`Append` 幂等**：记录带自己的 id；重复 id 返回 `Error(Conflict)` 或 no-op（二者择一，但**必须一致**）。
5. **`Scan` 只读**：不得在扫描中写；顺序只在同一时刻内稳定，跨时刻不保证（一致性级别 ★待定）。
6. **事务不重入**：`BeginAsync` 内再 `BeginAsync` ⇒ `Error(Conflict)`。
7. **失败不拖垮进程**：磁盘错误一律 `Error(Unavailable)`，不抛异常。

### 1.6 反向判据（会红的测试）

1. `store` 程序集引用 `session` / `channel` / `adapter` 模块程序集 ⇒ 红（只能引用契约层的模型与 `IStore`）。
2. 库里出现 TTL / 定时删除逻辑 ⇒ 红（清理必须走 `Purge`）。
3. 迁移函数出现"降级"分支 ⇒ 红。
4. `StoreManager` 里出现业务字段（缓存消息、会话状态）⇒ 红（管理器只做索引）。
5. 同一 `StoreKind` 能被打开两次 ⇒ 红。

### 1.7 待定

- `GraphStore` 是否成为第四个库（★待定第 2 条）；
- `Scan` 的一致性级别（快照 vs 弱一致）；
- 附件等二进制大对象的存放：进 `AdapterStore` 还是文件系统 + 引用（`09 §3.2` 相关）；
- 是否内建压缩 / 加密（若加密，密钥归 `secret`，库自己不认识密钥内容）。

### 1.8 现状：实际落地的形状

上面 1.1–1.3 的 `IStoreManager` / `IStore` 是目标形状，代码里还不是它。今天的存储是**一个实现多个端口**：

| 端口 | 谁在用 | 说明 |
|---|---|---|
| `IStateStore` | 组件状态、图、参数、频道期望状态 | `scope + key → JSON`；"不存在"不是错误 |
| `IMessageStore` | Adapter / Channel 的历史与留痕 | 一行一条消息；重复的平台消息是 `Conflict` 而不是第二行 |
| `IQueuedMessageStore` | 入站日志、待办标记 | 一行一条，能删、能数、能按容量裁旧 |
| `IArtifactStore` | 模型请求/响应、拼装后的提示词 | 只认字节与路径，不认识任何业务类型 |
| `IMemoryStore` | 会话的 `remember` / `recall` / `forget` | 碎片与笔记两层，见 [`21`](21-记忆.md) |
| `IAtomicWork` | "追加消息 + 写标记"这类一步两个写 | SQLite 上有真事务；文件后端只能顺序执行 |
| `IAuditSink` | 每一次能力调用 | 不可关，写失败也不能拖垮它描述的动作 |

一个 `SqliteStore` 同时实现它们（`src/ALN.Storage.Sqlite`），schema 版本记在 `PRAGMA user_version`
（当前 v4；每一步迁移都在 `Migrate()` 里按版本号加，不去要求任何人丢掉数据）。`store` 还不是模块
（见 `18` 的扩展点清单），端口由宿主直接给需要的人。

## 2. `model`：一次无状态的模型调用

（用户裁定：**模型调用参考 ALC**；执行模型是**单线程 async**。）

### 2.1 先划清与 ALC 的差别

ALC 的 `IModelClient` 是**状态式**的：`AddMessage` / `SetConversationHistory` / `AddToolResult` 累积在 client 内部，再 `StreamChatAsync` 吐出增量。ALN **不照搬**这一层，原因只有一条：

> **会话是数据，请求是由记录现算出来的**（`I-11`、`08 §2`）。状态挂在 client 上，就等于把会话历史复制了一份到 provider 手里，两份事实必然分叉。

所以 ALN 的 provider **无状态**：每次调用把**完整请求**传进去，provider 不记得上一次。

### 2.2 形状

| | id | 是什么 |
|---|---|---|
| 唯一模块 | `model` | provider 注册表 + 按 `modelId` 解析 + 健康与限流 |
| 模块类 | `model.openai` / `model.anthropic` | **一种协议**的实现契约 |
| 实例 | `model.openai#…` | 一个 endpoint + 一份凭据 |

```csharp
public interface IModelManager
{
    ValueTask<Result> RegisterAsync(IModelProvider provider, CancellationToken ct);
    Result<IModelProvider> Resolve(string modelId);          // 由 provider 声明自己承载哪些 modelId
    IReadOnlyList<ProviderInfo> List();                       // 含健康、当前在飞数、限流窗口
}

public interface IModelProvider
{
    ProviderDescriptor Describe { get; }
    IAsyncEnumerable<ModelEvent> CompleteAsync(ModelRequest request, CancellationToken ct);
}
```

### 2.3 请求：三槽位 + 时间线 + 工具表

```csharp
public sealed record ModelRequest(
    string ModelId,
    PromptBlock  System,                  // 系统块：1 块（框架 + 人设 + 准则）
    TimelineItem Opening,                 // 会话的第一条 user 消息（原因 + 目标）
    IReadOnlyList<TimelineItem> Timeline, // 时间线：已渲染成请求形态的记录
    PromptBlock                  Round,   // 本轮注入块：浮动（时间/记忆/状态）+ 新消息；浮动不落盘（11 §5）
    IReadOnlyList<ToolSchema> Tools,      // 工具表：恒定，不随会话/频道/切号变（09 §2.4）
    SamplingSettings Sampling,
    string? CacheHint = null);            // 供应商前缀缓存的可选提示，不是正确性依赖

public sealed record ToolSchema(string Name, string Description, string ParametersJson);
public sealed record SamplingSettings(double? Temperature, int? MaxOutputTokens, double? TopP, IReadOnlyList<string>? Stop);
```

⚠️ **`Head` / `Tail` 是渲染产物，不是数据源**：它们由 `session.build-prompt` 现算（`08 §10`），provider 只见字节，不见贡献者。

⚠️ **不用 `previous_response_id`**：ALC 的核查结论是它本来就没用（每次全量重放，`OpenAiResponsesRequest.cs:10-24`），前缀命中交给供应商按前缀处理。ALN 沿用这条，**不引入"续链"这条隐式状态**。

### 2.4 响应：事件流，恰好一个终态

```csharp
public abstract record ModelEvent;
public sealed record ThinkingDelta(string Text)      : ModelEvent;   // 推理内容（如有）
public sealed record TextDelta(string Text)          : ModelEvent;
public sealed record ToolCallDelta(int Index, string CallId, string Name, string ArgsJsonFragment) : ModelEvent;
public sealed record Completed(StopReason Reason, Usage Usage, string? ProviderResponseId) : ModelEvent;
public sealed record Failed(Error Error)             : ModelEvent;

public sealed record Usage(int InputTokens, int OutputTokens, int? CacheReadTokens = null, int? CacheWriteTokens = null);
public enum StopReason { EndTurn, ToolUse, MaxTokens, ContentFilter, StopSequence }
```

三条不变量：

1. **流以 `Completed` 或 `Failed` 结束，恰好一个**——没有"自然结束"，也没有"结束两次"。
2. **`Usage` 必须上报**（拿不到就填 0 并标 `Detail`），否则计量与预算没有依据。
3. **取消原样冒泡**（`OperationCanceledException`），**不算 `Failed`**——失败是"模型/协议层面不行了"，取消是"我们不要了"（`08 §9`）。

### 2.5 重试：在 `session` 的步 ④，不在 provider 里

- provider **只负责把 `Error.Retryable` 标对**（429 / 5xx / 连接重置 = 可重试；400 / 内容过滤 = 不可重试）；
- **重试决策在会话的步 ④**（`08 §2` 的"唯一重试点"）：指数退避 + 抖动，且**每次重试前丢弃已收到的增量缓冲**；
- 这样"机制/策略分离"（`I-16`）成立：provider 不知道预算，会话不知道 HTTP。

⚠️ **重试的边界**：只重试"还没产出任何有效增量"的那一段；如果已经收到部分文本再失败，**要么整体重来要么如实报错**，不许把两次输出拼成一条（那会产出一段从未存在过的文本）。

### 2.6 事件与审计

| 事件 | 去向 | 说明 |
|---|---|---|
| `model.request.started` | journal | 模型、请求指纹、估算输入 |
| `model.request.finished` | journal | 用量、耗时、终态 |
| `model.request.failed` | journal + 审计 | 失败码与 `Retryable` |
| 每次出站网络访问 | **审计**（不可关） | 走 `net` 能力，`06` 的绝对要求 |

### 2.7 不变量

1. **provider 无状态**：不持有任何会话历史、工具结果、上一次响应。
2. **一个 provider 实例可被多会话并发使用**（单线程 async 下即交错），因为它无状态。
3. **请求必须自足**：只给 `ModelRequest` 就能发出，不需要"先设置什么"。
4. **不静默降级**：provider 不支持的工具/多模态，在 `Describe` 里声明，由调用方决定，不在发送时偷偷丢弃。

### 2.8 反向判据（会红的测试）

1. `IModelProvider` 上出现 `AddMessage` / `SetHistory` / `AddToolResult` 这类累积型方法 ⇒ 红（ALC 形状不许回流）。
2. 请求里出现 `previous_response_id` 或"只传增量"⇒ 红。
3. 一个流没有终态、或终态出现两次 ⇒ 红。
4. provider 内部做重试 ⇒ 红（重试归会话）。
5. 把两次尝试的文本拼接输出 ⇒ 红。

### 2.9 待定

- 多模态 `content parts` 的具体形状（图片、音频、文件）；
- 推理内容是否要在下一轮回传（部分 provider 要求回传 `reasoning` 块才不报错）；
- 每 provider 的并发/限流参数（QPS、在飞上限）；
- `CacheHint` 的实际用途（只是诊断，还是参与请求）。

## 3. `tool`：一次工具调用

### 3.1 形状

| | id | 是什么 |
|---|---|---|
| 唯一模块 | `tool` | 注册表 + 工具表（进请求的那一份） |
| 模块类 | `tool.<name>` | **一个工具的定义**（描述符 + 绑定 + 渲染器） |
| 实例 | `tool.<name>#1` | 同名工具的不同实现（v0 只有一个） |

```csharp
public interface IToolManager
{
    ValueTask<Result> RegisterAsync(ITool tool, IToolRenderer renderer, CancellationToken ct);
    Result<ITool>     Resolve(string name);
    IReadOnlyList<ToolInfo> List();            // 进模型工具表的那些（已按 Exposed 过滤）
}

public interface ITool
{
    ToolDescriptor Describe { get; }
    ValueTask<Result<ToolOutcome>> InvokeAsync(ToolInvocation inv, IToolContext ctx, CancellationToken ct);
}

public interface IToolRenderer
{
    // 纯函数：同样的 outcome 两次渲染必须逐字节相同（I-14）
    IReadOnlyList<PromptBlock> Render(ToolInvocation inv, ToolOutcome outcome);
}
```

### 3.2 描述符：显式声明，不从端口投影

```csharp
public sealed record ToolDescriptor(
    string       Name,
    string       Description,
    string       ParametersJson,     // JSON Schema；加载期做合法性校验
    ToolBinding  Binding,            // 绑定到哪个模块端口：{ module, kind?, instance?, port }
    ToolEffects  Effects,            // None | ReadOnly | SideEffect | NonIdempotent
    ToolTimeouts Timeouts,           // SyncWait / AsyncDeadline（I-23）
    bool         ExposedToModel);    // 默认 false：逃生舱（adapter/invoke）默认不给模型

public sealed record ToolTimeouts(TimeSpan SyncWait, TimeSpan? AsyncDeadline)
{
    public bool CanGoAsync => AsyncDeadline is { } d && d > SyncWait;
}
```

⚠️ **与 `X-16` 的分界**：`ExposedToModel` 是**每个工具自己的显式声明**，不是"端口默认暴露再挑着关"。判据：一个工具可以没有对应端口（纯函数工具），一个端口可以不产生任何工具——两者独立声明，互不推导。

### 3.3 五阶段由执行器负责，不写在工具里

```csharp
public interface IToolExecutor
{
    // ① 权限检查 ② 审计 ③ 绑定调用 ④ 结果规范化 ⑤ 渲染
    ValueTask<Result<ToolExecution>> ExecuteAsync(string name, string argsJson, IToolContext ctx, CancellationToken ct);

    // 异步结局回来时，作为 pending 的一次调用推入时间线（08 §5.2）
    ValueTask<Result> PushDeferredAsync(string attemptId, ToolOutcome outcome, CancellationToken ct);
}

public sealed record ToolExecution(
    string   AttemptId,
    ToolStatus Status,               // Ok | Error | Timeout | Denied | Unsupported | Deferred
    IReadOnlyList<PromptBlock> Blocks);
```

`ToolOutcome`（规范化后的结果）：

```csharp
public sealed record ToolOutcome(
    ToolStatus Status,
    IReadOnlyList<ContentPart> Parts,   // 结构化内容，不是拼好的字符串
    ToolSnapshot? Snapshot,             // 引用 + 快照 + 指纹（I-14）
    string? Detail);                    // 原话，不解析

public sealed record ToolSnapshot(string Ref, string Fingerprint, bool Frozen);
```

### 3.4 不变量

1. **工具不抛异常**：一切失败都是 `Status != Ok` + `Detail`。
2. **同一会话内串行执行**（v0）；并行只允许显式声明 `Effects == ReadOnly` 的工具。
3. **取消必须传下去**：`ct` 要传到绑定调用与底层 IO。
4. **脚本不能运行期注册工具**：注册只发生在装配期。
5. **绑定加载期校验**：`Binding` 指向的模块/实例/端口必须存在，否则加载失败。
6. **`NonIdempotent` 在飞时拒绝重复**：同一逻辑操作的第二次发起返回 `Deferred` 或 `Denied`，不执行两遍。
7. **渲染是纯函数**：同 `(inv, outcome)` 两次渲染逐字节相同。

### 3.5 事件

| 事件 | 去向 |
|---|---|
| `tool.invoked` / `tool.finished` | journal |
| `tool.denied` | journal **+ 审计**（拒绝也要记，`06` 绝对要求 ④） |
| `tool.deferred` / `tool.settled` | journal |

### 3.6 反向判据（会红的测试）

1. 工具实现里 `throw` 逃出 `InvokeAsync` ⇒ 红（执行器要兜住并转成 `Error(Internal)`，但工具自己也不许抛）。
2. 运行期调用 `RegisterAsync` ⇒ 红（只在装配期允许）。
3. `Binding` 指向不存在的端口而加载成功 ⇒ 红。
4. 同一工具两次渲染同一结果产生不同字节 ⇒ 红。
5. 工具表里出现未声明 `ExposedToModel` 的工具 ⇒ 红。

### 3.7 待定

- `ParametersJson` 的校验深度（只校验 JSON 合法性，还是校验能否解析成 schema）；
- 渲染器与工具的绑定关系（随工具一起注册，还是允许一个工具多个渲染器）；
- 单次结果的体积上限（防一个工具把 10 MB 塞进时间线）；
- `ReadOnly` 工具真并行的调度细节。

## 4. `logic`：一次纯计算

### 4.1 形状：判定点，不是执行点

```csharp
public interface ILogicManager
{
    ValueTask<Result<ILogic>> CreateAsync(LogicSpec spec, CancellationToken ct);   // 只在装配期
    IReadOnlyList<LogicInfo> List();
}

public interface ILogic
{
    LogicDescriptor Describe { get; }
    // 纯：同样的 (rules, input) 必须得到同样的 decision
    ValueTask<Result<Decision>> EvalAsync(JsonNode input, JsonNode rules, CancellationToken ct);
}

public sealed record LogicDescriptor(
    string Name,
    string InputSchema,        // 输入形状（便于装配期校验）
    IReadOnlyList<IntentKind> CanEmit,   // 它能产出哪些 intent kind
    bool IsPure);              // false ⇒ 用到了时钟/随机（必须显式声明）
```

### 4.2 产物是 `Intent`，不是动作

```csharp
public sealed record Decision(
    Intent  Intent,
    string? Rationale,     // 为什么这么判（诊断用，可为空）
    double? Confidence);   // 可选，模型/规则给的自评

public sealed record Intent(
    IntentKind Kind,               // 封闭枚举，住在代码里（03 §6）
    IntentTarget? Target,          // 相对角色——不许写死实例
    JsonNode? Args);               // 该 kind 的参数

public sealed record IntentTarget(string? Role);   // 如 "session:this" / "channel:bound"
```

⚠️ **`Kind` 是代码不是数据**：脚本不能发明新的 kind（那等于让脚本定义能力）。新增 kind 要走装配版本。

⚠️ **`Target` 只能相对**：脚本说"发给这个会话绑定的频道"，不能说"发给 `Channel.Conversation#…`"。写死实例就是注入面（`02 §7.2`、`04` 的同一教训）。

### 4.3 不持表、不做事

1. **`rules` 随输入进来**，`ILogic` 实例不缓存规则表（可缓存"编译后的脚本"，不缓存"这一次的规则"）。
2. **没有任何其他端口**：`ILogic` 上不出现 store / tool / channel 的方法。它算，不算就是不算。
3. **能力注入只给"算"需要的东西**：时钟、随机、纯函数库；**不给** net / file / store。

```csharp
public interface IScriptHost        // 受限域的脚本执行（05 / 06 / 07）
{
    ValueTask<Result<JsonNode>> RunAsync(
        ScriptRef               script,
        JsonNode                input,
        IReadOnlyList<CapabilityGrant> grants,   // 装配授予的 scoped 句柄
        CancellationToken       ct);
}
```

### 4.4 不变量

1. **纯**：`IsPure == true` 的逻辑点，同输入必须同输出（可测、可重放）。
2. **有 deadline**：脚本执行必须有超时——Jint 的 constraints 是 cooperative，管不住同步回调（`06 §6.3`），所以超时要靠容器外的墙钟 + 能力自带超时。
3. **能力全 async**：注入的能力接口一律 `ValueTask` + `ct`，不许同步阻塞。
4. **不许动态注册**：脚本不能在运行期造工具、造 kind、造能力。
5. **失败即 `Result`**：脚本抛错 → `Error(Invalid, Detail: 脚本栈摘要)`，不穿透。

### 4.5 事件

`logic.evaluated`（journal：名字、耗时、是否纯、产出 kind）；`logic.failed`（journal + 审计，若脚本来自自举改动则必须审计）。

### 4.6 反向判据（会红的测试）

1. `logic` 程序集引用 `store` / `tool` / `channel` ⇒ 红。
2. 脚本能触达 `Process` / `File` / 网络 ⇒ 红（容器白名单）。
3. `IntentTarget` 能指向任意实例地址 ⇒ 红（只允许相对角色）。
4. 一次 `EvalAsync` 没有超时 ⇒ 红。
5. 同一 `(rules, input)` 两次 `EvalAsync` 结果不同（`IsPure == true` 时）⇒ 红。

### 4.7 待定

- `IntentKind` 的初始枚举（`ignore` / `reply` / `inject` 够不够，README 待办 #5）；
- 规则表归谁（频道配置 / 独立 `rule` 模块属性，README 待办 #4）；
- "表达式"与"脚本"是同一个 `ILogic` 的两种 spec，还是两个接口（`03` 的阶梯：无能力表达式 → 有白名单能力的脚本）。

## 5. `session`：一步怎么走

（依据 [`08`](08-会话与循环.md)。这是最大的一个模块，也是"会话是数据、推进是过程"（`I-11`）的落点。）

### 5.1 一个会话的形状

| | id | 是什么 |
|---|---|---|
| | 例子 | 是什么 |
|---|---|---|
| 模块类 | `Session.Chat` | 一种会话 |
| 唯一模块 | `SessionManager` | 索引 + 创建/销毁 + 激活入口（单例） |
| 实例 | `Session.Chat#…` | 一个会话 |

```csharp
public interface ISessionManager
{
    // 命名即创建：不在就给一个，在就把那一个还回来（spec 只被创建用到）
    ValueTask<Result<ISession>> OpenAsync(string sessionId, SessionSpec spec, CancellationToken ct);
    ValueTask<Result<ISession>> GetAsync(string sessionId, CancellationToken ct);   // 只查，不造

    // 没人说话的一轮（到点醒来）。忙就拒绝，不排队
    ValueTask<Result<SessionTurnResult>> ActivateAsync(string sessionId, ActivationReason reason,
        DateTimeOffset? at, CancellationToken ct);

    ValueTask<Result>           DeleteChannelAsync(string channel, CancellationToken ct);
    Result<SessionState>        GetState(string sessionId);
    ValueTask<Result<IReadOnlyList<SessionSummary>>> ListAsync(CancellationToken ct);
    ValueTask<Result<SessionSweepReport>> SweepAsync(DateTimeOffset now, ISessionDeadlineHandler? handler, CancellationToken ct);
    ValueTask<Result>           ArchiveAsync(string sessionId, string destinationDirectory, CancellationToken ct);
    ValueTask<Result>           RestoreAsync(string sessionId, string sourceDirectory, CancellationToken ct);
}

public interface ISession : IModule, IAddressed      // Id 与 Address 是同一个值，两种写法
{
    SessionSpec  Spec  { get; }     // 它是什么，创建时定下，之后谁也不能改
    SessionState State { get; }     // 做出这个句柄时的样子
    ValueTask<Result<SessionTurnResult>> RunTurnAsync(
        Guid activationId, SessionTurnInput input, ISessionToolbox? tools, CancellationToken ct);
}
```

### 对外只有四样

会话循环**留在模块内部**（这是"模块坐办公室"），它对世界只做四件事：

| 形态 | 名字 | 说明 |
|---|---|---|
| 函数调用 | `provideContext` | 要这一轮的系统块与消息 |
| 函数调用 | `complete` | 要一次模型补全 |
| 工具 | `speak` | 要说话（由图代理到频道） |
| 生命周期事件 | `session.turn.started` / `session.turn.completed` / `session.waiting` | 只通知，无返回 |

- 会话**不认识**消息库、模型、频道——它只持两个脚本实例的 `ModuleId`（在 spec 里写一次）。
- **spec 在创建时给一次**，之后不再传：`RunTurnAsync` 不收 `SessionSpec`，`SessionState.SupersededAt` 已经删掉。**已实现**。调用方拿一个已存在的名字再开一次，得到的是那个会话自己的 spec（不是它这次传的），差异记一条 warn 信号（`session.spec` / `stored-wins`）——**说清楚，但不改写它**。这也是为什么"spec 变了"不再是一种死亡：会话照样活着，只是不按新来的那份跑。
- 句柄按 id 解析、**按需构造**，不必常驻：会话是"偶尔被叫醒"的东西。**已实现**：管理器实现 `IModuleIndex`，`Locate` 只读 `spec.json` + `state.json` 两个小文件就构造出句柄；`Entries` 只列目录名。

### 5.2 数据：三件套 + 状态

```csharp

    string        ModelId,
    string        Objective,             // 必填：会话因目标而生；没目标它自己也不知道干什么（08 §10.2）
    Continuation  Continuation,          // UntilDone | OneStep
    IReadOnlyList<string> Tools,         // 工具名（装配期已校验存在）
    string        FormatVersion);

public enum SessionStatus { Running, Dormant }        // 只有两个（X-15）

public sealed record SessionState(
    SessionStatus Status,
    SessionPhase  Phase,                 // 只是观察值，不落盘（08 §1）
    bool          Locked,                // 单向刹车（I-21），与 Status 正交
    DormantInfo?  Dormant,
    UsageAccumulator Usage,              // 累计 token
    int           SchemaVersion);

public sealed record DormantInfo(
    string?       Awaiting,              // 在等什么（自由字符串，给人看）
    IReadOnlyList<string> Activations,   // 哪些东西能唤醒它
    DateTimeOffset? NotBefore,
    bool          ExitOnWake);

public enum SessionPhase { Collecting, AwaitingModel, Thinking, Outputting, ToolCalling, Persisting }

// 步 ③ 的产物：四样 + 工具表 + 指纹（08 §10.2）
public sealed record BuiltPrompt(
    PromptBlock  System,                    // 1 块：ALN 环境（框架 + 人设 + 准则）
    TimelineItem Opening,                   // 会话的第一条 user 消息（激活原因 + 目标）
```

⚠️ **`Phase` 不进记录、不落盘**：它每步都变，落盘就等于给每一步制造一次无意义的写入（`08 §1`）。

### 5.3 一步的九个位置，哪些是端口

```
① emit step.begin            → IEmit（不是端口）
② 取用（拉到新消息）          → 图上的 call（channel.read / adapter 相关）
③ build-prompt              → ISession.BuildPromptAsync     ← 端口
④ 调模型                     → 图上的 call（model.CompleteAsync）+ 唯一重试点
⑤ 工具                       → 图上的 call（tool.ExecuteAsync）+ 双超时
⑥ apply（把结果并进记录）     → 会话内部硬代码
⑦ persist（原子边界）         → 图上的 call（store.Append / Put）
⑧ output（发给频道）          → 图上的 call（channel.post）
⑨ 内核判定（继续/Dormant/退出）→ 驱动（不是 session 的端口）
```

### 5.4 上下文注入：贡献者接口（详见 `08 §10`）

```csharp
public interface IPromptContributor
{
    ValueTask<Result<PromptContribution>> CollectAsync(CollectPoint point, PromptContext ctx, CancellationToken ct);
}

public enum CollectPoint
{
    SessionStart,     // 只一次
    Prompt,           // 系统块（纯只读）
    Tail,             // 本轮注入块（物理位置在末尾）
    Timeline,         // 时间线增量
    BeforeModelCall,
    ModelDelta,
    AfterToolCall,
    StepEnd,
    SessionEnd
}

public sealed record PromptContribution(
    CollectPoint Point,
    string Slot,                        // system / premier / tail / ...
    IReadOnlyList<PromptBlock> Blocks,  // 渲染输入，不是渲染结果
    int Order,                          // 稳定排序键
    string Source);                     // 谁贡献的（诊断 + 审计）
```

三条约束：

1. **贡献者只提供渲染输入**，渲染由会话做（`08 §10.1`）。
2. **不许否决**：`CollectAsync` 失败 = 这一段缺席，不是整轮失败（失败要可见：journal + 计数）。
3. **`Prompt` 点只在全局重载时被问**（不是每步）：它必须纯只读，且同一份输入重算出的字节要与上次一致——否则一次重载就会让所有会话的头同时漂移（`11 §2`）。

### 5.6 事件

| 事件 | 何时 |
|---|---|
| `session.created` / `session.destroyed` | 生命周期 |
| `session.activated` | 有激活源进来 |
| `session.dormant` | 进入 `Dormant`（带 `DormantInfo`） |
| `session.phase` | `Phase` 变化（观察用，不进记录） |
| `session.step.completed` / `session.step.failed` | 一步结束 |
| `session.exited` | 软着陆退出 |

### 5.7 不变量

1. **无后台循环**：`ISession` 的实现不得持有 `Task` / `Timer` / 订阅（`I-11` 的判据：构造参数里出现即红）。
2. **状态只有两个** + `Locked` 是正交布尔（`X-15`）。
3. **系统块由全局快照提供**；只有全局重载能换，且**一次换全部**（`08 §10.3`）；开场消息永不替换。
4. **落盘是原子边界**：⑦ 之前的东西一律不留（`08 §9`）。
5. **一步内的跨模块动作全走图**（`01 §11`），会话不持有任何别的模块端口。
6. **重试只在 ④**，且只在"还没产出有效增量"时（`§2.5`）。

### 5.8 反向判据（会红的测试）

1. `ISession` 实现里出现 `Task.Run` / `Timer` / `Subscribe` ⇒ 红。
2. `SessionStatus` 出现第三个值 ⇒ 红。
3. `Phase` 被写进 `history` / `state` ⇒ 红。
4. 会话构造参数里出现 `IChannel` / `IStore` / `ITool` 端口 ⇒ 红（跨模块只走图）。
5. `Unlock` 出现在模块描述符或工具表里 ⇒ 红。
6. 同一会话两步之间系统块字节不同（未经全局重载）⇒ 红。

### 5.9 待定

- 游标存在 `state` 的哪个字段、一次读多少条；
- 压缩检查点的触发条件（步数 / token 水位）；
- `ReloadSystemPromptAsync` 的验收细节（`08 §10.3`）：指纹相同 no-op、重载后所有会话下次请求换新、历史不变；
- `UsageAccumulator` 的粒度（按步 / 按轮 / 按会话）。

## 6. `channel`：一条双向对话

（依据 [`09`](09-频道与连接.md)。）

### 6.1 形状

| | id | 是什么 |
|---|---|---|
| 唯一模块 | `channel` | 索引 + 创建/销毁 |
| 模块类 | `channel.<platform>` | 一种逻辑对话契约 |

```csharp
public interface IChannelManager
{
    ValueTask<Result<ModuleId>> CreateAsync(ChannelSpec spec, CancellationToken ct);
    ValueTask<Result>          DestroyAsync(ModuleId channel, CancellationToken ct);
    Result<IChannel>           Get(ModuleId channel);
    IReadOnlyList<ChannelInfo> List();
}

public interface IChannel
{
    ChannelSpec Spec { get; }
    IReadOnlyList<AdapterAvailability> Availability { get; }   // 三色表（只读观察）

    // 入站认领：图把 adapter.envelope 转成一次 call（09 §3）
    ValueTask<Result<ClaimResult>> ClaimAsync(AdapterEnvelope envelope, CancellationToken ct);

    // 读取：被会话的步 ② 调，游标归会话
    ValueTask<Result<MessagePage>> ReadAsync(Cursor cursor, int limit, CancellationToken ct);

    // 出站：被会话的步 ⑧ 调
    ValueTask<Result<SendResult>> PostAsync(OutboundMessage msg, CancellationToken ct);
}
```

### 6.2 数据

```csharp
public sealed record ChannelSpec(
    string PlatformId,
    IReadOnlyList<Binding> Bindings,     // 加载期校验：每个 adapter 必须是 IChatAdapter
    string FormatVersion);

public sealed record Binding(string AdapterInstanceId, string PlatformConversationId);

public sealed record Cursor(string? AfterCanonicalId, long? Seq);

public sealed record MessagePage(
    IReadOnlyList<ChannelMessage> Items,
    Cursor Next,
    bool HasMore);

public enum ClaimResult { Accepted, NotMine, SelfEcho, Rejected }
```

⚠️ **`ClaimAsync` 的四种结果各有语义**：

| 结果 | 含义 | 后续 |
|---|---|---|
| `Accepted` | 是本频道的、且不是自己发的 | 走 candidate → accepted → 激活会话 |
| `NotMine` | 不是本频道绑定的（群 id / adapter id 不匹配） | **丢弃**，零成本（`09 §3` 约束 4） |
| `SelfEcho` | 是自己名下某个账号发的 | 只做回执与对账，**不激活会话**（`09 §2.3`） |
| `Rejected` | 归属对但被拒（权限 / 形状不合法） | 记审计，不回执 |

### 6.3 可用性表：三色

```csharp
public sealed record AdapterAvailability(
    string        AdapterInstanceId,
    AvailabilityColor Color,             // Green | Yellow | Red
    AvailabilitySource Source,           // HeartbeatTimeout | AdapterFault | SendFailure | AdapterHealthy | SendSuccess
    string?       Detail,                // 自由字符串，不解析（09 §6.1.1）
    int           ConsecutiveFailures,
    DateTimeOffset LastHeartbeatAt,
    DateTimeOffset ChangedAt,
    DateTimeOffset? EligibleAt);

public enum AvailabilityColor  { Green, Yellow, Red }
public enum AvailabilitySource { HeartbeatTimeout, AdapterFault, SendFailure, AdapterHealthy, SendSuccess }
```

选路（`09 §6.1.3`）：`priority` 升序 × 三色 → 选中一个或 `no-route`。**这是 Channel 内部硬代码**，不进图（它是同一个实例内部的决策）。

### 6.4 事件

| 事件 | 何时 | 载荷要点 |
|---|---|---|
| `channel.message.candidate` | 认领成功、待持久化 | `canonicalMessageId`、来源 |
| `channel.message.accepted` | 持久化确认后 | 同上 + 可读水位 |
| `channel.outbound.requested` | 会话要发 | `attemptId`、目标 |
| `channel.adapter.availability.changed` | 换色 | `from` / `to` / `source` / `detail` |
| `channel.primary.changed` | 选路结果变 | `fromAccountId` / `toAccountId` / 候选快照 |
| `channel.no-route` | 出站无可用候选 | 候选快照 |

### 6.5 不变量

1. **只绑双向 Adapter**：`Binding` 指向的实例必须是 `IChatAdapter`，否则加载失败（`09 §2.4`）。
2. **`(adapterInstanceId, platformConversationId)` 在同一个 Channel 内唯一**。
3. **只有主 Adapter 投递**：入站与出站都走选路结果，副只留存（`09 §4.2`）。
4. **全红拒发**：不挑一个红的试（`09 §6.1.3`），返回 `Error(Unavailable)`。
5. **candidate → accepted 是屏障**：Store 未确认前不得对外宣告可读（`09 §3.1`）。
6. **`SelfEcho` 不激活会话**（`09 §2.3`）。
7. **不做去重、不做自动过期**（`09 §4`、`09 §4.2`）。

### 6.6 反向判据（会红的测试）

1. `IChannel` 上出现 `Adapter` 类型的参数/返回值（而不是地址与不可变数据）⇒ 红。
2. Channel 里出现去重表 / TTL ⇒ 红。
3. 绑到单向 Adapter 而加载成功 ⇒ 红。
4. Channel / Session 侧出现 `platformId` 分支 ⇒ 红（`09 §2.4`）。
5. `PlayLoad`/平台报文类型出现在 `IChannel` 签名里 ⇒ 红。

### 6.7 待定

- `Cursor` 的具体形状（canonical id vs 单调序号 vs 两者）；
- `ReadAsync` 的 `limit` 上限与分页语义；
- 编辑 / 撤回等平台动作**不经过 Channel**（走 `adapter` 工具），Channel 是否需要知道"某条消息已被编辑"（若需要，是 `claim` 的一种 envelope 类型）。

## 7. `adapter`：外部通道

（依据 [`09 §2](09-频道与连接.md)。**方向是能力，不是残缺**；Channel 只绑双向。）

### 7.1 形状

| | id | 是什么 |
|---|---|---|
| 唯一模块 | `adapter` | 索引 + 创建/销毁 + 全局健康汇总 |
| 模块类 | `adapter.qq` / `adapter.rss` | 一种平台协议 |
| 实例 | `adapter.qq#…` | 一个账号 / 一个端点 |

```csharp
public interface IAdapterManager
{
    ValueTask<Result<ModuleId>> CreateAsync(AdapterSpec spec, CancellationToken ct);
    ValueTask<Result>          DestroyAsync(ModuleId adapter, CancellationToken ct);
    Result<IAdapter>           Get(ModuleId adapter);
    IReadOnlyList<AdapterInfo> List();
}
```

### 7.2 三个能力接口（按方向）

```csharp
public interface IAdapterBase
{
    AdapterDescriptor Describe { get; }      // 平台、账号、动作表、限额、方向
    ValueTask<Result> ConnectAsync(CancellationToken ct);
    ValueTask<Result> DisconnectAsync(CancellationToken ct);
    ValueTask HeartbeatAsync(CancellationToken ct);                  // 喂狗（不能升级颜色）
    ValueTask ReportFaultAsync(string detail, CancellationToken ct); // 自报故障 ⇒ 红
    ValueTask ReportHealthyAsync(CancellationToken ct);              // 恢复 ⇒ 绿 + 冷却
}

public interface IInbound  : IAdapterBase { }   // 只收：RSS / webhook / 邮件 / 目录投递
public interface IOutbound : IAdapterBase
{
    ValueTask<Result<SendResult>> SendAsync(OutboundMessage msg, CancellationToken ct);
}
public interface IChatAdapter : IInbound, IOutbound { }   // 双向：聊天平台，Channel 只绑这个
```

⚠️ **入站不走方法，走广播**：`IInbound` 上没有 `ReceiveAsync`——Adapter 收到什么就 `IEmit("adapter.envelope", …)`，**它不知道谁在听**（`09 §3`）。

### 7.3 描述符：动作表就是 `adapter` 工具的展开来源

```csharp
public sealed record AdapterDescriptor(
    string     PlatformId,
    string     AccountId,
    AdapterDirection Direction,               // Inbound | Outbound | Both
    IReadOnlyList<AdapterAction> Actions,     // 逐层展开的第二层（09 §2.4）
    AdapterLimits Limits);

public sealed record AdapterAction(
    string  Name,             // 自由字符串，不设封闭枚举（建议名表 ★待定）
    string  Description,
    string  ParamsSchema,     // JSON Schema
    string? ImplVia = null);  // 原生为 null；替代实现留痕，如 "withdraw+resend"

public sealed record AdapterLimits(
    int  MaxMessageLength,
    int? MaxPerMinute,
    int? MaxAttachmentBytes);
```

`adapter()` → 列 `IAdapterManager.List()`；`adapter(id)` → 列该实例的 `Actions`；`adapter(id, action)` → 回 `ParamsSchema` + 示例；`adapter(id, action, params)` → 调用并返回 `SendResult` 形状。

### 7.4 事件

| 事件 | 说明 |
|---|---|
| `adapter.envelope` | **瞬时广播**：平台收到什么（不重放、不知道订阅者） |
| `adapter.connected` / `adapter.disconnected` | 连接生命周期 |
| `adapter.fault` / `adapter.healthy` | 供 Channel 改可用性 |
| `adapter.heartbeat` | 喂狗 |

### 7.5 不变量

1. **一个 Adapter = 一个平台 + 一个账号 + 一条连接**；`(platformId, accountId)` 全局唯一。
2. **至少一个方向**；Channel 只接受 `IChatAdapter`。
3. **只做协议清洗，不做业务**：不认 `/help`、不做关键字匹配、不判意图。
4. **不读本地路径**：附件进出都通过 `file` 能力句柄拿字节或引用（`09 §2.4` 的"不读本地路径"约束）。
5. **不分派**：不知道有哪些 Channel，只广播（`09 §3`）。
6. **允许持有长驻监听循环**——这是它作为"有输入源的模块"的本质；但只做"收 → 清洗 → emit"，并把 `OnEmergencyStop` 实现成"立刻断开、允许丢"（`08 §6.3`）。

### 7.6 反向判据（会红的测试）

1. Adapter 程序集引用 `channel` / `session` ⇒ 红。
2. Adapter 里出现关键字/命令解析 ⇒ 红（人工审：出现业务词表即红）。
3. Adapter 直接 `File.ReadAllBytes("/path")` ⇒ 红（必须走 `file` 句柄）。
4. 两个实例相同 `(platformId, accountId)` ⇒ 红。
5. Adapter 里出现去重表 ⇒ 红（`09 §4`）。
6. `IInbound` 上出现 `send`、`IOutbound` 上出现入站方法 ⇒ 红。

### 7.7 待定

- **动作名建议表**（`edit` / `modify` / `update` 的推荐命名，不强制）；
- 附件字节怎么传（`mediaRef` 是引用字符串，还是 `IBlobHandle`）；
- 心跳间隔 / 超期阈值 / 冷却期（`09 §8` 的数值待定）；
- 单向 Adapter 的 envelope 由谁消费（`09 §2.4` 待定）。

## 8. `graph` 与驱动：早期静态图接口草案（已由 13 暂时取代）

（本节原依据 [`02`](02-图模块.md)，仍保留作历史接口推导；脚本主导模型见 [`13-脚本编排与工程实施蓝图.md`](13-脚本编排与工程实施蓝图.md)。本节“图是静态数据、无分支”的契约不适用于新方向。）

### 8.1 模块只看得到 `IEmit`

```csharp
public interface IEmit
{
    ValueTask EmitAsync(string @event, JsonNode? payload, ModuleId source, CancellationToken ct);
}
```

- 模块**不认识 `IGraphManager`**（否则就是一次跨模块调用，会成环，`01 §11`）。
- `source` 必填：节点据此解引用（`02 §2`），所以同一张图能跨部署复用。

### 8.2 唯一模块

```csharp
public interface IGraphManager
{
    ValueTask<Result<CompiledGraph>> CompileAsync(GraphSpec spec, CancellationToken ct);   // 校验 → 编译
    ValueTask<Result<ModuleId>>       MountAsync(CompiledGraph graph, CancellationToken ct);
    ValueTask<Result>                UnmountAsync(ModuleId graph, CancellationToken ct);
    ValueTask<Result>                SwapAsync(ModuleId graph, CompiledGraph next, CancellationToken ct);
    IReadOnlyList<GraphInfo>         List();
}
```

### 8.3 编译产物

```csharp
public sealed record CompiledGraph(
    string Name,
    IReadOnlyList<Subscription> Subscriptions,
    string Fingerprint);          // 装配版本的一部分（05）

public sealed record Subscription(
    string Id,                    // 稳定 id：日志、诊断、按边聚合（I-24）
    string FromEvent,
    IReadOnlyList<Node> Chain,
    EdgeKind Kind);               // Signal | Call（只有最后一个节点能是 Call）

public sealed record Node(NodeKind Kind, JsonNode? Config);

public enum NodeKind { Call, Resolve, Map, Eval }   // 四型，无分支无循环（02 §5）
```

### 8.4 驱动（内核，不是模块）

```csharp
public interface IDriver
{
    // 入队只回答"谁可以动了"，不带业务内容（08 §2）
    ValueTask EnqueueAsync(ModuleId target, ActivationReason reason, CancellationToken ct);

    // 跑一步；单线程 async，天然串行
    ValueTask<Result<StepRun>> RunOneAsync(CancellationToken ct);

    DriverStats Stats { get; }   // 队列长度、在飞、最近派发耗时
}

public sealed record StepRun(ModuleId Target, bool Produced, TimeSpan Elapsed);
```

### 8.5 派发点：唯一的记录处（`I-24`）

每次 `EmitAsync` / `CallAsync` 在**这里**记一条结构化记录：

```text
{ stepId, edgeId, subscriptionId, from, to, kind, outcome, elapsedMs, error? }
```

- **不漏记是结构保证**，不是纪律（记录点在唯一入口）。
- 模块自己打的业务日志**不进**链路复原（`09 §6.5.2`）。
- 写入失败只计数告警，**绝不阻塞派发**（`09 §6.5.3`）。

### 8.6 热替换的边界

`SwapAsync` 期间：

- **已经在飞的派发**用旧版跑完（与急停的"在飞步允许收尾"同一条语义）；
- **新到的派发**用新版；
- 因此同一时刻可能有两版并存——**但它们的边 id 一定不同**（`subscriptionId` 含版本指纹），日志不会混。

### 8.7 不变量

1. **模块只认识 `IEmit`**；`graph` 程序集不被任何功能模块引用。
2. **四型节点，无分支无循环**；一张订阅只有最后一个节点能是 `Call`（`02`）。
3. **预算**：订阅 ≤12 条、单条 ≤8 节点、图不触发图；超了加载期拒绝。
4. **图只连不决**：权限、能力、"要不要执行"全在模块或内核（`02 §5`）。
5. **单线程 async**：不存在两个派发同时执行；"模块实例内部串行"因此是天然性质。
6. **派发点必记**：任何一条派发没有 journal 记录即为缺陷。

### 8.8 反向判据（会红的测试）

1. 任何模块程序集引用 `graph` ⇒ 红。
2. `NodeKind` 出现 `Branch` / `Loop` / `If` ⇒ 红。
3. 一张订阅的非末节点是 `Call` ⇒ 红。
4. 订阅数 >12 或链长 >8 ⇒ 加载失败。
5. 一条派发后 journal 里查不到记录 ⇒ 红。

### 8.9 待定

- `GraphStore` 是否成为第四个库（`01 §7`）；
- `Procedure`（过程）的步骤表：一步 / 入站 / 出站 / 定时各自精确到哪几次派发；
- 编译产物是否持久化（还是每次启动重编）。

## 9. 后勤：log / journal / audit / config / secret

三者是**三条不同的通道**，不许合并（`09 §6.5.3`）。

### 9.1 `journal`：可过滤的链路记录

```csharp
public interface IJournal
{
    JournalLevel Level { get; set; }                      // Debug / Info / Warn / Error，单一配置源
    ValueTask WriteAsync(JournalEntry entry);              // 非阻塞；写失败只计数

    // 沿用 ALP 的 ISignalLogger 形状（分组 + 命名 + 结构化 detail）
    IJournalScope Open(string group, string name, JsonNode? detail = null);
}

public sealed record JournalEntry(
    DateTimeOffset At,
    JournalLevel   Level,
    string         Group,        // 模块名
    string         Name,         // 事件名
    JsonNode?      Detail,       // 结构化，不是格式化字符串
    string?        StepId,
    string?        SubscriptionId,
    string?        Error);

public interface IJournalScope : IDisposable { void Event(string name, JsonNode? detail = null); }
```

- **可丢、可落后、绝不阻塞派发**。
- 派发点记录由驱动写入（`§8.5`），模块自己不打链路日志。

### 9.2 `audit`：不可关

```csharp
public interface IAudit
{
    // 关键判定点必须同步落盘；拒绝也要记（06 绝对要求 ④）
    ValueTask<Result> RecordAsync(AuditEntry entry, CancellationToken ct);
}

public sealed record AuditEntry(
    DateTimeOffset At,
    string  Actor,        // 会话 / 用户 / 内核
    string  Action,       // 读 / 写 / 执行 / 拒绝
    string  Target,       // 能力名 + 对象（路径 / 域名 / 主机 / 工具名）
    bool    Allowed,
    string? Reason,
    string? Detail);
```

- **没有 Level、没有过滤开关、没有"关闭"**。
- 写失败怎么办：**记到备用 sink + 计数**，但不静默；这是它自己的预算项。

### 9.3 `log`：给人看的自由文本

```csharp
public interface ILog
{
    void Write(LogLevel level, string message, Exception? ex = null);
}
```

它**不进**链路复原，也不承担审计。允许人读，允许丢弃。

### 9.4 `config`：单一配置源（`X-08`）

```csharp
public interface IConfig
{
    Result<T> Get<T>(string key);
    ValueTask<Result> SetAsync<T>(string key, T value, string reason, CancellationToken ct);
    IReadOnlyList<ConfigEntry> Snapshot();     // 键、值、来源（文件 / 环境 / 默认）、何时改的
}
```

- **只允许一个来源**：散落的 `Environment.GetEnvironmentVariable` 即红（`X-08`）。
- `SetAsync` **必须带 `reason`**（"为什么改"要有字段，`X-08` 的判据）。

### 9.5 `secret`：是**能力**，不是模块端口

```csharp
// 只在受信域注入；受限域拿不到
public interface ISecretAccess
{
    ValueTask<Result<string>> GetAsync(string name, CancellationToken ct);
    // 没有 List / Enumerate：不许枚举密钥名
}
```

⚠️ **它不是模块**：凭证只能通过 scoped 句柄拿到（`06` 的绝对要求 ③），所以它进的是能力表，不进模块清单。

### 9.6 `clock` / `random`

已在 `§0.4`：注入，禁止静态调用。

### 9.7 反向判据（会红的测试）

1. 出现第二条链路记录通道 ⇒ 红。
2. 安全事件只写 `journal` ⇒ 红（`09 §6.5.3`）。
3. `audit` 上出现 `Level` / `Enabled` / `Disable` ⇒ 红。
4. 代码里出现 `Environment.GetEnvironmentVariable` ⇒ 红（`X-08`）。
5. `ISecretAccess` 上出现 `List` / `Enumerate` ⇒ 红。
6. 模块直接 `DateTime.Now` / `Random` ⇒ 红（用注入的 `IClock` / `IRandom`）。

### 9.8 待定

- `journal` 的存储与保留期（与审计分开算量，`09 §8`）；
- `audit` 的备用 sink（写失败时去哪）；
- `config` 的热加载是否允许（还是只允许"显式重载"，与 `C11` 一致）。
