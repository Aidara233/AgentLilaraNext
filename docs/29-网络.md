# 29 · 网络：只能去被点名的地方

> 状态：第一期已实现（`ALN.Net` + 五个动作 + 一个模型工具 + 测试 27 条）。
>
> 本文回答一个问题：**一次抓取怎么能"读一个网页"，而这件事不会变成"这个进程能访问任意地址"。**

---

## 0. 威胁模型（先写这一节，后面所有争论都由它判）

**信任边界 = 宿主磁盘与进程。** 磁盘守不住的部分不为此设计（与 [`27 §0`](27-SSH.md) 同一条线）。这个出口只守四件事：

1. **地址不来自调用方。** 参数里没有任何地方能放绝对 URL —— 这是构造上的，不是校验上的。
2. **名字到地址的映射是人写的。** 只有 `net/targets.json` 里的一行能让一个地址变得可达。
3. **名字解析到哪儿也要看。** 白名单说的是"哪个名字"，不是"哪个 IP"（§4）。
4. **每一次调用都留痕，包括被拒的那些。** 谁、哪个 target、哪个路径、什么结果、多久。

不守的：宿主被攻破、内存被 dump、DNS 服务器本身被投毒（§4 说的是解析结果被检查，不是解析过程可信）。

`06 §2` 早就把这一行写下了 —— `net → AllowlistHttp 句柄：域名白名单 + 方法白名单 + 体积/超时上限` —— 本文是它落地后的样子。

---

## 1. 一个判据：只认名字，不认地址

```csharp
// 调用方写得出这个：
await net.SendAsync(new NetRequest("docs", "GET", "/releases?page=2"), ct);

// 写不出这个 —— NetRequest 里没有字段能放它：
await net.SendAsync("https://example.com/releases", …);   // 不存在这个重载
```

这与 `IFileSystemAccess` 只认 scope、`ISshAccess` 只认 `SshTarget` 是同一条做法：**能力是句柄，不是权限位**（`06 §0` 第 3 条）。

三个后果，都是想要的：

- 模型把地址记错了也走不通，它得到的是"没有这个目标"，而不是去了一个半记得的主机；
- 审计里写的是 `docs`，不是一条带查询串的 URL（查询串是 token、搜索词、账号 id 落地的地方）；
- 允许访问什么，是一份人能读、能 diff、能进版本库的文件。

**本文只管"连接从哪儿出去"，不管"取回来怎么读"。** 取网页、发原始 HTTP、调已登记的服务是三件不同的事，分在 [`30`](30-搜索与抓取.md) 的三层里；这里的三道闸对它们全部生效，唯一的区别是"名字在不在表里"那一道 —— 见 `IAdHocNetAccess`。

## 2. 配置：`<DataRoot>/net/targets.json`

文件不存在 = **一个目标都没有** = 什么都到不了。这是全新数据根的默认，也是唯一安全的默认。

```json
{
  "targets": [
    {
      "name": "docs",
      "base": "https://example.com",
      "methods": ["GET", "HEAD"],
      "paths": ["/docs", "/releases"],
      "maxBytes": 1048576,
      "timeoutSeconds": 15,
      "callsPerMinute": 30,
      "maxConcurrent": 2
    },
    {
      "name": "local-model",
      "base": "http://127.0.0.1:11434",
      "allowPrivate": true,
      "callsPerMinute": 120
    },
    {
      "name": "status-api",
      "base": "https://status.example.com",
      "secret": "status-api"
    }
  ]
}
```

| 字段 | 缺省 | 说明 |
|---|---|---|
| `name` | 必填 | 一个词，无空格。所有调用只用它 |
| `base` | 必填 | 绝对 http(s) URL，**只有 scheme + host + port**。带 `user:pw@`、带 query、带 fragment 的条目**整条拒绝** |
| `methods` | `GET, HEAD` | 只认这七个词；写别的整条拒绝 |
| `paths` | 空 = 该 host 的任何路径 | 前缀按**整段**匹配：`/api` 允许 `/api/v1`，不允许 `/apifoo` |
| `headers` | 空 = 调用方一个头都不能设 | 且 `Host` / `Authorization` / `Cookie` / `Content-Length` / `Transfer-Encoding` / `Connection` / `Proxy-Authorization` **永远拒绝**，即使写了 |
| `maxBytes` | 1 MiB | 上限 8 MiB（硬顶，见 §3） |
| `timeoutSeconds` | 15 | **整次调用的总时长**：DNS + 连接 + 读体 |
| `followRedirects` | `false` | 见 §3 最后一条 |
| `maxRedirects` | 0（`followRedirects` 为真时 3） | |
| `callsPerMinute` | 30 | 滑动窗口，按 target 统计跨所有调用方 |
| `maxConcurrent` | 2 | 同一个 target 同时在飞的请求数 |
| `allowPrivate` | `false` | 见 §4 |
| `secret` | 无 | `ISecretStore` 里的名字；注入为 `Authorization: Bearer <值>`，值从不进参数、审计或回答 |

**坏条目丢弃并说明原因，绝不猜。** `"base": "example.com/x"` 不会被补成 `https://`；`"maxBytes": 0` 不会被当成"不限"。启动时逐条打一行：

```
net: targets[1]: "base" must not carry a user name or password — put the credential in "secret"
restored net: 1 target(s): docs, 1 refused entry(ies)
```

理由和 `24` 的文件 scope 一样：一个跑着的进程与它旁边那份文件说法不一致，比没有这个设置更糟——读文件的人无法从文件推断行为。

## 3. 六道闸

按一次调用的顺序：

| # | 闸 | 形态 | 拒绝时 |
|---|---|---|---|
| 1 | **目标名** | `targets.json` 里有没有这个名字 | `Denied` + `NoSuchTarget`，**不回显调用方给的字符串** |
| 2 | **方法与路径** | `policy.Methods` / `policy.Paths` | `Denied` + `NotAllowed`，回答里列出允许项 |
| 3 | **路径不离开 origin** | 解析后的 URI 必须仍是同一个 scheme + host + port | `Invalid` + `Invalid` |
| 4 | **解析到的地址** | 逐个 IP 检查（§4） | `Denied` + `PrivateAddress` |
| 5 | **体积** | 流式读到上限就停，标 `Truncated`；响应声明超过 8 MiB 直接 `TooLarge` | 从不"静默地短" |
| 6 | **配额与期限** | 每分钟 + 并发 + 总超时 | `Conflict` + `Throttled`（可重试） / `Timeout` |

第 3 条挡的是 `//evil.example/x`：作为相对引用它不是路径，是一个新的 authority，`Uri` 会把它解析到另一台主机。所以判据不是"字符串看着像不像相对路径"，而是"**解析结果还指向不指向这个 target**"。

**第 6 条的期限是一次性的**：`CancellationTokenSource` 从进门开始计时，DNS、连接、等并发槽位、读 body 都算在内。`HttpClient.Timeout` 只覆盖"发出并收到头"，既不是这里要的语义，也拦不住一个缓慢吐字节的服务器。

**重定向默认不跟随。** 允许跟随时也不交给 handler —— handler 会跟到任何地方。这里一跳一跳跟，**每一跳都过第 3 条**，跨 origin 的 302 直接 `NotAllowed`。重定向按原方法与原 body 重放（不做浏览器的 POST→GET 降级）：需要浏览器语义的调用方应当自己读 `Location`。

## 4. 私网：白名单说的是名字，不是地址

`allowPrivate: false`（默认）时，名称解析出的**每一个** IP 都要过一遍：

| 拒 | 范围 |
|---|---|
| 环回 | `127.0.0.0/8`、`::1`、`::ffff:127.0.0.1` |
| 私网 | `10/8`、`172.16/12`、`192.168/16`、`fc00::/7` |
| 链路本地 | `169.254/16`（**云元数据服务就在这儿**）、`fe80::/10` |
| 其他 | `100.64/10`（CGNAT）、`0.0.0.0/8`、组播、广播、保留段 |

检查发生在**自己的连接回调里**，不是先校验再让 handler 重新解析一次 —— 后者有一个 TOCTOU 窗口：校验时解析到公网，连接时解析到 `127.0.0.1`。这里解析一次、用自己解析到的那一个地址连，中间没有第二次解析。

**每个地址都查，不是只查第一个。** 一个名字同时解析出公网与私网地址时，"公网正好排在前面"不能成为可达的理由。

真要用本机服务（本地模型、本机 API）就写 `"allowPrivate": true` —— 那是人的决定，按 target 记下。

## 5. 失败要分得开

| kind | 含义 | 谁的问题 | ErrorCode |
|---|---|---|---|
| `NoSuchTarget` | 名字没写过 | 配置 | `Denied` |
| `NotAllowed` | 方法/路径/头/跨源重定向不在策略里 | 配置 | `Denied` |
| `Invalid` | 路径不是合法相对引用，或离开了 origin | 调用方 | `Invalid` |
| `PrivateAddress` | 解析到了不许碰的地址 | 某个人的决定 | `Denied` |
| `Unreachable` | DNS 失败 / 连不上 | 网络 | `Unavailable`（可重试） |
| `Timeout` | 总期限用完 | 对端或网络 | `Timeout` |
| `TooLarge` | 响应声明自己超过 8 MiB | 对端 | `Invalid` |
| `Throttled` | 每分钟或并发用满 | 本进程在自保 | `Conflict`（可重试） |

压成一个"失败了"，模型只能对用户说"网络不行"，而用户没法据此改任何东西 —— 与 [`27 §5`](27-SSH.md) 同一条理由。

`Error.Detail` 的第一个词就是 kind（`"Timeout: …"`），因为 `Error` 只有一个自由文本字段，而调用方需要能用程序判断。

## 6. 接口

### 6.1 端口（两层，故意的）

```csharp
interface INetAccess           // 取东西：所有会发请求的人拿这一个
{
    IReadOnlyList<string> Targets { get; }        // 只有名字，不含 URL 里的任何东西
    NetTarget? Describe(string target);
    ValueTask<Result<NetResponse>> SendAsync(NetRequest request, CancellationToken ct);
}

interface INetTargetEditing    // 改名单：只有控制面和参数面拿这一个
{
    Result Replace(NetTarget target, bool allowCreate = false);
    Result Remove(string name);
}
```

分成两个而不是一个，因为"能读一个网页"和"能把这个 target 指到别处"是两件不同的事：后者正是把"模型可以读文档站"变成"模型可以读任何地方"的那一步。

### 6.2 模型：`net_fetch`

| 工具 | 参数 | 等级 | 对外办事 |
|---|---|---|---|
| `net_fetch` | `{target, path, method?, body?}` | agent | 是 |

- **`targets.json` 一个目标都没有时，这个工具根本不出现** —— 一个只会被拒的工具会买走一轮，并教会模型怀疑整张工具表（与 `27 §6` 里 `ssh_save` 不出现在 agent 级同一条）。
- 名字写错时回答里带上**现有的名字**：这是模型在这里唯一会犯的错，而一个能照抄的名字只需要错一次。
- 正文超过 32 000 字符就截断并明说"cut short"。

### 6.3 动作（脚本、WebUI、`actions_call` 都走这里）

| id | 能力 | 变更 |
|---|---|---|
| `net.targets.list` | `net.read` | 否（每个 target 的名字、地址、策略、有没有凭据） |
| `net.targets.get` | `net.read` | 否（一条，**凭据永远显示为 `***`**） |
| `net.targets.set` | `net.control` | 是（新增要 `create: true`；省略的字段保持原值；`secret: "***"` = 保留，`""` = 移除，明文 = 写入 `ISecretStore`） |
| `net.targets.remove` | `net.control` | 是（在飞的请求跑完；**保存的凭据不删**——忘掉一个名字不该顺手毁掉别人还在用的钥匙） |
| `net.fetch` | `net.read` | 否（与 `net_fetch` 工具同一个端口、同一份策略、同一行审计） |

顺序是**先应用、后落盘**，与 [`15`](15-网络接口.md) 的 `params.set` 一致：策略先进进程，再把整份名单写回文件。落盘失败不是回滚，而是回答里 `persisted: false` + 一句"现在生效、重启后会丢"——那才是实情。

`net.read` 是 **agent 级**（"你能不能读那个页面"是助手该能回答的问题），`net.control` 也是 **agent 级**（2026-11-12 改，原 operator）：裸门 `net.request` 一直是 agent 级——地址由调用方说、没有名单挡在前面——那么"把这次用的地址记下来"不比"现在就 POST 过去"更深，留一道 operator 只会让模型每次重问一遍。名单是**便利**，不是闸门；闸门是那句"每次调用一条审计"。

## 7. 脚本

脚本**没有** `net` 对象。要上网，两步：

1. manifest 里声明 `net.read`（与其它能力同一条规则：没声明就解析不到，`GraphManager` 的允许表里没有的能力整条拒绝）；
2. `ctx.actions.call('net.fetch', '{"target":"docs","path":"/releases"}')`。

这样做的原因不是省事，而是**不新增一条能力通路**：动作表已经是"谁能做什么"的唯一回答处，鉴权、审计、信号都只在那里做一次（`15` 开头那条）。加一个 `ctx.net` 会多出第二个执行点，而第二个执行点迟早漏掉三者之一。

**已知的放宽**：脚本能调用宿主 allowlist 里的**全部** target，而不是逐个脚本声明。做到逐脚本需要在 `ScriptFileManifest` 上加一个 `netTargets` 数组并贯穿装载、校验、执行三处——那是下一次改动，不是这一期的半成品。当前的立场是：脚本的 `net.read` 由写 manifest 的人负责，而 target 名单由写 `targets.json` 的人负责，两者都在磁盘上可查。

## 8. 明确不做

| 不做 | 为什么 |
|---|---|
| 任意 TCP / UDP / SOCKS / 端口扫描 | 那是"把宿主变成出口"，与 `06 §0` 直接冲突 |
| 接受绝对 URL 的参数 | 见 §1：不是校验掉，是类型里没有 |
| `file:` / `ftp:` / `data:` 等非 http(s) | 每一种 scheme 都是一种新的能力面 |
| 浏览器自动化（JS 渲染、点击） | `06 §8.3` 的清单里，需要另一套威胁模型 |
| Cookie 容器 / 会话态 / 自动重试 | 这里是一次抓取，不是一个客户端 |
| 二进制下载 | 字节面已经在 `IBinaryFileAccess` 与 `IMediaStore` 上，且那条路有 64 MiB 上限与 scope 规则（`24`、`28`）。网络面只给"能读回来的文本" |
| 让 provider 走这条端口 | provider 的地址是 operator 在配置里写的、它有自己的凭据与 `artifacts` 记录；把它塞进白名单只会让那两条审计互相打架 |

## 10. 现状、验证与没做的事

**已实现**：`ALN.Net`（`HttpNetAccess` / `NetTargetFile` / `NetActions`），`NetContracts`（8 个类型 + 2 个接口），宿主的装配与收据行（`net: N target(s): …`），`NetTools`（`net_fetch`），五个动作，两条能力（`net.read` agent / `net.control` agent，2026-11-12 起；见 [`07`](07-域与权限分级.md) §9.1），脚本端的 `net.read` 声明位。

**离线可验证的部分都有测试**（`NetAccessTests` 20 条、`NetActionsTests` 9 条）：

- 未登记的名字被拒且不回显调用方给的字符串；
- 方法/路径前缀/头不在名单里的三种拒绝，各自答出允许项；
- `//host/x`、`/../etc/passwd`、`http://host/x` 三种路径都出不了 origin；
- `127.0.0.1` 在 `allowPrivate: false` 下被拒（`PrivateAddress`），`true` 下可达；
- 12 个私网/环回/元数据地址被判死，3 个公网地址放行；
- 超上限标 `Truncated` 且 `Bytes` 等于上限；
- 慢服务 1 秒被切断，且总时长 < 4 秒；
- 302 不跟随时原样返回；跟随时同源跟随到底；跨源重定向被拒；
- 每分钟 1 次时第二次 `Conflict` + `Retryable`；
- 审计：一条，不含 body、query 只留 key、actor 与 target 都在；
- 拒绝也记一条；
- `targets.json` 的坏条目逐条拒绝（带 userinfo / 非绝对 URL / 未知方法 / 超顶 `maxBytes` / 重名），好的那条留着，写回再读仍然干净；
- 动作层：新增改了进程也改了文件、改字段不动其它字段、不写 `create` 就拒绝、凭据写入后只以 `***` 回显、`"***"` 表示保留、删 target 不删凭据、模型能读不能改、文件写不动时"现在生效、重启会丢"。

**没有验证的（明确的空白）**：

1. **没有一次真实的对外 HTTPS 会话。** 所有测试都在本机 loopback 的裸 socket 上，所以 TLS 握手、真实 DNS、真实 CDN 的重定向行为都没有跑过。第一件该做的事：给一个真实 target（比如某个公开文档站），跑一次 `net.fetch`。
2. **凭据注入没测过。** `secret` → `Authorization: Bearer` 的路径写了，但没有测试用一个会检查该头的服务器验证它；也没有测"凭据不存在时"的那条拒绝。
3. **压缩响应没测过。** gzip/br 解压在 handler 里，`maxBytes` 是在解压后的流上截断——逻辑上对，但没有一条测试用压缩响应证明它。
4. **并发上限没测过**（只测了每分钟配额）。`maxConcurrent` 被用满时的等待与超时分支没有覆盖。
5. **脚本经 `ctx.actions.call('net.fetch')` 的端到端没跑过。** 只验证了 `net.read` 进了脚本的允许表，没有写一个真脚本调一次。
6. **WebUI 没有入口。** 五个动作都能用，但界面里没有 target 的列表/编辑/试用页面——那是 `ALN.WebUi/wwwroot/js/views/` 的一次新增，不在这一期。
7. **`allowPrivate` 的一个残余风险**：它按 IP 判，不按接口判。开着的 target 能到本机任何端口，包括 `ALN.Api` 自己（那里有令牌，所以打到也只是 401）。
