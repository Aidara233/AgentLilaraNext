# 18 · 模块插件（把外部模块嵌进宿主）

> 最后更新：`8d1f221`
>
> 这篇回答一个问题：**别人写的模块，怎么装进这个进程、能用哪些扩展点、出错了会不会把宿主拖死。**

---

## 1. 一个插件就是一个目录

```
<dataRoot>/modules/<包 id>/
  module.json            ← 清单：宿主读它，不信插件自己说的
  <EntryAssembly>.dll    ← 插件本体（可以带自己的私有依赖，放在同目录）
  ...                    ← 其它私有文件，随便放
```

扔进去、重启宿主，它就加载了。启动收据会写一行：

```
restored modules: plugin sample.environment 1.0.0 from sample.environment
```

为什么放数据根而不是程序目录：**升级会整个替换程序目录**，而插件不是升级的一部分。内置模块（bundled.runtime、模型 provider、两个适配器）仍然从程序目录的 `modules/` 加载——它们是发布物的一部分。

## 2. module.json

```json
{
  "id": "sample.environment",
  "version": "1.0.0",
  "contracts": "1",
  "entryAssembly": "SampleEnvironment.dll",
  "entryType": "SampleEnvironment.Plugin",
  "provides": [],
  "dependencies": [],
  "reloadPolicy": "replace"
}
```

| 字段 | 作用 |
|---|---|
| `id` / `version` | 包身份；同 id 不能加载两次（Conflict） |
| `contracts` | 编译时对齐的契约版本。与宿主不同 → **当场拒绝**并说明双方版本，而不是等某个方法调用时才炸 |
| `entryAssembly` / `entryType` | 入口程序集与类型；必须是实现了 `IModulePlugin` 的**具体、有公共无参构造**的类型 |
| `provides` | 这个包提供的**模块类型**（`adapter.qq`、`model.openai-chat`、`channel.conversation`……）。纯服务型插件可以是空数组 |
| `dependencies` | 依赖的包 id + 版本；必填依赖没加载 → 拒绝（`*` 或精确匹配） |
| `reloadPolicy` | `none` = 只能随进程走；`replace` = 允许热替换。**插件必须是 `replace`**，bundled 必须是 `none`（宿主按来源判定，插件无法自我提权） |

`IModulePlugin.Manifest` 必须与 `module.json` **逐字段一致**：包不能对自己撒谎，宿主只信文件。

## 3. 插件能接触什么

只有 `ALN.Contracts`（外加 `ALN.Graph.Contracts`）。宿主的内部分解——`ALN.Runtime`、`ALN.Channel`、`ALN.Graph` 的实现——都不该被编译引用；`IModulePluginContext` 给的是两件事：

- `HostServices.GetService(typeof(X))`：按契约取宿主服务（`IRoundContextContributorRegistry`、`IAdapterFactoryRegistry`、`IModelManager`、`IStateStore`、`IQueuedMessageStore`、`ISignalLog`、`IModuleLoggerFactory`……）；
- `RegisterService(id, object)` / `GetService<T>(id)`：插件之间的服务交换，包卸载时按包清理。

每个插件跑在自己的 `AssemblyLoadContext`（可回收）里，共享契约程序集、优先解析包目录里的私有依赖。所以两个插件可以带不同版本的同一个库。

## 4. 生命周期

```csharp
public ValueTask<Result> StartAsync(IModulePluginContext context, CancellationToken ct);      // 注册扩展点
public ValueTask<Result<ModuleUnloadReadiness>> PrepareUnloadAsync(...)                        // 卸载前：说清还有没有在飞的活
public ValueTask<Result> DisconnectAsync(bool forced, CancellationToken ct)                    // 真的断开：把注册的东西还回去
```

`StartAsync` 失败 → 整个包回滚（类型、服务、参与者都清掉，加载上下文卸载），**宿主继续启动**。可选的 `dependencies` 还允许"网络断了但不致命"。

## 5. 扩展点

| 扩展点 | 怎么提供 | 例子 |
|---|---|---|
| 模块类型（可被 `graph.mount` / 频道 / 适配器规格引用） | `provides` + `IModuleTypeRegistry` 自动登记 | `adapter.qq`、`channel.conversation` |
| 适配器 | `IAdapterFactoryRegistry.Register` | `adapter.file`、`adapter.qq` |
| 模型 provider | `IModelManager.RegisterFactory` | `model.openai-chat` |
| 每轮上下文 | `IRoundContextContributorRegistry.Register` | 内置 `system.time`、样例 `sample.environment` |
| 宿主服务 | `context.RegisterService` | 给别的插件用的查询器 |
| 脚本执行器 | 预留（`IScriptExecutor` 在合约里） | 未来的 JS/WASM 运行时 |

**没有**的扩展点（明确不做）：覆盖核心动作（`CoreActions` 是宿主的）、替换加载器本身、往模块目录之外写文件（`IModulePackageResourceRegistry` 只清理自己登记的）。

## 6. 出错时的规矩

| 情况 | 结果 |
|---|---|
| 包目录存在但 `module.json` 读不出来 / 字段不合法 | 跳过该包，`plugin skipped: <目录名> — <原因>`，其它照常 |
| `contracts` 与宿主不一致 | 同上，消息里带双方版本 |
| 入口类型不是 `IModulePlugin` 或无公共无参构造 | 同上 |
| `StartAsync` 返回失败或抛异常 | 该包回滚 + 跳过；已加载的包不受影响 |
| 依赖的包没加载 | 这一轮先跳过，下一轮再试（目录顺序不代表依赖顺序） |
| 内置包（bundled / 模型 provider / 适配器）加载失败 | **仍然是致命的**：发布物坏了不该"带病启动" |

这几条就是"能否嵌入"的实质：**外部包的失败必须被关在它自己那格里。**

## 7. 怎么看、怎么改

- `modules.list`（`system.read`）：列出已加载的包、版本、来源种类、提供的类型、依赖、重载策略，以及宿主当前的契约版本。
- 热替换：`ModulePackageLoader.ReplaceAsync` 已实现（同 id、更高版本、独立目录、失败自动回滚到原版本，含依赖闭包）。**还没有动作接口**——目前只能由宿主代码调用。
- 卸载：`UnloadAsync`，先跑 `PrepareUnloadAsync` 屏障，超时或强制则走 `DisconnectAsync(forced)` + 强制清理（例如按类型销毁剩余适配器实例、摘掉频道绑定、退订时钟）。

## 8. 样例：`samples/plugins/sample.environment`

一个真能被加载的最小插件：往每轮模型请求里加一节 `<section name="environment">`，内容是宿主运行时版本。它同时是**测试夹具**——`ModulePluginTests` 把它拷进临时包目录、用真的加载器加载，然后断言：贡献者确实被注册、确实回答了请求、`modules.list` 能看到它、卸载后从注册表消失。

怎么试：

```bash
dotnet build samples/plugins/sample.environment
cp samples/plugins/sample.environment/bin/Debug/net10.0/SampleEnvironment.dll \
   samples/plugins/sample.environment/module.json \
   <dataRoot>/modules/sample.environment/
# 重启宿主，然后 modules.list；随便发一条消息，模型请求里会多一节 environment
```

（实测：`section name="environment" source="sample.environment"` 出现在 model-calls 记录里，紧挨着内置的 `time`。）

## 9. 还没做的

1. **没有 `modules.load` / `modules.unload` / `modules.replace` 动作**：加载目前是启动时的扫描 + 宿主代码调用。要做成动作，得先回答"谁能调"——`graph.mount` 是 `graph.control`，模块装载该属于更窄的一档。
2. **没有签名/来源校验**：`ModulePackageKind` 由宿主按目录来源判定，但目录本身没有可信度分层（谁往数据根写文件，谁就能塞代码）。隔离够了，来源信任还没有。
3. **契约版本只有一个数字**：`"1"`。真出现不兼容变更时，需要"最低版本/最高版本"或能力位，而不是等 `MissingMethodException`。
