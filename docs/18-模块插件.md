# 18 · 模块插件（把外部模块嵌进宿主）

> 最后更新：`8d1f221`
>
> 这篇回答一个问题：**别人写的模块，怎么装进这个进程、能用哪些扩展点、出错了会不会把宿主拖死。**

---

## 1. 一个插件就是一个目录

```
<dataRoot>/plugins/<包 id>/
  plugin.json            ← 清单：宿主读它，不信插件自己说的
  <EntryAssembly>.dll    ← 插件本体（私有依赖放同目录，不会被别的插件看见）
  scripts/<脚本 id>/      ← 随插件发行的脚本：manifest.json + main.js
    manifest.json
    main.js
```

扔进去、重启宿主，它就加载了。启动收据会写两行：

```
restored modules: plugin sample.environment 1.0.0 from sample.environment
restored graph: 1 mount rule(s) → 0 mount(s); …（脚本目录一并被扫描，见 §3）
```

为什么放数据根而不是程序目录：**升级会整个替换程序目录**，而插件不是升级的一部分。内置模块（`bundled.runtime`、`archive`、模型 provider、两个适配器）仍然从程序目录的 `modules/` 加载——它们是发布物的一部分。

内置包现在有五个，各自只做一件事，靠服务 id 互相找：`bundled.runtime`（时钟 / 频道 / 图 / 脚本执行器）、`archive`（回收站，服务 id `archive.manager`）、`model.openai-chat`、`adapter.file`、`adapter.qq`。**归档单独成包**的理由与"为什么不设 `plugins/<id>/modules/`"是同一个道理的正面：会堆积的东西不止会话，而"搬走 / 拿回来"这件事只该有一份实现——包边界让这条边界看得见（细节见 [`17` §8](17-状态与恢复.md)）。

包之间的一个约定，靠它才不用给加载排序：**谁创建服务谁负责用服务 id 暴露；谁要登记就在自己的启动里登记。** 归档包在宿主启动时先加载，自己 `new ArchiveManager(数据根)` 并 `RegisterService("archive.manager", …)`；`bundled.runtime` 随后启动，从服务 id 取到 registry，把自己的 `SessionArchiveSource` 登记进去。没有谁持有 `ALN.Archive` 的类型，也没有"必须先启动谁"的隐含规则。

**为什么不设 `plugins/<id>/modules/` 这一层**：一个插件的边界就是它的加载上下文，多包共存只会带来"这两个包谁先谁后"的问题，而这类问题的答案通常是"它们本来就是一个包"。真要两个包，就是两个插件目录。

## 2. plugin.json

```json
{
  "id": "sample.environment",
  "version": "1.0.0",
  "contracts": "2",
  "entryAssembly": "SampleEnvironment.dll",
  "entryType": "SampleEnvironment.Plugin",
  "provides": [],
  "dependencies": [],
  "reloadPolicy": "replace"
}
```

| 字段 | 作用 |
|---|---|
| `id` / `version` | 包身份；同 id 不能加载两次（Conflict） |
| `contracts` | 编译时对齐的契约版本。与宿主不同 → **当场拒绝**并说明双方版本，而不是等某个方法调用时才炸 |
| `entryAssembly` / `entryType` | 入口程序集与类型；必须是实现了 `IModulePlugin` 的**具体、有公共无参构造**的类型 |
| `provides` | 这个包提供的**模块类型**（`adapter.qq`、`model.openai-chat`、`channel.conversation`……）。纯服务型插件可以是空数组 |
| `dependencies` | 要**先**加载的包 id；`versionRange` 留空 = 任何版本（见 §4） |
| `reloadPolicy` | `none` = 只能随进程走；`replace` = 允许热替换。**插件必须是 `replace`**，bundled 必须是 `none`（宿主按来源判定，插件无法自我提权） |

`IModulePlugin.Manifest` 必须与 `plugin.json` **逐字段一致**：包不能对自己撒谎，宿主只信文件。（文件原名 `module.json`，已改名；目录里只有旧名字时宿主会直接告诉你改名，而不是装作没看见。）

## 3. 模块 + 脚本才是一个插件

一个模块往往只是**机械**：新的适配器、新的 provider、新的频道类型。让它真的干活的**行为**在脚本里——而脚本此前只能由运营者自己写进 `scripts/trusted/`。于是"装一个插件"变成"装一个 dll，再自己写脚本"，这不是发行单元。

现在插件目录里的 `scripts/` 与 `scripts/trusted/` 一样会被 `JsonScriptCatalog` 扫描：

- 每个脚本仍是一个目录（`manifest.json` + `main.js`），id 全局唯一；
- 随插件发行的脚本**必须声明 `trustDomain: trusted`**——装插件这个动作本身就是信任决定，但一个随包来的脚本不能自称 `builtin`（那是发布物的特权）；
- 脚本包的 `Origin` 记成 `plugin:<包 id>`，所以"这个脚本哪来的"以后能查；
- 脚本 id 与运营者手写脚本**共用命名空间**：撞名直接报 `Conflict` 并列出两个路径，不猜哪个优先。

样例里就有一个：`samples/plugins/sample.environment/scripts/sample.clock/`，手动挂载后回一句宿主时间（模型自己不知道"现在几点"）。

**插件仍然不发行为以外的配置**：它不写频道、不写挂载规则、不覆盖别人的脚本。默认挂载策略还是运营者的决定（`bundle` 脚本随包自动挂，这是脚本清单里的 `mount` 字段，不是插件清单）。

只有 `ALN.Contracts`（外加 `ALN.Graph.Contracts`）。宿主的内部分解——`ALN.Runtime`、`ALN.Channel`、`ALN.Graph` 的实现——都不该被编译引用；`IModulePluginContext` 给的是两件事：

- `HostServices.GetService(typeof(X))`：按契约取宿主服务（`ISessionExtensionRegistry`、`IAdapterFactoryRegistry`、`IModelManager`、`IStateStore`、`IQueuedMessageStore`、`ISignalLog`、`IModuleLoggerFactory`……）；
- `RegisterService(id, object)` / `GetService<T>(id)`：插件之间的服务交换，包卸载时按包清理。

每个插件跑在自己的 `AssemblyLoadContext`（可回收）里，共享契约程序集、优先解析包目录里的私有依赖。所以两个插件可以带不同版本的同一个库。

## 4. 依赖：原则上不该有

**一个插件不该依赖另一个插件。** 插件只和宿主对话（`HostServices` 按契约取服务），不直接调用彼此；如果两段代码必须一起工作，它们就是一个插件的两个类型，或者一个包里的两个程序集。若只是因为共用一段库而想拆包，正确的是把库放进包目录当私有依赖——加载上下文会优先解析它，别的插件看不到。

`dependencies` 保留下来只为一件事：**加载顺序**。留空的 `versionRange` 表示"任何版本"，只有极少数确实绑死了 ABI 的场合才写具体版本。它是"先加载谁"，不是"少了谁就活不了"——真少了，通常说明这两半本该是一个包。

所以看到 `dependencies` 有两项以上时，第一反应应该是拆得不对，而不是"依赖管理得不错"。

## 5. 插件能接触什么

```csharp
public ValueTask<Result> StartAsync(IModulePluginContext context, CancellationToken ct);      // 注册扩展点
public ValueTask<Result<ModuleUnloadReadiness>> PrepareUnloadAsync(...)                        // 卸载前：说清还有没有在飞的活
public ValueTask<Result> DisconnectAsync(bool forced, CancellationToken ct)                    // 真的断开：把注册的东西还回去
```

`StartAsync` 失败 → 整个包回滚（类型、服务、参与者都清掉，加载上下文卸载），**宿主继续启动**。可选的 `dependencies` 还允许"网络断了但不致命"。

## 6. 扩展点

| 扩展点 | 怎么提供 | 例子 |
|---|---|---|
| 模块类型（可被 `modules.edge.mount` / 频道 / 适配器规格引用） | `provides` + `IModuleTypeRegistry` 自动登记 | `adapter.qq`、`channel.conversation` |
| 适配器 | `IAdapterFactoryRegistry.Register` | `adapter.file`、`adapter.qq` |
| 模型 provider | `IModelManager.RegisterFactory` | `model.openai-chat` |
| 每轮上下文 / 工具 | `ISessionExtensionRegistry.Register`（浮动 / 时间线 / 工具三类） | 内置 `system.time`、`system.channel-info`、`channel.delta`、`memory.store`，样例 `sample.environment` |
| 宿主服务 | `context.RegisterService` | 给别的插件用的查询器 |
| 脚本执行器 | 预留（`IScriptExecutor` 在合约里） | 未来的 JS/WASM 运行时 |

**没有**的扩展点（明确不做）：覆盖核心动作（`CoreActions` 是宿主的）、替换加载器本身、往模块目录之外写文件（`IModulePackageResourceRegistry` 只清理自己登记的）。

### 6.1 一个模块的运行期参数：`IParameterTarget`

模块可以把自己的一两个数字公开成**参数**，于是改它们不需要重启也不需要重新加载包：

| `media.local` 的参数 | 默认 | 作用 |
|---|---|---|
| `autoView` | `first` | 收到图自动看多少（`off` / `first` / `all`） |
| `allowed` | png, jpeg, gif, webp | 可自动看的格式 |
| `maxImageBytes` / `maxImageBytesPerRequest` | 8 MiB / 24 MiB | 单张 / 一次请求的字节上限 |
| `maxImagesPerRequest` / `maxAutoViewsPerTurn` | 6 / 3 | 一次请求几张 / 一回合自动看几张 |

规则只有一条：**参数是"这个部署怎么调"，不是"这个模块做什么"**。所以它进 `module.json` 的默认值由模块给
（`DefaultConfig`），运行期由 `ApplyParameterAsync` 校验后**一次性整体替换**（`Volatile.Write`），
请求拼装时读到的永远是某一整份决定，不会是半份。改完**下一轮生效**，不重载包。
细节见 `docs/28 §4.2`；注册/注销在模块生命周期里（`InitializeAsync` / `StopAsync`），
`Conflict` 视为"别人已经在回答"而不是失败。

## 7. 出错时的规矩

| 情况 | 结果 |
|---|---|
| 包目录存在但 `plugin.json` 读不出来 / 字段不合法 | 跳过该包，`plugin skipped: <目录名> — <原因>`，其它照常 |
| `contracts` 与宿主不一致 | 同上，消息里带双方版本 |
| 入口类型不是 `IModulePlugin` 或无公共无参构造 | 同上 |
| `StartAsync` 返回失败或抛异常 | 该包回滚 + 跳过；已加载的包不受影响 |
| 依赖的包没加载 | 这一轮先跳过，下一轮再试（目录顺序不代表依赖顺序） |
| 内置包（bundled / 模型 provider / 适配器）加载失败 | **仍然是致命的**：发布物坏了不该"带病启动" |

这几条就是"能否嵌入"的实质：**外部包的失败必须被关在它自己那格里。**

## 8. 怎么看、怎么改

- `modules.list`（`system.read`）：列出已加载的包、版本、来源种类、提供的类型、依赖、重载策略，以及宿主当前的契约版本。
- 热替换：同 id、更高版本、独立目录、失败回滚到原版本（含依赖闭包）。动作接口未定。
- 卸载：`UnloadAsync`，先跑 `PrepareUnloadAsync` 屏障，超时或强制则走 `DisconnectAsync(forced)` + 强制清理（例如按类型销毁剩余适配器实例、摘掉频道绑定、退订时钟）。

## 9. 样例：`samples/plugins/sample.environment`

一个真能被加载的最小插件，两半都齐：模块半边往每轮模型请求里加一节 `<section name="environment">`（宿主运行时版本），脚本半边 `scripts/sample.clock/` 回一句宿主时间。它同时是**测试夹具**——`ModulePluginTests` 把它拷进临时包目录、用真的加载器和真的脚本目录去读，断言：贡献者被注册并回答了请求、`modules.list` 能看到包、`JsonScriptCatalog` 能读出 `sample.clock` 且 `Origin = plugin:sample.environment`、卸载后从注册表消失。

怎么试：

```bash
dotnet build samples/plugins/sample.environment
mkdir -p <dataRoot>/plugins
cp -r samples/plugins/sample.environment <dataRoot>/plugins/
rm -rf <dataRoot>/plugins/sample.environment/bin <dataRoot>/plugins/sample.environment/obj
# 重启宿主 → modules.list 里出现 sample.environment
# 脚本要手动挂：modules.edge.mount { "script": "sample.clock", "scope": "type", "selector": "channel.conversation" }
```
