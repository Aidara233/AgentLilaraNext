# ALN 网络接口（WebUI 的唯一入口）

本体不包含任何界面代码，只暴露动作（action）。WebUI 是独立项目，通过本接口驱动核心；
以后再加第二个前端（CLI、脚本、另一个 UI），走的是同一套动作和同一套鉴权。

## 为什么不是"内部接口 + 一层鉴权"

内部管理器的方法为进程内调用者设计：`ScriptApi` 依赖挂载点与来源事件，`IModelManager.List()`
带着 Provider 配置，`AdapterEnvelope` 是传输结构。照搬到网络上等于把内部对象、密钥和重构自由
一起交出去。所以统一在**动作层**：

- 每个动作有 id、摘要、所需能力、是否变更状态。
- 所有前端共用 `IControlPlane.InvokeAsync(actor, action, json)` 这一个执行点，鉴权、审计、信号
  都只在那里做一次——新增传输不可能漏掉其中任何一项。
- 返回值是**为外部定义的 DTO**，不是内部对象。`models.list` 连 Provider 配置字段都不存在。

## 配置

`<DataRoot>/api/server.json`。文件不存在 = 不监听（默认关闭）。

```json
{
  "urls": ["http://127.0.0.1:5199"],
  "cors": ["http://127.0.0.1:5200"],
  "roles": { "admin": ["*"], "viewer": ["*.read"] },
  "tokens": [
    { "name": "admin-local", "sha256": "<sha256 hex>", "roles": ["admin"] }
  ]
}
```

- 令牌只存 SHA-256，不存明文；比较用定长时间比较。生成：`printf 'token' | sha256sum`。
- 能力匹配只支持**一个** `*`：`adapters.*`、`*.read`、`*`。更复杂的模式不支持，且不匹配即拒绝。
- 角色只是能力的别名；动作只认能力，不认角色名。

### `cors`：哪些源能从这个浏览器里调用

字段可省，**省略 = 不允许任何跨源调用**（curl、脚本、服务端调用都不受影响，它们不发 `Origin`）。

- 每一项必须是**源**：`scheme://host[:port]`。带路径、查询、`*`、带账号的 URL 一律丢弃，并在启动时打一行
  `Warning: cors entry '…' is not an origin…`。丢弃而不是放行，是因为浏览器在 `Origin` 里根本不会发路径，
  接受一个带路径的条目只会得到一个"看着对、永远不匹配"的配置。
- 预检（`OPTIONS`）由 CORS 中间件在**鉴权之前**答复：预检请求不带 `Authorization`，若要它先过鉴权，
  浏览器永远看不到放行头。
- 允许任意请求头与方法，但只对名单里的源回 `Access-Control-Allow-Origin`；名单外的源拿不到该头，
  浏览器自己就会拦下。
- 401/403 这类错误响应**也带**放行头，否则前端读不到 `{"code":"Denied"}`，只能看到一句"网络错误"。

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/actions` | 动作目录，带当前身份与每个动作是否被允许 |
| POST | `/actions/{action}` | 执行动作，body 为 JSON 参数 |

无 `Authorization: Bearer <token>` → `401`。能力不足 → `403`（`code: Denied`）。未知动作 → `400`
（`code: Invalid`，与权限无关：它根本不存在）。动作内部失败 → `400/409/502`，带 `code`。

## 动作

| id | 能力 | 变更 |
|---|---|---|
| `system.info` | `system.read` | 否 |
| `adapters.list` / `channels.list` | `adapters.read` / `channels.read` | 否 |
| `adapters.start` / `adapters.stop` | `adapters.control` | 是 |
| `channels.start` / `channels.stop` | `channels.control` | 是 |
| `channels.send` | `messages.write` | 是（向频道的唯一绑定发一条文本） |
| `graph.list` | `graph.read` | 否（列出每个已挂载脚本与它的目标实例） |
| `graph.mount` / `graph.unmount` | `graph.control` | 是（把 `"mount": "manual"` 的脚本挂到**某一个**实例上） |
| `params.list` | `params.read` | 否（所有可调项 + 当前值 + 生效方式） |
| `params.set` | `params.write` | 是（组件校验 → 立即应用 → 持久化） |
| `models.list` | `models.read` | 否 |
| `signals.recent` | `signals.read` | 否 |

`signals.recent` 支持 `{"limit": 200, "group": "dispatch"}`，只读内存窗口，不扫文件。

### 运行时参数：`params.list` / `params.set`

组件把自己的可调项登记到一个注册表里，`params.list` 列出全部（含当前值、类型、范围、生效方式），
`params.set` 改一个：**组件自己校验 → 立即应用 → 持久化**（顺序如此，见下）。

```json
{ "scope": "channel.conversation#qq-private-1664093638", "name": "maxMessages", "value": "25" }
```

每个参数必须声明**什么时候生效**，因为"立即生效"对有些参数是做不到的：

| `apply` | 含义 |
|---|---|
| `Immediate` | 下次用到就生效，不用重启（如频道的 `maxMessages`，每次激活都会读） |
| `NextRound` | 同一进程里慢一拍，下一轮/下一个 tick 生效 |
| `Reconnect` | 需要重连才生效（如适配器的 endpoint） |
| `Restart` | 只在启动时读；现在存下来，重启后才生效 |

现在有哪些参数：

| scope | 名字 | 生效 | 作用 |
|---|---|---|---|
| `channel.conversation#<id>` | `maxMessages` | Immediate | 一轮最多携带多少条消息；更早的折叠成"省略更早的 N 条" |
| `channel.conversation#<id>` | `modelProfile` | Immediate | 这个频道用哪个模型 profile；留空 = 由宿主解析（`default` 优先，否则 id 序第一个） |
| `adapter.qq#<id>` | `requestTimeoutSeconds` | Immediate | 一次 OneBot 动作等应答多久；改了下一次动作用上，不必重连 |

频道侧还有一层"继承"：脚本给的会话 spec 里没写 `modelProfileId` 时，先看频道自己的 `modelProfile`，
再退回宿主的全局解析。哪个频道用哪个模型是部署的事，不该写进脚本。

三条硬规则：

1. **先应用、后持久化**。应用失败就报错且不落盘——一个文件说着一件事、进程做着另一件事，
   比没有这个设置更糟。落盘失败会回报"已生效但重启后会丢"。
2. **`secret` 参数只写不读**：可以设，`params.list` 里永远是 `null`。令牌不该从任何能被日志、
   截图或工单带走的接口里回显。
3. **`<= 0`、越界、类型不对一律拒绝**，不猜意图（`maxMessages: 0` 不会被当成"不限"）。

持久化走 `IStateStore`：`aln.db` 的 `state` 表，scope 是编码后的组件地址，key 是参数名。地址里的 `#` 等字符会被编码
（保留可读前缀 + 短哈希），存储层保持严格的 token 规则不变。启动时在频道复活之后统一回放一遍，
所以重启不会丢。

当前已登记的参数：`channel.conversation#<id>` 的 `maxMessages`（`Immediate`）。
其余组件接上 `IParameterTarget` 就会出现，不需要改动作层。

脚本 manifest 里 `"mount": "manual"` 表示**谁也不会替你挂**：加载之后它不跑在任何目标上，
只能由 `graph.mount` 指到具体实例：

```json
{ "script": "channel.echo", "target": "channel.conversation#chat-auto" }
```

- `default` 脚本拒绝被手工挂载（`Denied`）：它的挂载属于实例生命周期，手工再挂就是两份；
- 同一 (script, target) 重复挂载是 `Conflict`；卸载不存在的挂载是 `Invalid`；
- 挂载是即时的，不需要重启；但新增/修改脚本包本身要重启才被加载。

这就是"每个频道各自的策略"的做法：写一个 manual 脚本，只挂到需要它的那个频道上，而不是所有频道共用一份 default。

## WebUI（独立项目 `src/ALN.WebUi`）

本体不含任何界面代码；界面是一个**独立进程**，只通过上面两个 HTTP 端点说话。

```
run-webui.cmd                      :: 默认 127.0.0.1:5200，默认 API http://127.0.0.1:5199
dotnet run --project src\ALN.WebUi\ALN.WebUi.csproj -- --port 5200 --api http://127.0.0.1:5199
```

`run-webui.cmd` 会额外传 `--root src\ALN.WebUi\wwwroot`：直接把源码目录当站点根。改完一个模块、刷新浏览器就生效，
中间没有构建步骤。不加 `--root` 时服务的是编译输出旁边那份拷贝，重启才更新——这是给"跑编译好的产物"用的路径。

- **结构性隔离**：这个项目的 `.csproj` **没有任何 ProjectReference**。它看不到 `ALN.Contracts`，
  更看不到任何 Manager，所以界面要显示什么，就只能由动作的 DTO 给。想加类型引用时，正确的改法是
  扩动作的返回值，不是加引用。
- **没有构建步骤**：`wwwroot` 里是纯 ES 模块（`js/main.js` + `js/api.js` + `js/ui.js` + `js/views/*.js`），
  浏览器直接加载。这台机器上没有 node/npm，界面也不该因此变成一个需要装工具链才能跑的产物。
- **令牌来自人**：登录页填接口地址与令牌，存在 `sessionStorage`（关标签页即失效），每次请求带
  `Authorization: Bearer`。令牌不写进任何静态文件，也不写进这个进程。
- **默认地址另一个来源**：`GET /config.json` 返回 `--api` 给的默认值；人仍然可以改，因为只认启动端口的
  界面没法指向另一台核心。
- **跨源**：界面在 5200、核心在 5199，属于跨源。必须把界面地址写进 `server.json` 的 `cors`，否则
  浏览器在预检阶段就拦掉，页面上表现为"连不上核心"。

界面覆盖的动作：

| 页面 | 用到的动作 |
|---|---|
| 概览 | `system.info`，以及身份与动作目录的统计 |
| 适配器 | `adapters.list` + `adapters.start/stop` |
| 频道 | `channels.list` + `channels.start/stop` + `channels.send` |
| 模型 | `models.list` |
| 信号 | `signals.recent`（分组/条数过滤，5 秒自动刷新） |
| 动作 | `GET /actions` 的目录，外带一个按 JSON 原样调用的入口 |

约定：

- 能力不足的动作**按钮直接是灰的**，并给出缺哪个能力；服务端反正会 403，但"按下去才知道不行"是更差的界面。
- 变更类动作先确认，再调用；按钮在飞行中禁用，避免连点发出两次 stop。
- 401 统一回到登录页：一个过期令牌会让每个面板都在说假话。
- 所有来自核心的字符串都进 `textContent`。`WebUiAssetsTests` 会拦住 `.innerHTML` / `.outerHTML` 赋值。

界面没有测试运行器，所以用两个测试替它把关（`tests/ALN.Tests/WebUiAssetsTests.cs`）：

1. 用脚本模块已依赖的 Acornima 解析器把每个 `.js` 当 ES 模块解析——语法错误在这里失败，而不是白屏；
2. 核对 import 图：相对路径指向的文件存在，且具名导入确实是目标文件导出的名字（改名漏改导入是最常见的白屏原因）。

这**不能**代替浏览器里的真实点按：布局、事件时序、fetch 的实际跨源行为都不在测试覆盖内。

## 尚未实现（明确列出，避免误以为能用）

- **流式动作**：`sessions.turn`、`model.complete` 是流，不能塞进普通 JSON 响应，需要单独的 SSE
  契约；目前没有暴露。
- **会话读写**：只有 `sessions/<id>` 文件，没有 serve 它们的动作。
- **写类配置**：创建/修改 Adapter、Channel、Provider 的动作尚缺；`channels.create` 仍由脚本侧的
  `channel.route` 承担。
- **审计查询**：审计是追加文件，没有查询动作。
- **界面侧**：没有会话/消息页面、没有流式对话、没有 Adapter/Channel 的新建表单——都卡在上面的动作缺口。
  动作页的"原样调用"是当前唯一的临时通道。
