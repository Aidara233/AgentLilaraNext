# ALN 网络接口（WebUI 的唯一入口）

本体不包含任何界面代码，只暴露动作（action）。WebUI 是独立项目，通过本接口驱动核心；
以后再加第二个前端（CLI、脚本、另一个 UI），走的是同一套动作和同一套鉴权。

## 为什么不是"内部接口 + 一层鉴权"

内部管理器的方法为进程内调用者设计：`ScriptApi` 依赖挂载点与来源事件，`IModelManager.List()`
带着 Provider 配置，`AdapterEnvelope` 是传输结构。照搬到网络上等于把内部对象、密钥和重构自由
一起交出去。所以统一在**动作层**：

- 每个动作有 id、摘要、所需能力、是否变更状态。
- 所有前端共用 `IControlPlane.InvokeAsync(actor, action, json)` 这一个执行点，鉴权、审计、信号
  都只在那里做一次——新增传输不可能漏掉其中任何一项。
- 返回值是**为外部定义的 DTO**，不是内部对象。`models.list` 连 Provider 配置字段都不存在。

## 配置

`<DataRoot>/api/server.json`。文件不存在 = 不监听（默认关闭）。

```json
{
  "urls": ["http://127.0.0.1:5199"],
  "roles": { "admin": ["*"], "viewer": ["*.read"] },
  "tokens": [
    { "name": "admin-local", "sha256": "<sha256 hex>", "roles": ["admin"] }
  ]
}
```

- 令牌只存 SHA-256，不存明文；比较用定长时间比较。生成：`printf 'token' | sha256sum`。
- 能力匹配只支持**一个** `*`：`adapters.*`、`*.read`、`*`。更复杂的模式不支持，且不匹配即拒绝。
- 角色只是能力的别名；动作只认能力，不认角色名。

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/actions` | 动作目录，带当前身份与每个动作是否被允许 |
| POST | `/actions/{action}` | 执行动作，body 为 JSON 参数 |

无 `Authorization: Bearer <token>` → `401`。能力不足 → `403`（`code: Denied`）。未知动作 → `400`
（`code: Invalid`，与权限无关：它根本不存在）。动作内部失败 → `400/409/502`，带 `code`。

## 动作

| id | 能力 | 变更 |
|---|---|---|
| `system.info` | `system.read` | 否 |
| `adapters.list` / `channels.list` | `adapters.read` / `channels.read` | 否 |
| `adapters.start` / `adapters.stop` | `adapters.control` | 是 |
| `channels.start` / `channels.stop` | `channels.control` | 是 |
| `models.list` | `models.read` | 否 |
| `signals.recent` | `signals.read` | 否 |

`signals.recent` 支持 `{"limit": 200, "group": "dispatch"}`，只读内存窗口，不扫文件。

## 尚未实现（明确列出，避免误以为能用）

- **流式动作**：`sessions.turn`、`model.complete` 是流，不能塞进普通 JSON 响应，需要单独的 SSE
  契约；目前没有暴露。
- **会话读写**：只有 `sessions/<id>` 文件，没有 serve 它们的动作。
- **写类配置**：创建/修改 Adapter、Channel、Provider 的动作尚缺；`channels.create` 仍由脚本侧的
  `channel.route` 承担。
- **审计查询**：审计是追加文件，没有查询动作。
- **WebUI 本体**：未开始，本轮只交付它需要的网络面。
